# 安克创新 2026 笔试 — 完整笔记

## 笔试全景：三大环节

安克创新笔试分为三大环节，按顺序进行：

```
简历初筛 → CATA 自适应能力测评 → 创造者启航试炼（价值观）→ AI 飞行员试炼（实操）→ 业务面试
```

| 环节 | 类型 | 权重/角色 | 时长 |
|---|---|---|---|
| CATA 自适应能力测评 | 客观题，行测 | 准入门槛，不过直接淘汰 | 约 30-40 分钟 |
| 创造者启航试炼 | 情景选择题 | 占总分 60%，核心筛选 | 20 分钟 / 20 题 |
| AI 飞行员试炼 | 业务实操大题 | 核心筛选，影响定级薪资 | 3 小时 |

---

## 一、CATA 自适应能力测评

### 设计意图

筛选具备岗位基础职业能力的候选人，防止入职后在信息理解、数据处理、逻辑判断方面出现断层。采用**自适应模式**，题目难度根据正确率动态调整，**全程单题限时**。

### 三个模块

| 模块   | 考察内容             | 建议策略                                                                              |
| ---- | ---------------- | --------------------------------------------------------------------------------- |
| 言语理解 | 信息抓取、主旨判断、细节甄别   | 先看问题→再找核心信息；**关注转折/总结关键词**；单题 ≤60 秒                                               |
| 资料分析 | 数据提取、基础商业运算、风险细节 | 先看问题→再找数据；注意单位、图例、时间范围；善用估算；单题 ≤90 秒                                              |
| 图形推理 | 逻辑规律识别、快速应变      | 固定路径：**<span style="color:rgb(255, 77, 77)">位置规律→数量规律→样式规律；30 秒未找到规律立即跳过</span>** |

### 评分与淘汰规则

**按岗位分及格线**：

| 岗位类别             | 合格线  |
| ---------------- | ---- |
| 职能支持类（行政、财务、人力等） | 60 分 |
| 市场、销售、产品类        | 70 分 |
| 研发、算法、技术类        | 75 分 |

**模块短板淘汰**：三个模块中任一模块正确率低于 **50%**，即使总分达标也被标记淘汰，原则上不进面试。

**AI 监考红线（触发即判定无效）**：
- 连续 ≥3 题秒选（作答时间 < 10 秒）
- 全程切屏次数 ≥3 次
- 摄像头内出现第二人、查资料等作弊行为

### 关键提醒

- ⚠️ <span style="color:rgb(255, 77, 77)"><b>前 10 道题决定后续难度基线</b></span>，务必认真作答
- **题目难度升高 = 前面正确率高，稳住心态不要慌**
- 设备：带摄像头的电脑，Chrome 或 Edge 浏览器，网络稳定，安静环境

## 二、创造者启航试炼（价值观测评）

### 设计意图

占笔试总分权重 **60%**。20 道四选二情景题全部源自安克真实业务场景（产品瑕疵反馈、项目延期、供应链问题、跨部门冲突等），判断候选人是否与安克核心价值观和内部优秀员工行为一致。

### 六大核心价值观与权重

| 价值观  | 权重  | 核心含义              |
| ---- | --- | ----------------- |
| 客户第一 | 20% | 把用户体验和产品品质放首位     |
| 追求极致 | 20% | **深挖根源，不满足于表面解决** |
| 主动担当 | 15% | 遇事不甩锅，主动复盘和解决     |
| 长期主义 | 15% | 不因短期利益牺牲长期价值      |
| 团队协作 | 15% | **公开沟通、大局观、共同目标** |
| 务实创新 | 15% | 创新要能落地，不搞花架子      |

### 评分规则

- 完全匹配核心价值观：单选项权重 **10 分**
- 部分匹配：单选项权重 **5 分**
- 违背核心价值观：单选项权重 **0 分**
- 每题选 2 项，单题满分 20 分，**20 题总分 200 分**

### 评级与筛选

| 等级 | 分数 | 结果 |
|---|---|---|
| S 级 | 180+ | 优先面试，面评优先级最高 |
| A 级 | 160-179 | 直接进入面试 |
| B 级 | 140-159 | 待定，结合 CATA 与简历综合评估 |
| C 级 | 120-139 | 直接淘汰 |
| D 级 | <120 | 直接淘汰 |

### ⚠️ 一致性校验红线

系统自动校验 20 道题的行为一致性。若前后价值观匹配度低于 **70%**，即使总分达 A 级也**直接降级为 B 级或以下**。前后矛盾 = 不真实、不坦诚。

### 四大高频场景与答题逻辑

**1. 产品与用户相关场景（权重最高）**

> ✅ 选：主动调研用户真实痛点、深挖根源、针对性优化
> ❌ 避：赶进度牺牲体验、营销引导接受缺陷、无视问题直接上线

**2. 项目管理与危机处理场景**

> ✅ 选：梳理核心断点重构方案、带头复盘根源、直面用户坦诚沟通
> ❌ 避：盲目赶工、转移焦点、甩锅

**3. 团队协作与资源分配场景**

> ✅ 选：公开沟通共同制定方案、一对一了解公平分配、抓核心兼顾长期
> ❌ 避：独断专行强行分配、平均主义、只顾短期放弃长期

**4. 技术与研发相关场景**

> ✅ 选：深挖问题本质优化架构、主动探索技术突破、分析瓶颈找替代方案并风险兜底
> ❌ 避：只修补不碰根源、为进度牺牲质量与技术健康

### 答题提醒

- 每题**必须选 2 个选项**，少选视为无效
- **真实作答**比追求"标准答案"更重要——一致性校验会揪出装的人
- 20 题限时 20 分钟，每题约 1 分钟，跟随直觉快速选择，不反复纠结

## 三、AI 飞行员试炼（实操笔试）

### 基本概念

AI 飞行员试炼**不是面试**，是招聘流程中的**核心实操笔试**，3 小时云端考核。在 CATA 行测、启航价值观测评之后，过了才能进业务面试。成绩直接影响定级和薪资，表现优异可拿 SSP Offer。

> 别和「AI 认知测评」搞混——那个是 10 分钟客观选择题（大模型基础、AI 优缺点等），纯理论。AI 飞行员试炼是 3 小时纯业务实战。

**所有岗位都有这个环节**，考核内容按岗位方向分化。

### 考试环境

| 项目 | 详情 |
|---|---|
| 平台 | 阿里无影云虚拟机 |
| 内置工具 | VS Code + Claude Code |
| 监控 | 双机位全程监控 |
| 时长 | 激活即倒计时 3 小时 |
| 输出 | 全部成果打包提交（Markdown、图表、代码），无客观选择题 |

### 考试流程

1. **前置学习（~15 分钟）**：看工具教程，教怎么写提示词、调用 AI 生成代码/报表/方案
2. **查看任务**：阅读业务场景和问题
3. **AI 协作解题**：用 Claude Code 完成数据清洗、分析、方案设计、可视化
4. **整合交付**：打包所有成果提交

### 核心考核内容

#### 一、Prompt 工程 / AI 协作能力（分值最高，~40%）

- 会不会拆解复杂需求、精准写提示词
- 能不能引导 AI 多轮迭代修正
- 能不能识别 AI 幻觉和漏洞
- 典型考察点：
  - 给模糊业务需求 → 分层写结构化 Prompt（区分需求边界、约束条件、输出格式）
  - AI 输出错误 → 反向优化指令、纠错重做
  - 多轮对话从粗框架细化到可落地执行方案

#### 二、第一性原理商业思维（~30%）

安克核心价值观，所有任务强制围绕三个标准打分：

1. **回归用户本质** — 定位根本痛点，不做表面方案
2. **极致优化** — 量化指标，多方案对比择优
3. **长期协同** — 考虑长期价值和生态协同

固定思考流程：

```
定位业务根本痛点 → 量化指标（成本、销量、转化率、留存）→ 多版迭代方案对比 → 标注风险、限制条件、落地资源
```

##### 终局思维（HR 明确会考）

终局思维是安克面试中的核心考察维度，要求候选人**站在未来看现在**：

> 不是"我现在有什么资源、能做什么"，而是"5 年后这个市场/产品/用户需求的终局是什么 → 那个位置需要什么能力 → 今天我该建什么、放弃什么"。

**三段式推演框架**：

```
看终局 → 推路径 → 定今天
```

| 步骤 | 要回答的问题 | 在试炼中的体现 |
|---|---|---|
| 看终局 | 这个品类/市场 3-5 年后什么样？谁会赢？为什么？ | 方案抬头先写终极格局判断，再展开具体策略 |
| 推路径 | 从今天到终局，关键里程碑是什么？必打的仗是什么？ | 分阶段执行计划，每个阶段有明确的里程碑和验收标准 |
| 定今天 | 当前最优的资源投向是什么？该放弃什么？ | 方案中明确取舍——不做哪些事，为什么 |

**试炼中的实际运用**：

1. **做新品方案时**：不要只写功能列表。先判断这个品类（如储能/快充）3 年后的终局——是技术决胜还是渠道决胜？价格战还是品牌溢价？然后倒推你这个新品的定位该卡哪个生态位
2. **做营销预算分配时**：不要均分渠道。判断这个品牌在当地市场的终局目标是认知覆盖还是转化收割，倒推每个阶段的渠道重心
3. **做产品迭代方案时**：不要只修 Bug。判断用户需求的终局体验是什么，倒推这次迭代应该往哪个方向演进

**终局思维 vs 第一性原理的关系**：

- 第一性原理是**向下拆**：剥开表象找到最根本的物理/商业约束
- 终局思维是**向前看**：从终局倒推回来决定今天的行动
- 两者结合 = 方案既有深度（找到根本解），又有远见（不是短期打补丁）

#### 三、逻辑完整度（~20%）

- 拆解清晰、分层递进
- 方案有对比、有取舍理由
- 风险预判和应对措施

#### 四、交付规范（~10%）

- 文件完整、排版清晰
- 图表规范、格式统一

### 分岗位差异化任务

#### 市场 / GTM / 运营岗（非技术主流）

1. 海外销售数据复盘：给亚马逊/独立站原始销售表格，AI 清洗数据、同比环比、找销量下滑原因
2. 营销预算分配：固定预算（如 1000 万欧美新品牌投放），拆分渠道、测算 ROI、设数据看板
3. 用户分层运营方案：充电/音频产品海外用户，AI 生成分层策略、活动 SOP、KPI
4. 数据可视化：AI 生成 HTML 数据看板（销量、客单价、复购趋势）

#### 产品 / AI 产品岗

1. 0→1 新品方案：储能/耳机/快充新品，市场调研、用户痛点、核心功能、差异化卖点
2. 产品迭代优化：现有产品投诉问题 → 完整优化 PRD 框架
3. AI 硬件落地设计：边缘 AI、语音降噪、电池健康预测等，兼顾成本与体验

#### 研发 / 嵌入式 / 技术岗

1. Python 数据自动化脚本：清洗销售/测试数据、批量统计、输出分析报告
2. 简易可视化面板：Claude Code 生成前端页面展示硬件测试数据
3. 技术方案推演：AI Agent、本地大模型在消费电子硬件的适配方案

#### 供应链 / 职能岗

成本优化测算、库存周转模型、供应商分级管理方案，AI 做多场景测算对比

### 必做通用模块

#### 数据分析大题（全岗位）

给原始 CSV 业务数据，全程靠 AI 辅助：
- 数据清洗：剔除异常值、补全缺失
- 指标计算：增长率、市场份额、毛利、复购率
- 归因分析：什么因素影响业绩波动
- 产出可视化图表 + 文字分析结论

#### 方案整合与交付（收尾）

把前面所有内容整合为一份完整商业文档（Markdown）：

```
业务背景 → 核心问题 → 数据分析结论 → 完整落地策略 → 分阶段执行计划 → 风险 & 优化空间 → 量化预期收益
```

### 评分权重总览

| 维度 | 占比 | 关键点 |
|---|---|---|
| AI 使用能力 | 40% | Prompt 质量、多轮迭代、纠错、提效 |
| 商业业务思维 | 30% | 第一性原理、数据驱动、可落地、量化 |
| 逻辑完整度 | 20% | 拆解清晰、方案对比、风险预判 |
| 交付规范 | 10% | 文件完整、排版格式统一 |

### 核心认知：它到底在考什么？

**本质上考的是产品管理能力**（看清需求、结构化分析、产出方案、交付成果），**手段上是项目管理能力**（拆解任务、分配 AI 资源、把控进度和质量）。

角色定位：**你是项目经理/产品经理，AI 是你的下属**。你下达指令、检查产出、把控质量，AI 负责执行。

## 产品管理 + 项目管理知识体系（试炼实操手册）

> 以下每个知识点都标注了**是什么**和**在试炼中怎么用**，按需查阅。

---

### 一、产品管理核心知识（16 项）

#### 1. 第一性原理

**是什么**：把问题剥到最底层的基本事实，抛开类比和经验，从物理/商业的本质约束出发重新推导方案。

**试炼怎么用**：
- 遇到业务问题时，Prompt 先写：「请从第一性原理出发，分析这个问题的底层约束是什么，不要给出基于行业惯例的答案」
- 做新品方案时，先追问本质——用户买充电器买的是"充电速度"还是"随时有电的安全感"？本质不同，方案完全不同
- 方案中显式标注"第一性推导"段落，直接命中评分维度

#### 2. 用户分层 + LTV + UJM 用户旅程地图

**是什么**：
- 用户分层：按价值/行为将用户分群（新客/活跃/沉默/流失）
- LTV（Life Time Value）：单个用户全生命周期贡献的利润
- UJM（User Journey Map）：用户从认知→购买→使用→复购→推荐的完整路径

**试炼怎么用**：
- 做用户运营方案时，用 AI 生成分层策略：「请根据以下用户数据，按 LTV 高低分三层，每层给出不同的运营策略和预算分配」
- 产品迭代题中用 UJM 定位问题：「请画出充电产品用户从开箱到日常使用的完整旅程，标注每个触点的痛点和机会」
- 数据题中计算 LTV，对比不同渠道用户的长期价值差异

#### 3. 价值主张 + 差异化定位 + 竞品对标

**是什么**：
- 价值主张：你的产品给用户创造什么独特价值
- 差异化定位：在竞品地图中找到自己的生态位
- 竞品对标：系统对比定价、功能、渠道、用户评价

**试炼怎么用**：
- 新品方案题的核心框架，用 Prompt：「请帮我做 [产品] 的竞品对标分析，维度包括定价、核心功能、亚马逊评分、差评高频词，最后给出差异化定位建议」
- 方案中务必体现「我们为什么赢」——不是比竞品多做，是在关键点上做得更好

#### 4. MoSCoW 法则

**是什么**：需求优先级排序工具
- Must（必须有，否则产品不可用）
- Should（应该有，重要但可替代）
- Could（可以有，锦上添花）
- Won't（这次不做，明确放弃）

**试炼怎么用**：
- 写 PRD 或方案时，用 MoSCoW 给功能分级，避免"什么都重要"
- Prompt 示例：「请用 MoSCoW 法则对我列出的功能需求排序，并说明每项归类的原因」
- 这是展示「取舍思维」的最直接方式，阅卷加分

#### 5. 机会成本 + 取舍思维

**是什么**：
- 机会成本：选择 A 意味着放弃 B 的收益
- 取舍思维：成本、体验、性能三者不可能同时最优，必须做选择

**试炼怎么用**：
- 方案里必须写"我们选择不做的事"，并说明为什么
- 预算分配题尤其关键：「投入 A 渠道意味着放弃 B 渠道，选择 A 的机会成本是 B 的预估 ROI × 预算」
- 阅卷时"明确取舍"比"方案全面"得分更高

#### 6. 批判性验证（区分噪音 vs 刚需）

**是什么**：用户说的不一定是他真正需要的。通过交叉验证、行为数据比对、场景还原，区分真实刚需和随口反馈。

**试炼怎么用**：
- 这是 AI 协作的最高分项。拿到 AI 输出的方案后，主动质疑：「请用批判性视角审视以上方案——哪些结论可能基于噪音数据？哪些假设未经验证？」
- 在方案中单独一节写「方案局限性与待验证假设」，证明你不是无脑接受 AI 输出
- 与终局思维联动：用终局倒推来验证当下的需求是否值得投入

#### 7. PRD / MRD 完整结构

**是什么**：
- PRD（Product Requirement Document）：背景、目标用户、痛点、核心功能、交互规则、验收标准、风险
- MRD（Market Requirement Document）：市场规模、竞品、机会点、商业化目标

**试炼怎么用**：
- AI 飞行员的最终交付文档应具备 PRD 骨架，用 Prompt：「请按照 PRD 结构输出以下方案：1.背景 2.目标用户 3.痛点 4.核心功能 5.验收标准 6.风险」
- 不要写成随笔——结构化的文档 = 交付规范满分

#### 8. 用户调研输出

**是什么**：问卷设计、差评归因、访谈结论提炼、需求池管理——把杂乱用户声音转化为结构化洞察。

**试炼怎么用**：
- 数据题里给的 CSV 就相当于用户行为数据，要把数字翻译成洞察
- Prompt：「请分析以下差评数据，按频次排序 Top5 痛点，归因到产品/运营/客服三个环节，并给出优先级改进建议」
- 需求池管理：用 AI 把痛点→需求→功能→排期串成一条线

#### 9. 产品迭代复盘模板

**是什么**：版本目标 → 数据结果 → 未达预期原因 → 下一轮优化动作。形成闭环学习。

**试炼怎么用**：
- 产品迭代题的核心输出框架
- 方案收尾必须包含复盘模板：「假设方案已上线 3 个月，请预设可能的复盘结论——哪些指标会成为成败判断依据？」
- 阅卷要点：不只"向前看"（终局），也要"向后学"（复盘）

#### 10. 增长/营收/体验类指标

**是什么**：
- 增长类：曝光量、CTR（点击率）、CVR（转化率）、复购率、留存率（次日/30日）
- 营收类：客单价、单品毛利、毛利率、库存周转、单品贡献占比
- 体验类：投诉率、退货率、使用时长、功能渗透率

**试炼怎么用**：
- 数据题直接考。关键是**不只会算，还要会归因**——指标波动背后是产品问题还是运营问题还是供应链问题？
- Prompt：「请计算以下数据的同比环比增长率、客单价、复购率，并指出异常波动的可能原因」
- 方案里用到指标时，必须带量化数字，否则"商业思维"维度扣分

#### 11. 归因分析

**是什么**：区分数据波动到底是产品（功能问题）、运营（活动影响）、还是供应链（缺货/物流）导致的。

**试炼怎么用**：
- 数据题最高分项。不只算数，要做归因判断
- Prompt：「以下销售数据下滑，请从产品维度（评分、退货率）、运营维度（流量、转化）、供应链维度（库存、时效）分别分析可能的贡献因素」
- 方案中把归因用 MECE（相互独立、完全穷尽）结构呈现

#### 12. 硬件产品研发链路

**是什么**：需求 → ID 设计 → 结构 → 硬件调试 → 试产 → 上市 → 迭代。与纯软件产品流程不同，硬件有模具、物料、产线排期等不可逆节点。

**试炼怎么用**：
- 新品方案必须体现对硬件节奏的理解——试产节点、模具锁定时间点、合规认证周期
- Prompt：「请按硬件研发流程，给出 [产品] 从立项到上市的关键里程碑，标注每个阶段的风险点和不可逆决策」
- 纯互联网产品思维套到硬件上会不落地，阅卷人会看出来

#### 13. 海外电商用户痛点

**是什么**：充电类（速度、发热、兼容性）、音频类（降噪、延迟、佩戴舒适度）、储能类（容量、重量、户外可靠性）——安克品类的核心用户关注点。

**试炼怎么用**：
- 这些是出题场景，不懂就抓不住题目重点
- Prompt 示例：「假设你是亚马逊上 Anker 充电产品的目标用户，请列出购买决策中最关心的 5 个因素，按优先级排序」
- 方案中扣住具体品类痛点，不要空谈"用户体验"

#### 14. 竞品分析维度

**是什么**：定价区间、核心功能差异、渠道策略、用户评价短板、BOM 成本差异。不只是功能对比清单。

**试炼怎么用**：
- Prompt：「请对比 [产品A] 和 [竞品B]，从定价、功能、亚马逊评分分布、差评高频词、毛利率估算五个维度分析各自的优劣势」
- 竞品分析结果驱动你的差异化定位——不是为了分析而分析

#### 15. 新品商业化测算

**是什么**：定价区间、盈亏平衡销量（Break-even）、投放 ROI 预估、爬坡期现金流。回答"这个产品值不值得做"。

**试炼怎么用**：
- 新品方案题的核心一页——不能只谈产品不谈赚钱
- Prompt：「假设 [产品] BOM 成本 $X，请估算不同定价区间的盈亏平衡销量，并给出 12 个月的 ROI 预测」
- 阅卷时"对钱有感觉"是产品岗的强加分项

#### 16. AI + 产品结合

**是什么**：用 AI 做差评挖掘、方案对比、需求拆解验证；AI 硬件落地（边缘降噪、电池算法、智能识别等）。

**试炼怎么用**：
- 这是全场最高分值区。展示你用 AI 不止是"生成内容"，而是"深度协作分析"
- Prompt：「请分析以下 500 条亚马逊差评，用 AI 提取高频关键词、归因分类、并给出产品改进的 Top3 优先级建议」
- 做完后追加一轮：「请质疑你刚才的分析结论，指出可能的偏差来源」——这就是"批判性验证"，直接拉分

### 二、项目管理核心知识（13 项）

#### 1. 项目五阶段

**是什么**：启动 → 规划 → 执行 → 监控 → 收尾。PMBOK 标准框架。

**试炼怎么用**：
- 方案的分阶段执行计划部分直接套这个结构
- Prompt：「请按项目五阶段框架，输出 [产品] 的落地执行计划，每个阶段标注关键产出物」
- 阅卷看到"执行计划"有结构化分阶段 = 逻辑完整度加分

#### 2. 项目核心三角（范围/时间/成本）

**是什么**：三个要素互相制约——范围大了时间就长成本就高；砍范围才能抢时间。硬件项目在这个三角里几乎每天都要做决策。

**试炼怎么用**：
- 方案中遇到资源约束时，用三角语言分析：「如果上市时间提前一个月，要么砍功能范围（砍哪些），要么追加成本（加多少预算）」
- Prompt：「请用项目三角框架，分析 [场景] 中的权衡选项，给出推荐方案并说明理由」

#### 3. 干系人管理

**是什么**：把研发、供应链、市场、销售等各方的期望对齐。安克是硬件公司，跨部门协作是日常。

**试炼怎么用**：
- 方案中加上"干系人分析"——这个方案涉及哪些部门、各自关注什么、怎么对齐
- 价值观测评的"团队协作"场景也要用干系人思维答题

#### 4. WBS 工作拆解

**是什么**：Work Breakdown Structure，把大项目拆到最小可执行任务。拆到"一个人可以独立完成"的颗粒度。

**试炼怎么用**：
- 这是试炼的「任务拆解」评分维度最直接体现
- Prompt：「请用 WBS 方法将 [项目] 拆解为三级任务树，第三级任务必须是单人可实现、有明确验收标准的粒度」
- 方案中 WBS 树 + 责任分配 = 逻辑完整度加分

#### 5. 甘特图 + 关键路径 CPM

**是什么**：
- 甘特图：时间线上的任务排布，显示开始/结束/依赖关系
- CPM（Critical Path Method）：找到决定项目最短工期的那条"瓶颈路径"

**试炼怎么用**：
- 让 AI 生成时间线排期：「请为 [项目] 生成甘特图逻辑，标明里程碑、前置依赖和关键路径」
- 即使系统不支持画图，用 Markdown 表格或文字描述也能体现排期能力

#### 6. 敏捷基础

**是什么**：迭代周期（Sprint）、需求看板（To Do/In Progress/Done）、每日站会、版本节奏。不是只有 Scrum 才算敏捷，核心是短周期反馈。

**试炼怎么用**：
- 产品迭代题的最自然表达：「建议采用两周 Sprint 节奏，每轮聚焦一个核心功能假设，用数据验证后再决定下一轮方向」
- 不要死搬 Scrum 术语——试炼考的是敏捷思维，不是流程仪式

#### 7. 资源分配

**是什么**：人力、产线、预算在不同阶段的最优配置。前期研发占比高，中期产线爬坡，后期市场投放集中。

**试炼怎么用**：
- 预算分配题：「请按项目四阶段（研发/试产/量产/上市）分配以下 1000 万预算，每阶段说明分配逻辑和 ROI 预期」
- 资源分配要体现"非均等"——敢把资源集中在关键节点才是好方案

#### 8. 风险识别维度

**是什么**：硬件项目的五大风险维度——研发延期、物料涨价、库存积压、海外合规、差评危机。

**试炼怎么用**：
- 每个方案必须附风险矩阵，这是提分必写内容
- Prompt：「请从研发、供应链、市场、合规、口碑五个维度，列出 [方案] 的 Top5 风险，并给出应对措施」
- 阅卷看到风险章节 = 思维全面，没写 = 基本功缺失

#### 9. 风险分级（概率 × 影响）

**是什么**：不是所有风险都值得关注。按发生概率 × 影响程度做矩阵，分出高优（高概率高影响）和低优。

**试炼怎么用**：
- 用 3×3 或 5×5 风险矩阵呈现
- Prompt：「请将上述风险按发生概率和影响程度分为高/中/低三级，用矩阵形式呈现，并标明每个风险的建议应对等级」

#### 10. 风险应对策略

**是什么**：规避（不让它发生）、转移（让保险或供应商承担）、缓解（降低概率或影响）、接受（兜底预案）。四个策略对应不同风险类型。

**试炼怎么用**：
- 每个识别出的风险配一个应对策略
- 这是展示批判性思维的关键——方案不只是设想一切顺利，也要能应对不顺利

#### 11. 5Why 根因分析

**是什么**：连续追问五个"为什么"，从表象一层层挖到根本原因。丰田生产系统的经典工具。

**试炼怎么用**：
- 数据题里做归因的终极武器：「销量下滑 → 为什么？→ 退货率上升 → 为什么？→ ... 直到找到底层问题」
- Prompt：「请用 5Why 方法分析 [问题]，不要停在表面原因」
- 与安克"深挖、好奇心"价值观完美匹配

#### 12. BOM 成本管控 + 试产/量产节点 + 库存项目

**是什么**：
- BOM（Bill of Materials）：硬件产品的物料清单和成本结构
- 试产/量产节点：EVT→DVT→PVT→MP，每个阶段产出物不同
- 库存项目：滞销清仓策略、新品备货量测算、周转天数优化

**试炼怎么用**：
- 这是安克作为硬件公司的关键差异——纯互联网 PM 不会这个
- Prompt：「假设 [产品] 目标毛利率 45%，BOM 成本超预算 10%，请给出降本方案，区分短期切换供应商和长期重新设计两种路径」
- 库存周转：「请分析以下库存数据，计算周转天数，识别滞销风险，给出清仓方案」

#### 13. 项目复盘四件套

**是什么**：目标达成度 → 超预期/未达成事项 → 过程卡点与协作问题 → 沉淀可复用流程 + 下一期改进动作。

**试炼怎么用**：
- 方案收尾的标准动作：「请为此方案预设一个上线 3 个月后的复盘框架，包含目标达成判断标准、可能卡点、以及可沉淀的方法论」
- 阅卷时"复盘意识" = 长期主义价值观的直接体现

## Prompt 参考模板库（直接复制即用）

> 核心原则：**结构化 Prompt = 背景 + 目标 + 约束 + 输出格式 + 迭代要求**。每条模板都会触发多轮协作，不是一次输出就完了。

### 一、通用 Prompt 公式（所有题型的骨架）

```
【角色】你是一个[消费电子出海品牌]的[产品经理/项目经理]
【背景】[一句话描述业务场景]
【任务】[要解决的具体问题]
【约束】[限制条件：预算/时间/品类/市场]
【输出】请按以下结构输出：[1.xxx 2.xxx 3.xxx]
【迭代】输出后我会逐段审核，请准备好根据反馈修改
```

### 二、按题型分类的 Prompt 模板

#### 题型 1：数据清洗与分析

**第一步：数据探索**
```
我上传了一份亚马逊[产品品类]的销售数据（CSV格式）。
请先做数据概览：
1. 列名及含义
2. 数据行数、缺失值比例
3. 时间范围
4. 核心指标的描述性统计（均值、中位数、标准差）
5. 明显的异常值标记
```

**第二步：深挖计算**
```
请进行以下分析：
1. 按月度计算 GMV、订单量、客单价的同比和环比增长率
2. 计算各 SKU 的毛利率和单品贡献占比（毛利率 = (售价-成本)/售价）
3. 计算用户 30 日复购率
4. 对销量 Top 5 和 Bottom 5 的 SKU 做差异对比
5. 输出格式：每个指标用 Markdown 表格呈现，附一句话趋势判断
```

**第三步：可视化**
```
请用 HTML/CSS 生成一个数据看板，包含：
- 月度 GMV 趋势折线图
- 各 SKU 毛利率柱状图
- 复购率变化曲线
- Top/Bottom 5 SKU 对比卡片
要求：可直接在浏览器打开，配色简洁专业，适配浅色和深色背景
```

#### 题型 2：归因分析（销量下滑/退货率上升等）

```
【背景】[产品]在[时间段]出现[指标异常，如：退货率从 3% 升至 8%]
【任务】请用 MECE 框架从以下三个维度做归因分析：

1. 产品维度：评分变化、差评关键词、功能投诉分类、硬件故障率
2. 运营维度：流量来源变化、Listing 修改记录、竞品促销活动、广告投放调整
3. 供应链维度：库存深度、发货时效、物流投诉率、包装破损率

对每个维度，请：
- 列出最可能的 2-3 个原因
- 标注判断依据和置信度（高/中/低）
- 给出可验证的下一步排查方向

最后用 5Why 方法对最可能的原因深挖到底层根因。
```

#### 题型 3：0→1 新品方案（产品岗核心题）

**第一步：终局判断 + 机会扫描**
```
【背景】Anker 计划进入 [品类] 市场，目标 [地区]
【任务】请从终局思维出发分析：

1. 终局判断：这个品类在 [地区] 市场 3-5 年后的终局格局是什么？
   - 价格战还是品牌溢价？
   - 技术决胜还是渠道决胜？
   - 头部玩家会是谁？各自的护城河是什么？

2. 机会窗口：当前的进入时机为什么是现在？窗口期有多长？

3. 用户分析：
   - 目标用户画像是谁？购买决策链是怎样的？
   - 亚马逊该品类 Top 10 差评的高频关键词是什么？反映了哪些未满足的需求？

4. 竞品格局：Top 5 竞品的定价区间、核心差异化卖点、评分短板
```

**第二步：产品定义**
```
基于以上分析，请输出新品的产品定义：

1. 价值主张一句话（用户为什么选你而不选竞品？）
2. 核心功能列表，用 MoSCoW 排序：
   - Must（不可或缺的 3 个功能）
   - Should（差异化加分项 3 个）
   - Could（锦上添花 2 个）
   - Won't（明确不做并说明原因）
3. 定价策略：建议零售价区间、毛利率目标、盈亏平衡销量
4. 上市路线图：从立项到量产的关键里程碑（含硬件研发节点 EVT/DVT/PVT/MP）
```

**第三步：风险与商业化**
```
1. 风险矩阵（按概率×影响分级）：
   - 研发风险（技术可行性、专利壁垒）
   - 供应链风险（物料成本波动、产能爬坡）
   - 市场风险（竞品反应、渠道接受度）
   - 合规风险（[地区] 的认证要求）

2. 商业化测算：
   - 12 个月销量预估（低/中/高三个场景）
   - ROI 测算：研发投入 + 模具 + 首批备货 vs. 12 个月毛利
   - 爬坡计划：前 3 个月的产能和渠道铺设节奏
```

#### 题型 4：产品迭代优化

```
【背景】[产品] 在亚马逊上的差评主要集中在 [问题A]、[问题B]、[问题C]
【任务】请输出产品迭代方案：

1. 问题归因：
   - 用 5Why 对每个问题挖到根因
   - 区分产品设计缺陷 vs. 用户使用场景不匹配 vs. 预期管理问题

2. 解决方案对比：
   - 对每个问题给出 2-3 个解决方案（低成本快修 vs. 结构性改进）
   - 方案对比表：成本、开发周期、预期效果、副作用风险

3. 迭代优先级（MoSCoW）：
   - 结合用户影响面 × 实现成本，排序优先级
   - 明确哪些放下个版本做，哪些永远不做

4. 验证计划：
   - 上线后用什么指标判断改好了？
   - 预设"如果改完 60 天后退货率没降到 X%，复盘方向是什么？"

5. 复盘框架：
   - 预设 3 个月后的复盘模板（目标达成度、超预期/未达、卡点、可复用流程）
```

#### 题型 5：预算分配 / 资源排期

```
【背景】[新产品/新品牌] 进入 [市场]，总预算 $1000 万
【任务】请输出预算分配方案：

1. 终局目标校准：这个阶段的核心目标是认知覆盖还是转化收割？
   （不同目标 = 渠道权重完全不同）

2. 分阶段分配：
   - 研发阶段（X%）：模具、试产、认证
   - 试产阶段（X%）：小批量验证、用户测试
   - 量产阶段（X%）：首批备货、产能爬坡
   - 市场阶段（X%）：渠道铺设、KOL、广告

3. 渠道矩阵（以市场预算为例）：
   - 亚马逊站内广告：X%，预期 ROAS，适合目标
   - KOL/PR：X%，预期覆盖，适合目标
   - 独立站/DTC：X%，预期转化，适合目标
   - 线下渠道：X%，铺货节奏

4. 取舍声明：
   - 明确不投哪些渠道，为什么
   - 每个选择的机会成本是什么
   - 什么信号出现时（如 ROAS 低于 X），启动 B 计划
```

#### 题型 6：用户分层运营

```
【背景】[品牌] 在 [地区] 已有 [X 万] 用户，需提升复购率和 LTV
【任务】请输出用户运营方案：

1. 用户分层：
   - 按购买频次×客单价分四象限（高价值/潜力/沉睡/流失）
   - 每层用户画像和核心诉求

2. 分层策略：
   - 高价值用户：如何做忠诚度运营？（会员、新品优先、UGC 激励）
   - 潜力用户：如何提升客单价和跨品类购买？
   - 沉睡用户：唤醒策略和触达节奏
   - 流失用户：流失原因分析 + 挽回 ROI 测算

3. 活动 SOP：
   - 按季度排运营日历（新品季/大促季/淡季的内容节奏）
   - 每场活动的 KPI 和漏斗预期

4. AI 差评挖掘：
   - 请 AI 分析该品类 500 条差评，提取 Top 3 产品改进方向
   - 将改进方向对应到用户分层策略中
```

#### 题型 7：竞品分析

```
【任务】对 [竞品A]、[竞品B]、[竞品C] 做深度对标分析：

1. 基本面：定价、BSR 排名、评分、评论数、上架时间
2. 功能对比矩阵：[列出 6-8 个关键维度，标注各自的优劣势]

5. 差异化定位建议：基于以上分析，我们的切入点和"为什么赢"
```

#### 题型 8：风险识别与应对

```
【任务】请对 [方案/项目] 做全面风险评估：

1. 风险识别（五维度）：
   - 研发：延期、技术不可行、专利冲突
   - 供应链：物料涨价、供应商断供、良率不达标
   - 市场：竞品降价、渠道政策变化、需求误判
   - 合规：[地区] 的安规/环保/数据隐私要求
   - 口碑：差评风暴、社交媒体危机

2. 风险分级（概率 × 影响矩阵）：
   | 风险 | 概率 | 影响 | 等级 | 应对策略 |
   | xxx  | 高   | 中   | 红色 | 规避     |

3. 应对策略：
   - 规避：怎么设计让风险不发生？
   - 转移：哪些风险可以转给供应商/保险？
   - 缓解：降低概率或影响的措施
   - 接受：什么风险值得"赌"，兜底方案是什么？
```

### 三、加分 Prompt 组合（在每轮 AI 输出后追加）

#### 组合 1：批判性验证追问
```
请以批判性视角审视你刚才输出的方案：
1. 哪些结论基于假设而非数据？请逐一标注假设并评估其稳健性
2. 如果你是这个方案的反对者，你会攻击哪三个点？
3. 有没有反例或边界情况被忽略了？
```

#### 组合 2：终局思维反推
```
请用终局思维重新审视这个方案：
1. 如果 3 年后这个品类胜负已定，这个方案里的哪些动作回头看可能是错的？
2. 哪些短期看起来"正确"的决策，长期会变成包袱？
3. 现在没有考虑到的最大变量是什么？
```

#### 组合 3：多方案对比
```
请基于同一问题给出三个不同的方案路径：
- 方案A：激进型（追求速度/份额，承担高风险）
- 方案B：稳健型（平衡速度与质量）
- 方案C：保守型（最小可行范围，快速验证）

每个方案标注：适用场景、优缺点、所需资源、关键假设
并给出你的推荐方案及理由。
```

#### 组合 4：多轮迭代优化
```
第一轮输出 → 检查是否偏离要求 → 补充约束/纠正方向
第二轮修正 → 追问细节和落地性 → 要求补充量化数据
第三轮精炼 → 质疑逻辑漏洞 → 要求做风险兜底
第四轮交付 → 检查格式完整性 → 确认所有模块无遗漏
```

### 高频踩坑 & 备考要点

1. ❌ **不要只让 AI 输出答案**：必须展示自己拆解需求 → 校验 AI 结果 → 多轮优化的完整过程。只复制 AI 内容 = 大幅低分
2. ✅ **全程紧扣安克出海消费电子场景**：充电、音频、储能、智能家居、亚马逊跨境
3. ✅ **Prompt 是核心竞争力**：熟练结构化 Prompt 写法——背景 + 目标 + 约束 + 输出格式 + 迭代要求
4. ✅ **掌握基础商业指标**：毛利、ROI、环比同比、用户 LTV、渠道转化率
5. ✅ **主动纠错是加分项**：一旦察觉 AI 乱说，立刻指出纠正，这恰好证明你的判断力
6. ✅ **务必提交**：时间到了没点提交 = 白做
