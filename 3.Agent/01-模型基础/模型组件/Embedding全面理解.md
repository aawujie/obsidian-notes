# Embedding 全面理解

> 创建日期：2026-03-29
> 来源：学习讨论整理

---

## 核心问题：为什么需要 Embedding

模型只能处理数字，不能处理文字。

**最简单的方案 one-hot：**
```
词表 = ["猫", "狗", "汽车"]
"猫"  → [1, 0, 0]
"狗"  → [0, 1, 0]
"汽车" → [0, 0, 1]
```

**问题：**
- 词表 10 万个词 → 每个词是 10 万维稀疏向量，太大
- "猫"和"狗"向量完全没关系，但语义上很相近

**Embedding 解决这两个问题：低维、有语义。**

---

## Embedding 是什么

把离散的词映射到连续的向量空间：

```
"猫"  →  [0.2, -0.5, 0.8, 0.1, ...]  (768维)
"狗"  →  [0.3, -0.4, 0.7, 0.2, ...]
"汽车" →  [-0.8, 0.1, -0.3, 0.9, ...]
```

**语义相近的词，向量距离也近。**

---

## Embedding 怎么学

本质是一个可训练的矩阵，形状是 `(vocab_size, hidden_dim)`：

```python
embedding = nn.Embedding(10000, 768)
# 10000 个词，每个词对应 768 维向量
# 训练时自动调整，让语义相近的词向量接近
```

---

## ⚠️ 关键区分：静态 vs 动态

### 静态 Embedding（Word2Vec / GloVe）

```
"苹果" 永远是同一个向量
→ 不管是"苹果手机"还是"吃苹果"，向量完全一样
```

### 动态 Embedding（BERT / Transformer）

```
"苹果手机真好用" → "苹果"的最终表示偏向科技
"苹果真甜"       → "苹果"的最终表示偏向食物
```

**但这里有个重要的精确说法：**

> ✅ 准确：同一个词，上下文不同，**Transformer 输出的 hidden state 不同**
>
> ❌ 不准确："embedding 不同"（Embedding 表本身没有变）

---

## Transformer 如何实现"动态"

### 第一步：查 Embedding 表（静态）

```
"苹果手机真好用" 和 "苹果真甜"

两句里的"苹果" → 查 Embedding 表 → 完全一样的向量
```

### 第二步：经过 Attention，向量被上下文"染色"

每个词会问其他所有词：**"你和我有多相关？"**

```python
Q = x · Wq   # 查询：我在找什么信息？
K = x · Wk   # 键：我有什么信息？
V = x · Wv   # 值：我的实际内容

scores  = Q · K^T / √d      # 相关度打分
weights = softmax(scores)    # 归一化为概率
output  = weights · V        # 加权聚合
```

**为什么同一个词输出不同？**

```
句子1: "苹果 手机 真 好用"
K = [K_苹果, K_手机, K_真, K_好用]   ← 有"手机"

句子2: "苹果 真 甜"
K = [K_苹果, K_真, K_甜]             ← 有"甜"
```

Q 相同，但 K/V 不同（上下文不同）→ 注意力权重不同 → 加权求和结果不同。

**不是 Q 不同，是 K/V 不同。**

### 每层 Attention 的效果

```
第 0 层（Embedding 查表）：
  苹果₁ = [0.2, 0.5, ...]  ← 两句完全一样

第 1 层（看了一遍上下文）：
  苹果₁ = [0.8, 0.3, ...]  ← 被"手机"影响了
  苹果₂ = [0.1, 0.9, ...]  ← 被"甜"影响了

第 12 层（看了 12 遍上下文）：
  苹果₁ = [科技语义...]
  苹果₂ = [食物语义...]
```

## 三种粒度的 Embedding

| 粒度 | 名称 | 输出 | 用途 |
|------|------|------|------|
| 词级别 | Token Embedding | 每个 token 一个向量 | 模型输入层 |
| 词+上下文 | Contextualized Embedding (Hidden State) | 每个 token 一个动态向量 | 下游任务 |
| 句子/段落级别 | Sentence Embedding | 整段文字一个向量 | RAG 检索 |

---

## RAG 里的 Embedding

RAG 用的是 **Sentence Embedding**，目的是语义搜索：

```
【建库阶段】
文档 → Embedding 模型 → 一个向量 → 存入向量数据库

【查询阶段】
问题 → Embedding 模型 → 一个向量
     → 在向量数据库里找最近的向量
     → 取出相关文档
     → 塞进 prompt → LLM 回答
```

**为什么比关键词搜索好？**
```
问题：  "苹果手机怎么样"
文档A： "iPhone 是最好的智能手机"  ← 没有"苹果"这个词

关键词搜索：找不到 A
Embedding 搜索：找到 A（语义相似）✅
```

---

## 向量空间的语义关系

Word2Vec 著名例子：

```
国王 - 男人 + 女人 ≈ 女王
king_vec - man_vec + woman_vec ≈ queen_vec
```

向量之间可以做加减法，结果还有语义！

---

## 命名混乱总结

**"Embedding"这个词被过度使用了：**

- Embedding 表里的向量 → embedding
- Transformer 输出的 hidden state → 也叫 embedding
- 整句话的表示 → 也叫 embedding

**遇到时问自己：是查表出来的？还是过完模型的？**

| 说法 | 准确吗 |
|------|--------|
| "Embedding 表里的向量会随上下文变" | ❌ |
| "Transformer 输出的 hidden state 会随上下文变" | ✅ |
| "Contextualized Embedding" | 习惯说法，指的其实是 hidden state |
