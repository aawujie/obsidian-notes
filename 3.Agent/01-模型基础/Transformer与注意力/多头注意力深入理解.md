# 多头注意力 — 深入理解

> 整理日期: 2026-03-19
> 前置知识: [[注意力机制入门图解]]、[[Transformer架构从零理解]]

---

## 1. 为什么要"多头"？

单头注意力只能学一种关注模式。多头让模型**同时从多个角度**看同一段话。

---

## 2. d_k = d_model // num_heads 是什么意思？

假设 `d_model = 64`，`num_heads = 4`：

```
词向量: [████████████████████████████████████████████████████████████████]
         ← d_model = 64 →

拆分成 4 个头:
  头1: [████████████████]  ← d_k = 16
  头2: [████████████████]  ← d_k = 16
  头3: [████████████████]  ← d_k = 16
  头4: [████████████████]  ← d_k = 16
```

`//` 是 Python 整数除法（64 // 4 = 16）。维度必须是整数。

---

## 3. 每个头的区别是什么？

### 不是"拿到不同的维度"，是"戴着不同的眼镜看同一个词"

每个头有**不同的 W_q、W_k、W_v 权重矩阵**（实际上是一个大矩阵的不同切片）。

```
头1 的 W_q 部分: 16×64 矩阵（16 行，每行 64 个参数）
头2 的 W_q 部分: 另一个 16×64 矩阵（参数值不同）
```

**每个头的每一个输出维度，都是原始 64 维的加权组合：**

```
头1的第0个输出 = w₀₀×原始[0] + w₀₁×原始[1] + ... + w₀₆₃×原始[63]
```

所以每个头看到的是整个词的信息，只是"投影角度"不同。

### 摄影类比

```
同一座建筑 (= 完整的 64 维词向量)

摄影师1 从正面拍 → 看到门和窗户 (语法特征)
摄影师2 从侧面拍 → 看到层高结构 (语义特征)
摄影师3 从上方拍 → 看到布局位置 (位置关系)
摄影师4 从内部拍 → 看到装修细节 (词义细节)

每个摄影师都看到了整栋建筑，只是角度不同！
不是把建筑锯成 4 块。
```

### 训练后的实际例子

句子: "The cat sat on the mat because it was tired"

| 头 | 可能学到的关注模式 | "it" 最关注 |
|---|---|---|
| 头1 | 指代关系 | → "cat" |
| 头2 | 局部语法 | → "was" |
| 头3 | 介词搭配 | → "mat" |
| 头4 | 因果关系 | → "tired" |

---

## 4. 因果关系：为什么每个头会"分化"？

**不是**"因为拿到不同维度 → 所以权重不同"
**而是**"随机初始化 + 独立计算 → 训练中自然分化"

```
初始化: W_q 随机初始化 → 头1和头2本来就有不同的初始权重

训练中: 
  头1 用自己的权重独立算注意力
  头2 用自己的权重独立算注意力
  ↓
  loss 对不同头的权重给出不同的梯度
  ↓
  经过数千步训练，每个头走上了不同的"职业道路"
```

类比：一个班的学生刚入学时差不多，但分了不同组做不同项目后，每个人擅长的领域就不一样了。

---

## 5. 代码中的关键步骤

```python
# 1. 线性投影 (64→64)
Q = self.W_q(Q)  # (batch, seq, 64) → (batch, seq, 64)

# 2. 拆分多头 
Q = Q.view(batch, seq, 4, 16)  # → (batch, seq, 4头, 每头16维)

# 3. 转置，让每个头独立计算
Q = Q.transpose(1, 2)  # → (batch, 4头, seq, 16)

# 4. 每个头独立做注意力
attn = softmax(Q @ K.T / sqrt(16)) @ V

# 5. 拼接回来
out = out.transpose(1, 2).contiguous().view(batch, seq, 64)

# 6. 最终线性投影 (融合多头信息)
out = self.W_o(out)
```

## 6. 从文本到向量：完整流水线

### 第 1 步：分词 + 编号

```
"猫 吃 鱼" → 分词 → ["猫", "吃", "鱼"] → 查词表 → [42, 128, 256]
```

**42、128、256 就是编号，没有任何含义。** 就像学号不包含性格和长相。

### 第 2 步：查嵌入表 (nn.Embedding)

```python
embedding = nn.Embedding(10000, 64)  # 10000个词 × 64维
vectors = embedding(torch.tensor([42, 128, 256]))
# = embedding.weight[42], embedding.weight[128], embedding.weight[256]
# 输出形状: (3, 64) — 3个词，每个64维
```

### 第 3 步：加位置编码

```python
vectors = vectors + positional_encoding  # 注入位置信息
```

### 完整流程图

```
"猫 吃 鱼"           ← 原始文本
    ↓ 分词 + 查词表
[42, 128, 256]        ← 整数编号 (无含义) ← 模型的输入
    ↓ nn.Embedding 查表
(3, 64) 矩阵          ← 64维向量 (训练前=随机, 训练后=词义)
    ↓ + 位置编码
(3, 64) 矩阵          ← 词义 + 位置
    ↓ 送入编码器
```

### 每个阶段包含什么信息？

| 阶段 | 包含信息 | 备注 |
|---|---|---|
| 编号 `[42, 128, 256]` | **无** | 纯门牌号 |
| 训练前的嵌入向量 | **无** | 随机数 |
| 训练后的嵌入向量 | **词义** | "猫"≈"狗"，远离"桌子" |
| + 位置编码 | **词义 + 位置** | 句首/句尾的"猫"不同了 |
| 经过 Self-Attention | **词义 + 位置 + 上下文** | "猫吃鱼"的"吃"≠"吃亏"的"吃" |

> **Transformer 最强大的地方**: Self-Attention 让同一个字根据上下文动态变化。
> "猫**吃**鱼" → "吃"偏向"进食"；"他**吃**了亏" → "吃"偏向"承受"。
> 传统 Word2Vec 做不到这一点（每个词只有一个固定向量）。

## 7. 词向量是怎么做成 64 维的？

### 真相 1：开始时全是随机的

```python
embedding = nn.Embedding(vocab_size=10000, d_model=64)
```

创建一张 10000×64 的查找表，每个词分配 64 个随机数：

```
"猫"  → [0.12, -0.34, 0.78, ..., 0.56]   ← 64个随机数
"狗"  → [-0.45, 0.23, -0.11, ..., 0.89]  ← 64个随机数
"桌子" → [0.67, 0.05, -0.92, ..., -0.33]  ← 64个随机数
```

刚开始"猫"和"桌子"的向量没有任何区别——都是随机的。

### 真相 2：没人手动设计"第 N 维存什么"

64 个维度里**没有一个维度有预设含义**。不是"第0维=词义，第1维=语法"。

### 真相 3：训练让它们变得有意义

```
训练步骤 1~100000:
  模型反复看到 "猫 吃 鱼"、"狗 吃 骨头"、"猫 坐在 垫子上"...
  
  发现: "猫"和"狗"出现的位置经常可以互换
  → loss 把"猫"和"狗"的向量调得越来越近
  
  发现: "桌子"不能出现在这些位置
  → loss 把"桌子"的向量调得远离"猫"和"狗"
```

**经过百万次训练后**，64 维向量自动编码了：
- **词义相似性**：猫≈狗，远离桌子
- **语法角色**：名词 vs 动词的向量分布不同
- **语义关系**：国王-王后 ≈ 男人-女人（著名的 Word2Vec 发现）

### GPS 类比

给所有城市分配坐标：
- **随机阶段**：北京=(3.2, -1.5)，上海=(0.8, 4.1) ← 毫无意义
- **训练后**：地理近的城市坐标也近；文化近的在另一个方向上也近
- 没人规定"第一维是经度"——但训练后**自动学到了**类似经度的东西

### 位置信息不在词嵌入里

**词嵌入只编码词义，不包含位置！** "猫"不管在句首还是句尾，查表得到的向量都一样。

这就是为什么 Transformer 需要额外加[[位置编码从零理解|位置编码]]：

```python
x = embedding(tokens)        # 只有词义，没有位置
x = x + positional_encoding  # 加上位置信号 → 句首和句尾的"猫"变得不同
```

### 词嵌入 + 位置编码 → 最终输入

```
"猫"的最终输入向量 =
    词嵌入 (训练学到的词义)
  + 位置编码 (sin/cos 算出的位置信号)
──────────────────────────
    包含了词义 + 位置的 64 维向量

这个向量才是 Transformer 实际使用的输入。
```

## 8. 头数 vs 每头维度的权衡

头太多，每头维度太小，学不到东西：

```
d_model = 64
  4 头:  d_k = 16  ✅ 够用
  8 头:  d_k = 8   ⚠️ 有点紧
  32 头: d_k = 2   ❌ 太小
  64 头: d_k = 1   ❌ 一个数字没法表示任何模式
```

**原论文的选择**：d_k 始终保持在 **64** 左右。头数加倍时 d_model 也加倍。

| 配置 | d_model | num_heads | d_k |
|---|---|---|---|
| Base | 512 | 8 | 64 |
| Big | 1024 | 16 | 64 |

**设计规则**：先定 d_k（通常 64），再算 num_heads = d_model / d_k。

### 头会学到重复的特性吗？

**会！** 论文 "Are Sixteen Heads Really Better than One?" 发现：
- 8 个头里砍掉 4~5 个，性能几乎不变
- 多个头经常学到相似的模式（比如都在看邻近词）

**原因：**
1. 随机初始化偶然接近 → 训练后走上相似路径
2. 某些模式太重要（如看邻近词），多个头自发学到同一模式 = 天然"备份"
3. 标准 loss 没有"去重"惩罚

**解决方案：**

| 方法 | 做法 | 效果 |
|---|---|---|
| 正则化约束 | loss 里惩罚相似头 | 增加多样性 |
| 头剪枝 (Pruning) | 训练后删冗余头 | 减计算量，性能不变 |
| 共享参数 | 头之间共享部分权重 | 减参数量 |

实际中不太担心：大模型有足够多的头，冗余反而增加鲁棒性。

## 9. 不同语料训练 → 同词不同向量

同一个词在不同模型里的 embedding **完全不同**：

```
模型 A（新闻语料）: "苹果" → [-0.8, 0.3, ...]  偏向"水果"
模型 B（科技语料）: "苹果" → [0.6, -0.2, ...]   偏向"公司"
```

| 因素 | 同词向量会不同吗 | 原因 |
|---|---|---|
| 不同语料 | ✅ 不同 | 上下文不同 |
| 不同随机种子 | ✅ 不同 | 初始化不同 |
| 同语料+同种子 | ❌ 相同 | 完全复现 |
| 不同 d_model | ✅ 不同 | 向量空间不同 |

这就是预训练大模型（BERT/GPT）的价值：用海量语料训练出高质量 embedding。

## 9. 同模型内：同词查表 = 同向量

在同一个模型里，`nn.Embedding` 是一张固定表，同词永远查到同一行：

```
"猫 吃 鱼"     → embedding["猫"] = [0.85, 0.23, ...]
"猫 在 睡觉"   → embedding["猫"] = [0.85, 0.23, ...]  ← 完全相同！
```

**但经过 Self-Attention 后就不同了**：

```
"猫 吃 鱼"     → Self-Attention → "猫" = [0.92, -0.15, ...]  (吃鱼的猫)
"猫 在 睡觉"   → Self-Attention → "猫" = [0.71, 0.38, ...]   (在睡的猫)
```

**原因**：不同句子有不同的词 → 注意力分数不同 → 加权组合不同 → 最终向量不同。

具体来说：

```
"猫 吃 鱼" 中的 "猫":
  猫→猫: 0.2, 猫→吃: 0.3, 猫→鱼: 0.5
  新向量 = 0.2×V(猫) + 0.3×V(吃) + 0.5×V(鱼)  ← 混入了"鱼"

"猫 在 睡觉" 中的 "猫":
  猫→猫: 0.3, 猫→在: 0.1, 猫→睡觉: 0.6
  新向量 = 0.3×V(猫) + 0.1×V(在) + 0.6×V(睡觉)  ← 混入了"睡觉"
```

## 10. 训练：所有参数同时学

没有"先学 embedding，再学注意力"这样的阶段。

```
每次训练循环:
  1. 输入句子 → 前向传播 → 得到预测
  2. 预测 vs 答案 → 计算 loss
  3. 反向传播 → 所有参数同时获得梯度
  4. 更新: embedding 表 + W_q/W_k/W_v + FFN + ... 一起调

类比: 学开车不是"先学方向盘 100 小时再学刹车"，而是同时学。
```

## 11. 什么存储，什么不存储

| | 存储（在模型文件里） | 不存储（实时计算，用完就丢） |
|---|---|---|
| 例子 | embedding 表、W_q/W_k/W_v、FFN 权重、位置编码 | 注意力分数、中间层向量、softmax 结果 |
| 类比 | 你的大脑（知识、技能） | 你此刻的想法（看完就忘） |

为什么不存中间结果？太多了（每句话、每层、每位置都有），而且换句话就没用了。

> **例外**：[[KV Cache]] 是推理时缓存 Key/Value 的优化技术。

## 12. Attention weights 不是学到的——是实时算出来的

**关键区别**：

```
学到的 (存储在模型里):
  W_q, W_k, W_v  ← 这些权重矩阵是训练学到的

实时算的 (用完就丢):
  Q = W_q × 输入     ← 每次输入不同, Q 就不同
  K = W_k × 输入     ← 同理
  weights = softmax(Q·K^T / √d_k)  ← 由 Q 和 K 决定, 每句话都不同
```

同一个模型，不同输入 → 不同的 weights：

```
输入 "猫 吃 鱼":  Q(猫)·K(鱼) = 高分  → weights 中 猫→鱼 权重大
输入 "猫 在 睡觉": Q(猫)·K(鱼) 不存在  → weights 完全不同
```

**W_q 和 W_k 是训练学到的"规则"**，weights 是这些规则在具体句子上的**执行结果**：

- **W_q, W_k** = 你的大脑回路（"看到食物就关注价格"这种习惯）← 长期存储
- **weights** = 你此刻的注意力（看到这份菜单时，眼睛盯着第三行的价格）← 实时产生

## 13. 头的"模式"不是人为设定的——代码追溯

### 模式从哪来？

`nn.Linear(d_model, d_model)` 包含所有头的投影矩阵，`view` 把它切成多头：

```python
Q = self.W_q(Q)                           # [batch, seq_len, 64]
Q = Q.view(batch, -1, num_heads, d_k)     # [batch, seq_len, 4, 16]
Q = Q.transpose(1, 2)                     # [batch, 4, seq_len, 16]
```

**每个头分到的是 W_q 的不同列：**

```
W_q 的完整矩阵 [64×64]:

    列0-15   列16-31   列32-47   列48-63
   ┌────────┬────────┬────────┬────────┐
   │ 头0的  │ 头1的  │ 头2的  │ 头3的  │
   │ 投影   │ 投影   │ 投影   │ 投影   │  64行
   │ 参数   │ 参数   │ 参数   │ 参数   │
   └────────┴────────┴────────┴────────┘
```

### 因果链

```
随机初始化不同 → 看到同样的输入产生不同的 Q、K
→ 计算出不同的 attention weights
→ 反向传播时收到不同的梯度
→ 参数往不同方向更新
→ 逐渐分化出不同的"模式"
```

**没有人设定头的模式。模式是训练自动产生的，唯一的起因就是初始化时的随机差异。**

## 14. 论文证据：注意力模式是自动涌现的

### 原始论文

**Vaswani et al. 2017（"Attention Is All You Need"）** Section 6.3 展示了不同头的 attention 可视化，发现不同的头确实学到了不同的行为——有的头追踪句法关系，有的追踪长距离依赖。但**没有设计让它们这样做**。

### 后续系统研究

**Clark et al. 2019（"What Does BERT Look At?"）** 分析了 BERT 的 144 个注意力头：
- 某些头专门跟踪直接宾语（准确率 > 86%）
- 某些头专门跟踪介词搭配
- 某些头几乎只关注 [SEP] 标记（"我没什么要关注的"）
- 这些都是**自动涌现的**，没有显式监督

**Voita et al. 2019（"Analyzing Multi-Head Self-Attention"）** 把头分成几类：

```
自然涌现的模式:
├── 位置头 (Positional)    → 总是关注前一个/后一个词
├── 语法头 (Syntactic)     → 关注语法依存关系
├── 罕见词头 (Rare token)  → 特别关注低频词
└── 冗余头 (Redundant)     → 多个头学到了类似的东西
```

### 这不是注意力头独有的现象

深度学习中普遍存在"自动分工"：

```
CNN 第一层:  自动学出 边缘检测器、颜色检测器
CNN 深层:    自动学出 眼睛检测器、轮子检测器
注意力头:    自动学出 语法头、语义头、位置头
```

原因都是：**不同的随机初始化 + 共同的损失函数 + 梯度下降 = 自动分工**。

就像一个团队里，如果每个人特长不同（随机初始化），大家有共同目标（损失函数），互相配合（反向传播），自然会各司其职，而不需要领导（人类）明确分配任务。
