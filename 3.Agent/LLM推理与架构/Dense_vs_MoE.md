# Dense vs MoE 模型对比

## 基本概念

| 特性 | Dense (稠密模型) | MoE (混合专家模型) |
|------|-----------------|-------------------|
| **全称** | Dense Model | Mixture of Experts |
| **参数使用** | 所有参数每次都激活 | 每次只激活部分参数 |
| **计算量** | 固定，与参数量成正比 | 参数量大但计算量小 |
| **核心思想** | 一个通用网络处理所有输入 | 多个专家网络，按需调用 |

---

## 架构对比

### Dense 模型
```
输入 → [所有参数都参与计算] → 输出
      ↓
   64M 参数全部激活
```

**特点**：
- 简单直接
- 所有参数共享
- 推理速度稳定

---

### MoE 模型
```
输入 → [Router 路由网络] → 选择 Top-K 个专家 → 输出
              ↓
      8个专家网络（每个专家独立）
      
总参数: 104M
激活参数: ~64M (每次只选2个专家)
```

**特点**：
- 参数容量更大
- 计算效率更高
- 专家专业化

---

## 详细对比

| 对比维度 | Dense | MoE |
|---------|-------|-----|
| **总参数量** | 64M | 104M |
| **激活参数量** | 64M | ~64M |
| **推理速度** | 快 | 稍慢（有路由开销）|
| **内存占用** | 小 | 大（需加载所有专家）|
| **训练成本** | 低 | 高 |
| **知识容量** | 有限 | 更大 |
| **专业化程度** | 通用 | 专家各司其职 |

---

## 优缺点

### Dense 模型
**优点**：
- 架构简单，易于理解和实现
- 推理速度快，延迟低
- 内存占用小，适合边缘设备
- 训练稳定，不易出现负载不均衡

**缺点**：
- 参数量受限，知识容量有限
- 所有任务共享同一套参数

### MoE 模型
**优点**：
- 参数量可扩展，知识容量大
- 计算效率高（相同计算量，更多参数）
- 专家可以专业化学习不同领域知识

**缺点**：
- 架构复杂，需要路由机制
- 训练难度大，容易出现专家负载不均衡
- 推理时需要加载所有专家参数，内存占用大
- 路由开销导致推理延迟增加

---

## 为什么 MiniMind 同时提供两种？

| 场景 | 推荐模型 |
|------|---------|
| 学习入门 | Dense |
| 资源受限 | Dense |
| 低延迟要求 | Dense |
| 追求性能 | MoE |
| 知识密集型任务 | MoE |
| 研究路由机制 | MoE |

---

## 总结

- **Dense**：简单、高效、适合入门和资源受限场景
- **MoE**：容量大、效率高、适合追求性能和研究

选择取决于你的**硬件资源**、**延迟要求**和**任务复杂度**。
