# 1. Metadata

- Title: 从代码到通用工作流：AI 时代的机会与执行要点（Conviction 创始合伙人演讲要点）
- Author: Sarah Guo

# 2. Overview

本视频核心论题是：当前的生成式 AI 浪潮并非短暂的“夏天”，而是正在改变产品、工程和行业工作流的长期技术革命。结论是：能力层（尤其是“推理”能力和多模态能力）迅速进步，模型市场正变得多元化与竞争化；真正的商业价值更多来自于面向特定工作流的“厚包装”产品（演讲中称为 “cursor for X”），以及对执行力的持续投入——执行，是当前 AI 领域的护城河。

# 3. 按照主题来梳理

## 3.1 能力演进：推理（reasoning）作为新的放大手段

- 演讲一开始强调，过去一年最显著的能力进展是“推理”（reasoning）。这里的推理不是简单的文字生成，而是指通过更多计算资源和新架构，让模型在连续步骤、系统化搜索、显示中间步骤和可验证结论方面表现出更高能力。演讲者指出，实验室对这类能力十分兴奋，因为他们可以投入更多计算并获得更高输出，但对产品和用户来说，推理的价值在于解锁新的用例：例如需要透明、高风险决策（“showing the work matters”），或需要顺序性解决方案的问题（sequential problems）。
- 推理带来的直接产品影响：当模型能显示推理过程、保留中间假设、回溯并尝试不同假设时，它从“黑盒”生成器变为更像“同事”的工具，这样的工具更适合高价值、需要验证和可追溯的业务场景。演讲中提到，推理能力使得一些过去依赖人类系统性搜索和实验的任务能够被 AI 部分或全部承担，从而提升效率并扩展规模。
- 为什么推理现在可能更受重视：一方面，模型架构和训练数据的演进使得在较高成本投入下能看到显著能力提升；另一方面，业务方更愿意接受能够解释其决策或步骤的系统，尤其在医疗、法律、财务等需要合规和追责的领域。演讲者建议把“推理”视为一个促成新产品类别的能力层，而不是仅仅把它看成是又一项实验室指标。
- 对工程与研究的影响：实验室会继续把资源投到推理上，因为这是展示进步并证明价值的一个方向（研究者将其视为可衡量的里程碑）。同时，工程团队需要考虑如何把推理结果以用户可理解、可验证的方式展示出来，例如步骤化输出、可回溯日志和与外部验证系统的联动（tests/compilation/run 等自动化验证机制可以与推理流程结合，提升可靠性）。
- 风险与仍待解决的问题：推理能力虽然强，但并非万应丹。模型在复杂推理任务中仍可能出错或“hallucinate”（出现虚构事实）。因此，要把推理能力投入生产环境，需要配套的检测、回退与验证流程，保证在高风险场景下不致产生严重后果。演讲者强调，这并非理由去忽视推理，而是提示产品设计要将“展示工作过程”和“可验证性”作为核心考虑。

## 3.2 Agents（代理）：定义、变化范围与真实世界的增长

- 演讲对“agents”（代理）做了非营销性的定义：agents 是“软件，能够规划并执行一系列步骤，包含 AI，承担任务主导权并在记忆中保持目标，可以尝试不同假设并回溯”。这个定义强调代理的核心要素不是复杂的神经架构，而是任务所有权、目标保持（memory）、规划与回溯能力，以及使用外部工具或模型来完成任务的能力。换言之，agent 可以是简单也可以是复杂，范围很广。
- Agents 的工具链和实现要点：一个 agent 可能会调用多个模型（有的模型处理 diff 或 merge，有的生成文本，有的做搜索），也可能调用检索工具（retrieval）、概念搜索或外部 API。成功的 agent 通常会有“计划-执行-验证-回溯”的闭环：首先生成计划（plan），随后调用工具或模型执行子任务，然后验证结果能否达成目标，若失败则回溯并调整计划。
- 行业与初创公司趋势：演讲者提到她所在基金（Conviction）运营一个叫 Embed 的孵化/资助计划，他们每年收到数千份申请，过去一年中 agent 类初创数量增长了约 50%。这说明市场上不仅有概念验证（proof-of-concept），更在出现可投入生产、并取得收入的 agent 产品。尽管不少 agent 项目处于早期，但已有一些在真实客户场景中展现出价值。
- Agent 的实际价值场景：agents 特别适合那些需要有目标导向、多步决策或需要与外部系统交互的任务。例如：自动化复杂的工作流（包含多工具调用与验证）、持续监控与报警、跨系统汇报或替代重复的操作流程。agents 可以代替或增强“同事”角色，进行资料整理、问题排查、自动提交等。
- 营收与采用的现实考量：尽管市场对“完全自动化的 agent”很兴奋，但演讲中也提醒：从商业化和用户接受度角度看，完全自动化（无人工介入）面临较高的容错门槛。用户对系统失误、幻觉（hallucination）和不可预测行为的容忍度随自动化程度与延迟上升而下降。因此很多实际成功的产品会从“增强型协助（co-pilot）”开始，逐步演进到更高自主性的 agent。这一分阶段路径既能保住用户信任，也能在能力成熟时扩展自动化范围。
- Agent 发展中的技术挑战：构建可靠 agent 需要的不只是一个强大的基础模型，还需要卓越的 orchestration（编排）能力、长期记忆管理、错误处理与回滚机制、上下文检索（retrieval）和外部工具整合。除此之外，agent 在企业环境中还得应对权限（authorization）、审计（audit）与合规（compliance）需求，这些都是工程上不可忽视的复杂度。

## 3.3 多模态（voice/video/image）发展与商业化路径

- 演讲指出，多模态能力（voice、video、image generation 等）在过去一年同样取得显著进展，并且已经开始诞生“真实的生意”。她举例了 Hey Gen、11（演讲原文为“11”）和 Midjourney 等公司，它们已经实现每月超过 5000 万美元（视频中称“50 million of AR”）的年化经常性收入（ARR）。这些产品把文本、语音和视频结合起来，提供更高带宽、富含情绪和肢体语言的表达方式，能够生成“仿真人”视频或带有表情手势的虚拟代言人。
- 多模态的商业吸引力：多模态沟通是高带宽的交流方式，远超纯文本或静态图像；在销售、培训、客户服务、广告和咨询等场景中，语音与视频更接近人类自然沟通，因而在这些场景里商业价值更容易转化。演讲者特别提到 voice（语音）在企业工作流中首先落地的可能性更大，因为语音本身就是很多业务交流的天然形式，比如医疗咨询、销售电话与客户支持。
- 数据的采集与结构化问题：许多人认为企业没有足够的语音或视频数据来做多模态产品的规模化，但演讲者认为当工具变得能“理解并结构化”这些模态后，企业就会更有动机去捕获和存储它们。换言之，工具先出现并能派生价值，再促使企业去构建数据采集流程。随着可控性和成本下降，更多企业会开始保留会议录音、视频客服记录、销售通话等，从而形成良性循环。
- 多模态对产品设计的挑战：把多模态能力投入到产品中不是简单地把模型接入，而是要考虑用户体验、情绪传达的细微差别、合规（例如肖像权、隐私）以及验证生成内容真实性的需求。比如用虚拟代言人做营销时，需要明确用户知情与免责声明；在医疗场景中，语音生成必须与临床责任分界清晰，不能误导诊疗决策。
- 成本与竞争：演讲提到推理和大模型的成本正在下降，基础模型变得“商品化”（“last year's model is a commodity”）。这使得多模态能力的门槛降低，更多玩家（包括开源社区与新实验室）可以进入，为多模态产品提供基座。演讲者建议计划面向“多模型”的世界：使用 Open Router 或其他推理平台来自由选择合适的模型进行编排（orchestration），而不被单一供应商锁定。
- 风险与伦理考量：多模态生成的影响力很大（视频与音频更具说服力），因此误用或滥用的风险也更严重。产品团队在设计多模态系统时必须要有明显的防滥用策略、透明标识，并考虑监管合规、用户知情同意与生成内容的可追溯性。演讲并未扩展具体监管策略，但提醒听众要对这些问题保持敏感。

## 3.4 “Cursor for X”——以工程类成功为模板的产品化路径

- 演讲中反复使用了“cursor for X”这一短语，把 Cursor（一个工程领域的成功产品）看作通用模式：即在行业内部构建一个“厚包装”的工作流界面（workflow wrapper），把模型能力、检索、上下文整合、提示工程（prompting）与验证步骤包裹成对用户“无脑可用”的工具。Cursor 在代码领域的成功并非因为发明了模型或代码补全，而是因为深刻理解工程师工作流、设计了合适的 UX 并把模型能力可靠地嵌入到开发循环中。
- Cursor 成功的三大理由（演讲总结的要点）：
    1. 文本+逻辑性使得代码是“低悬果实”：代码本质是结构化的文本，有明确的逻辑和 deterministic validation（确定性验证）方式（如编译、运行测试、lint、CI/CD），因此自动化和模型补全在反馈闭环上更容易落地。
    2. 可以自动化验证：对于代码片段、API endpoint 或 React 组件，可以运行测试、编译或集成到 CI 流程里，从而实现“自动证实”或“自动修复”的能力，这大大降低了部署风险并提升了用户信心。
    3. 对工程师的深刻理解：Cursor 的团队懂工程师的真实工作流，能把模型能力嵌入到开发环境（如 VS Code）中，让快捷键、界面、上下文推送等与日常习惯一致，从而降低认知摩擦。
- 将 Cursor 模式推广到其他领域的通用规则（演讲者提出的产品策略）：
    - 不要做通用的文本输入框（generic text box），因为大厂（如 OpenAI）已在这个层面占优。真正的价值在于 domain knowledge（领域知识）和 workflow knowledge（工作流知识）。
    - 自动收集并打包上下文：产品应自动从用户的各种数据源（文件、数据库、工具）中收集并格式化上下文，而不是让用户从头解释问题。上下文覆盖（coverage）和时效性（freshness）越好，检索与生成的效果越佳。
    - 使用合适的模型组合（orchestration）：不是只靠一个大模型做一切，而是根据任务调用不同模型（如 diff model、merge model、embed model）或服务来完成更复杂的流程。
    - 精心呈现输出：模型生成的结果需以用户能轻松理解与验证的方式呈现（例如 color coding：绿色为添加，红色为删除），并提供快速回滚或确认机制。
    - 把 prompt 当成“漏洞（bug）而非产品特性”：理想的体验是“像读心术一样”的感觉，即用户无需解释或复杂 prompt 调整即可获得期望结果。Prompt 调优应在后端由产品自动完成，而不是让用户手工编写复杂提示。
- 商业模型与护城河：Cursor 类产品的护城河来自于数据与体验的累积（例如团队协作中检索准确率随使用增加而提升）、对特定工作流的深刻适配以及在客户内部嵌入的高度黏性。演讲者强调：模型可能被复制，但“执行”（execution）和“体验设计”才是长期的竞争优势（也就是“执行是 AI 的护城河”）。

## 3.5 保守行业的快速采用、自动化与“辅助手套”（copilot）策略

- 演讲提出一个反直觉观察：许多看似保守、技术接受度低的行业反而在采用 AI 方面进展迅速，这被基金方内部称为“AI leapfrog effect”（AI 跳跃效应）。举例来说：
    - Sierra（演讲提及的一家公司）能为客户解决 70% 的客服查询；
    - Harvey（法律领域）在两年内达到超过 7000 万美元的 ARR（演讲称“70 million of ARR”），并且 AI 已经成为其在法律行业竞争的核心要素；
    - Open Evidence（医疗领域）帮助医生在临床决策点检索并理解最新研究，覆盖大量医生并实现日常使用。
- 为什么保守行业会快速采用：这些行业往往工作流程高度重复、依赖大量文本（如法律文件、临床研究、客服交互），而 AI 可以直接在效率和成本两个维度上带来快速回报。并且在许多情形下，AI 可以被用来“放大稀缺专家”的能力（例如帮助医生更快地检索证据），从而带来实际的业务价值和竞争优势。
- 自动化 vs 协助（Full automation vs co-pilot）：很多人追求从“辅助”直接跃迁到“完全自动化”的最终形态（agent 成为完全的无人同事），但演讲者提醒这是一个风险很高的路径。现实数据表明，co-pilot（协助型产品）在驱动收入方面仍被严重低估，很多成功公司先从“增强（augmentation）”做起，再随着能力成熟逐步扩展自动化。
    - Iron Man（钢铁侠）类比：Tony Stark 的战衣首先是增强了他的能力（augmentation），而后某些功能可以在无人控制下短时运行。这比喻说明最佳路径是先做“穿戴式增强”（让人戴上并提升效率），然后逐步增加自主功能。
    - 用户容忍度问题：人类对错误、幻觉和不可预测行为的容忍度随着系统自主性和执行延迟的增加而降低（latency 增加时容忍度急剧下降）。因此，要取得用户信任并实现规模化，通常要通过高质量的协助体验累积信任，再向自动化迈进。
- 产品设计的建议性结论：对于许多垂直领域的创业者和产品经理，切入点应该是“构建高质量的协助工具”，把重点放在可靠性、可验证性和与现有工作流的无缝集成上。一旦用户信任和数据积累起来，再逐步扩展到更高层级的自动化（agent）。
- 对风险与更难问题的提示：演讲者也指出有些最困难的问题（例如机器人学、生物学、材料学）并不简单地依赖网络文本（common crawl）上的知识，这些领域需要与“原子而非仅仅是比特”的交互和数据采集（如实验数据、物理互动），因此创业向这些领域扩展时需要别样的方法与资本耐心。

# 4. 框架 & 心智模型（Framework & Mindset）

- 总览：从演讲中可以抽象出几个互为补充的 framework（框架）与 mindset（心智模型），用于指导如何在当前 AI 历史转折点中设计产品、组建团队与构建可持久的竞争力。以下为核心框架与心态的条理化阐述，包含实践步骤与常见陷阱的规避建议。
1. 能力—产品—执行 三层次框架（Capability → Product → Execution）
- 定义与逻辑：
    - 能力（Capability）：指模型与基础设施的本质能力，例如语言理解、推理、检索、多模态生成、低成本推理等。能力层决定了可以实现的技术上限与新用例的可行性。
    - 产品（Product）：指把能力嵌入特定工作流后的可用性与商业化形式。产品设计强调用户体验、上下文捕获、模型编排（orchestration）与验证机制。
    - 执行（Execution）：是把产品推向市场并持续优化的能力，包括工程实施、用户研究、数据采集、监控、合规与客户支持。演讲者反复强调“执行是护城河”——技术可以被复制，但对工作流深刻理解和快速、正确落地的执行难以被简单超越。
- 实践步骤：
    1. 评估能力是否允许某个用例进入可做阶段（能否被自动验证，是否需要多模态或推理等）。
    2. 以具体工作流为导向设计产品：自动捕获上下文、减少用户输入负担、用适当的模型组合实现任务、输出要易于验证与回滚。
    3. 集中于执行：快速迭代、关注指标（使用率、验证通过率、收入）、建立反馈闭环以改进检索与提示。
    4. 把执行视为长期投入：培养行业知识、构建数据与 UX 上的累积优势，形成非易位替代成本（switching cost）。
- 常见误区：
    - 盲目追逐模型最前沿而忽视 UX 与验证流程（“模型先行”但产品体验拉胯）。
    - 低估合规与权限复杂性（尤其在企业或医疗/法律场景）。
    - 以为先发就是护城河：实际是执行与体验构建了壁垒。
2. “Cursor for X” 产品化心智模型（Domain-first Workflow Wrapping）
- 定义：把成功的工程类产品（Cursor）作为模板，核心思想是：不要做通用的文本交互层，而是深度嵌入特定职业或行业的工作流，自动化上下文收集，使用合适的模型组合并提供清晰可验证的输出界面。
- 关键要素（可作为构建步骤）：
    1. 深入理解目标用户的日常工作流程：场景、痛点、接受事故或变更的边界（tolerance）。
    2. 设计 UX，将模型能力嵌入用户熟悉的工具/界面（如 IDE、EMR、CRM），尽量减少用户额外学习成本。
    3. 自动化上下文收集：包括从文件、数据库、通话录音、历史记录等数据源提取并格式化为模型可用的 prompt/context。
    4. Orchestration：根据任务调用不同模型或工具，编排成“计划-执行-验证-回溯”闭环。
    5. 验证与回滚机制：在高风险场景中提供自动测试、人工确认或逐步放大的部署策略。
    6. 数据循环：把用户交互数据（包括确认/撤销、测试结果等）用来改进检索与模型选择，形成长期优势。
- 心态与优先级：注重“领域一方优先”（domain expertise）高于纯模型创新；把 prompt 看作临时手段，目标是把智能集成成无需用户主动提示的体验。
3. 自动化策略心态：先增能后自动化（Augmentation-first）
- 定义：在多数行业与场景下，先构建高质量的辅助工具（co-pilot）会比直接构建完全自动化系统更容易获得商业成功与用户信任。
- 步骤化策略：
    1. 从增强用户能力开始：目标是提升用户效率与质量（例如让律师在草拟合同时速度和准确度大幅提升）。
    2. 设计清晰的责任界面：标注哪些输出由 AI 生成、哪些需人工审核，明确用户能快速验证并接管的方式。
    3. 随能力提升逐步放大自动化边界：在低风险且高重复性的任务上试验更大比率的自动化；在高风险情境中保留人工决策权。
    4. 用验证结果与用户反馈推动模型能力升级，避免在未完全可靠时扩大自动化范围。
- 风险识别：忽视用户对错误的低耐受度会导致产品快速失去信任；忽视延迟对容忍度的影响会导致自动化反而降低效率。
4. 多模型 / 多模态编排心智（Orchestration-first）
- 定义：面对日益多元化的模型市场与多模态需求，心态应是“多模型多工具并存”，通过编排达到最佳效果，而非把希望全部寄托于单一万能模型。
- 具体做法：
    1. 对任务进行分解：哪些子任务适合小模型，哪些需要大模型，哪些需要检索，哪些需要外部工具。
    2. 设计低耦合的接口：让模型/工具替换成为可管理的工程工作（例如用统一的 adapter 抽象各模型的输入输出）。
    3. 跟踪成本-准确率-延迟权衡：不同模型在成本与性能上有不同曲线，产品层需要做显式权衡。
    4. 引入降级策略：当某模型不可用或成本过高时，系统可以自动切换到备选模型或回退到较简单的规则引擎。
- 好处：抵御单一模型供应商风险，利用不同模型的优势；同时随着开源与新厂商进入，能灵活用更低成本的模型降本增效。
5. 护城河心智：执行为王（Execution as Moat）
- 内涵：演讲的一个反复主题是，模型和理念容易被复制，但优秀的执行（产品体验、领域理解、用户数据与团队速度）构成了真正的长期护城河。
- 如何构建执行护城河：
    1. 对用户与领域进行长期投资：深度客户研究、构建行业数据集、建立专家网络。
    2. 快速迭代并收集高质量反馈：在真实用户场景中不断改进验证率与 UX。
    3. 投入到工程与运维以保证稳定性与合规：企业客户尤其看重可靠性、审计与权限控制。
    4. 把产品嵌入日常工作流，形成高切换成本：接口、快捷键、自动化流程、团队协作特性会提高粘性。
- 心态警示：不要过度迷信模型领先带来的防护力——更重要的是把模型能力转化为可持续的用户价值并在运营上维持领先。

总结心智模型（mindset）要点：

- 以用户工作流为中心，不以模型为中心。
- 把 prompt 看作临时搭桥，目标是更智能的后端自动化，减轻用户思考负担。
- 先做增强，再逐步自动化，以维护用户信任。
- 用多模型编排策略控制成本与风险。
- 把执行视为主要护城河，长期投入体验与数据积累。

# 总结

视频的核心信息是：AI 的技术能力在快速提升（尤其是推理与多模态），模型市场也在走向多元竞争；真正的商业机会不是在基本的文本输入层被创造，而是在针对具体工作流的“厚包装”产品中——即“cursor for X”式的域内工作流工具。短期内，co-pilot 式的增强工具是最稳妥的路径，随着能力提高再逐步扩展自动化。最终的护城河来自于执行、产品体验与领域数据的累积，而非仅依赖模型本身。演讲鼓励工程师与创业者把握这个“像拨号到宽带的过渡期”的机会，做出面向行业与用户的革命性产品。
