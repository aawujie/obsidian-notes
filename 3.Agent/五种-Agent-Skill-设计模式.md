# 五种 Agent Skill 设计模式

> 核心问题：Skill 搭好了，但 Agent 输出还是不稳定——格式乱、漏步骤、答偏！  
> 真正的问题不在格式，而在**内容设计的逻辑组织**。

---

## 核心问题：Agent 的五类失控点

| 失控点 | 对应模式 | 核心问题 |
|--------|----------|----------|
| 知识加载时机 | Tool Wrapper | 什么时候应该把知识交给 Agent？ |
| 输出结构不稳定 | Generator | 为什么今天和明天输出长得不一样？ |
| 审查标准混乱 | Reviewer | 检查什么 vs 怎么检查混在一起 |
| 信息不全就开工 | Inversion | 模型太爱猜，补得很自信 |
| 复杂任务跳步骤 | Pipeline | 多步骤任务中途偷懒 |

---

## 模式一：Tool Wrapper（工具包装器）

### 解决的问题
**"知识什么时候应该被交给 Agent"**

### 常见错误
```
❌ 把某个技术栈的全部规范提前塞进 System Prompt
   - React 规范、FastAPI 规范
   - 团队约定、命名规则
   - 一次性全塞进去！

问题：
- 大部分任务根本用不到
- 浪费 Context
- 模型被无关知识干扰
```

### 正确做法
```
✅ 把内容放进 References
   Skill 只负责判断：
   - 当前任务是否进入 React 领域？
   - 当前任务是否进入数据库领域？
   - 只有判断命中才加载那一套知识
```

### 本质
> Skill 像一个**总闸门**，负责在合适的时候把某个专家手册接入上下文。

### 示例
```
任务：改一个 React 页面
→ 加载 References 里的 React 规范

任务：写 SQL 查询 / 改产品文案
→ 前端规范根本不出现
```

### 核心价值
**按需注入知识**

## 模式二：Generator（生成器）

### 解决的问题
**"为什么同样让 Agent 写文档，今天长这样、明天又长成另一种样子"**

### 根本原因
```
模型每次都在现场重新决定：
- 这份输出该长什么样
- 结构怎么组织
- 表达方式如何
```

### 解决方案
```
✅ 别让它现场发挥！

模板（Template）→ 回答 "What to produce"
风格指南（Style Guide）→ 回答 "How to write"

Skill 的职责：
1. 先补问缺失变量
2. 再把内容填进模板
```

### 示例：API 文档生成

**模板规定**：
- 接口说明
- 参数表
- 返回值
- 错误码
- 示例调用

**Style Guide 规定**：
- 标题格式
- 术语统一
- 语气
- 字段命名

### 效果
```
今天写、明天写
不同人触发
→ 结构还是同一套！
```

### 适用场景
- API 文档
- 标准化报告
- Commit Message 脚手架生成

## 模式三：Reviewer（审查器）

### 解决的问题
**"为什么你的审查任务经常要推倒重来"**

### 常见错误
```
❌ 把两件事写混了：
   1. "检查什么"（规则）
   2. "怎么检查"（流程）
```

### 正确做法
```
✅ 硬拆开！

Checklist → 检查什么（规则）
Skill MD  → 怎么检查（流程）

好处：
- 流程不动
- 规则可换
```

### 示例
```
今天：Python 风格审查
明天：OWASP 安全检查
后天：合规规则

→ 不需要为每一类审查重写 Skill
→ 只需要替换不同的 Checklist
```

### 输出规范
```
统一成层级格式：
- Error   → 必须修
- Warning → 建议修
- Info    → 只是提醒
```

### 核心价值
**流程与规则分离，可复用性大幅提升**

## 模式四：Inversion（反转）

### 解决的问题
**"Agent 太爱猜——信息不够就自己补，而且补得非常自信"**

### 核心思路
```
把流程反过来：
Agent 先发问 → 用户先回答

而不是：
Agent 直接生成 → 用户发现不对
```

### 三阶段流程

```
┌─────────────────────────────────────────┐
│  Phase 1: Discovery（发现）             │
│  确认你到底要解决什么问题               │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Phase 2: Constraints（约束）           │
│  平台、技术栈、限制条件、交付要求       │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│  Phase 3: Synthesis（综合）             │
│  信息齐了之后才允许开始生成             │
└─────────────────────────────────────────┘
```

### 示例：客服机器人规划

**应该先问**：
- 服务对象是谁？
- 接入微信还是网页？
- 要不要对接工单系统？
- 有没有合规要求？
- 有没有人工接管机制？

**门控指令**：
```
⚠️ 这些没问清之前，禁止直接开始写方案！
```

### 核心价值
**用门控指令明确规定：信息没齐不准开工**

## 模式五：Pipeline（流水线）

### 解决的问题
**"多步骤任务为什么总有人跳步骤"**

### 问题场景
```
有些任务是强顺序流程：
1. 分析输入
2. 生成中间产物
3. 组装最终结果
4. 验证

如果当成一句 Prompt → 模型很容易中途偷懒
```

### 解决方案
```
✅ 把 Skill MD 写成工作流！

定义：
- 第一步做什么
- 第二步做什么
- 什么时候能进入下一步
- 显式门控（Gate）
```

### 示例：文档生成流程
```
Step 1: 解析公开 API
   ↓ [Gate: 确认解析完成]
Step 2: 生成 Doc String
   ↓ [Gate: 确认 Doc String 完整]
Step 3: 组装成完整文档
   ↓ [Gate: 确认格式正确]
Step 4: 质量检查
```

### 优势
```
1. 顺序清晰，不能跳过验证
2. 每一步只加载当前所需的 References
3. 每一步只加载当前所需的 Templates
4. Context 始终保持干净
```

### 适用场景
- 文档生成
- 复杂代码修改
- 发布流程
- 合规流程

## 模式选择逻辑

```
                    ┌─────────────────┐
                    │ 这个 Skill 要    │
                    │ 产出内容吗？     │
                    └────────┬────────┘
                             │
              ┌──────────────┴──────────────┐
              │ Yes                         │ No
              ↓                             ↓
    ┌─────────────────┐           ┌─────────────────┐
    │ 从模板里产出？   │           │ 评估已有输入？   │
    └────────┬────────┘           └────────┬────────┘
             │                             │
      ┌──────┴──────┐                      │
      │ Yes         │ No                   │ Yes
      ↓             ↓                      ↓
  Generator   ┌─────────────┐         Reviewer
              │ 运行时加载   │
              │ 某套知识？   │
              └──────┬──────┘
                     │
              ┌──────┴──────┐
              │ Yes         │ No
              ↓             ↓
        Tool Wrapper   ┌─────────────┐
                       │ 开始前必须   │
                       │ 补全信息？   │
                       └──────┬──────┘
                              │
                       ┌──────┴──────┐
                       │ Yes         │ No
                       ↓             ↓
                   Inversion    ┌─────────────┐
                                │ 有严格步骤   │
                                │ 门控确认？   │
                                └──────┬──────┘
                                       │
                                ┌──────┴──────┐
                                │ Yes         │ No
                                ↓             ↓
                            Pipeline      重新分析
```

### 快速判断表

| 判断问题 | 答案 | 对应模式 |
|----------|------|----------|
| 要从模板产出内容？ | Yes | Generator |
| 只是运行时加载知识？ | Yes | Tool Wrapper |
| 在评估已有输入？ | Yes | Reviewer |
| 开始前必须补全信息？ | Yes | Inversion |
| 有严格步骤和门控？ | Yes | Pipeline |

## 模式叠加

> 这些模式之间可以互相叠加！

### 常见组合

```
┌─────────────────────────────────────────────────────┐
│  Inversion → Generator                              │
│  先问清楚需求，再生成标准化输出                      │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  Pipeline → Reviewer                                │
│  多步骤流程完成后，统一审查输出质量                  │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│  Tool Wrapper + 任何模式                            │
│  负责在运行时补充特定领域的知识                      │
└─────────────────────────────────────────────────────┘
```

### 叠加示例

```
客服机器人 Skill：

[Inversion] 先问清楚需求
   ↓
[Tool Wrapper] 加载客服系统规范
   ↓
[Generator] 生成标准化方案文档
   ↓
[Pipeline] 分步骤验证方案完整性
   ↓
[Reviewer] 最终质量审查
```

## 核心总结

### 核心洞察
```
❌ 别再把越来越复杂的指令一股脑塞进同一个 System Prompt！

✅ 真正可靠的 Skill，靠的是更合适的结构。
```

### 决策流程
```
1. 判断遇到的是什么问题：
   - 知识问题 → Tool Wrapper
   - 结构问题 → Generator
   - 审查问题 → Reviewer
   - 澄清问题 → Inversion
   - 流程问题 → Pipeline

2. 模式选对了，Agent 才会稳定输出
```

### 五种模式速查

| 模式 | 核心职责 | 关键机制 |
|------|----------|----------|
| **Tool Wrapper** | 按需注入知识 | References + 领域判断 |
| **Generator** | 稳定输出结构 | 模板 + Style Guide |
| **Reviewer** | 分离规则与流程 | Checklist + 统一输出层级 |
| **Inversion** | 先问后做 | 三阶段 + 门控指令 |
| **Pipeline** | 强制顺序执行 | 工作流 + 显式 Gate |
