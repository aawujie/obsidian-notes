# 推理脚本：仓库根目录 `eval_llm.py`

面向本地或离线环境的 **交互式 / 批式推理** 入口（与 `scripts/serve_openai_api.py` 不同，**不在 `scripts/` 下**）。

## 权重加载

- **模式 A（原生 `.pth`）**：当 **`'model' in args.load_from`**（子串判断，例如默认 `model` 或 `../model`）时，构造 **`MiniMindForCausalLM`** 并从 **`./{save_dir}/{weight}_{hidden}[_moe].pth`** 加载（与训练侧保存格式一致；花括号表示按 CLI 变量拼接）。
- **模式 B：HuggingFace 格式**：不满足上一条件时，通过 **`AutoModelForCausalLM.from_pretrained(..., trust_remote_code=True)`** 加载。
- **dtype / 模式**：`init_model` 返回前对整模执行 **`half()`** 并 **`eval()`**，再 `.to(device)`。

## LoRA

- 支持 **`apply_lora` + `load_lora`**：在基座之上 **叠加 LoRA 适配器权重** 做推理。

## 解码与对话行为

- **典型解码**：`temperature=0.85`，`top_p=0.95`，`max_new_tokens=8192`（大上限适合长思考/长工具链场景，实际长度仍受模型与显存约束）。
- **`open_thinking`**：CLI 整型 **`--open_thinking` 0/1** 转为布尔值传入 **`tokenizer.apply_chat_template(..., open_thinking=...)`**（与 `<think>...</think>` 模板行为对齐）。
- **预训练权重**：当 **`'pretrain' in args.weight`** 时，输入为 **`tokenizer.bos_token + prompt`**，**不走** chat template；其余权重走 `apply_chat_template`。
- **多轮对话**：通过 **`historys`** 控制 **保留的历史轮数**，在上下文窗口内维护 user/assistant 交替。

## 输出与评测

- **`TextStreamer`**：**流式打印** token，便于肉眼观察长生成。
- **速度统计**：记录生成耗时与吞吐，便于对比量化/FlashAttention 等优化前后差异。
- **运行模式**：支持 **自动测试**（预设用例）与 **手动交互** 两种入口。

# OpenAI 兼容 API：`scripts/serve_openai_api.py`

用 **FastAPI** + **`uvicorn.run(..., port=8998)`** 暴露与 OpenAI Chat Completions **兼容的 HTTP 接口**，便于接入现有客户端、评测框架或 Agent 编排器。

## 端点与能力

- **`POST /v1/chat/completions`**：核心对话接口。
- **`stream` / 非 `stream`**：两种响应形态均支持（**`ChatRequest.stream` 默认 `True`**）。
- **`tools` 参数**：声明 **函数工具 schema**，模型可返回 **tool_calls**。
- **`open_thinking` 参数**：默认 **`False`**；也可通过 **`chat_template_kwargs`** 里的 `open_thinking` / `enable_thinking` 开启（见 `ChatRequest.get_open_thinking()`）。
- **默认采样**：请求体默认 **`temperature=0.7`**, **`top_p=0.92`**, **`max_tokens=8192`**（与根目录 `eval_llm.py` 的 **0.85 / 0.95** 默认值不同，勿混用）。

## 响应解析：`parse_response`

将模型 **原始文本** 解析为 OpenAI 风格字段：

- **`<think>...</think>`**（或项目约定的 redacted 思考标签）→ 映射到 **`reasoning_content`**。
- **`<tool_call>...</tool_call>`** → 映射到 **`tool_calls`**（含 name / arguments 等结构化字段）。

## 流式输出顺序

在 **`stream=true`** 时，典型事件顺序为：

1. 先流式输出 **`reasoning_content`**（思考阶段）。
2. 遇到 **`</think>`**（闭合标签）后，切换到 **`content`**（对用户可见的最终自然语言）。
3. 末尾再输出 **`tool_calls`**（若本轮存在工具调用）。

## `CustomStreamer` 与线程安全

流式路径通过 **`Queue`** 在 **推理线程** 与 **FastAPI 响应生成器** 之间传递 token/片段，避免竞态，实现 **线程安全的流式传输**。

# Rollout 引擎：`rollout_engine.py`

为 **训练期采样（rollout）** 与 **策略热更新** 提供统一抽象，屏蔽「本地 PyTorch 推理」与「远端 HTTP 推理」差异。

## 抽象基类：`RolloutEngine`

每个具体引擎需实现：

- **`rollout(...)`**：给定 batch / prompt，返回 **生成序列、logprob、mask** 等训练所需张量或结构。
- **`update_policy(...)`**：在权重从磁盘刷新后，通知引擎侧 **重新加载或热更新**。

---

## `TorchRolloutEngine`（PyTorch 原生）

- 使用 **`model.generate()`** 完成自回归采样。
- **`compute_per_token_logps`**：借助 **`logits_to_keep`**（或等价参数）**只对 completion 段** 计算 logprob，避免对 prompt 段做无用计算，**降低显存与算力开销**。

---

## `SGLangRolloutEngine`（HTTP API）

- 对 SGLang 服务发起 **`POST /generate`**，请求体支持 **`return_logprob`** 等开关，直接拿回 **token 级 logprob** 供 RL loss 使用。
- **`update_policy`** 流程概览：
  1. 调用 **`save_pretrained`**（或等价保存）把最新权重落盘。
  2. 再 **`POST /update_weights_from_disk`** 触发服务端 **热更新权重**。
- **Weight tying 注意点**：保存前常需 **`clone lm_head.weight`** 以 **打破与 embedding 的权重共享**（避免部分格式保存/加载异常），保存后 **恢复原共享关系**，以免训练侧长期状态被意外改动。

---

## 工厂：`create_rollout_engine`

根据配置里的 **`engine_type`**（字符串枚举）选择并构造 **`TorchRolloutEngine`** 或 **`SGLangRolloutEngine`**，上层训练脚本只依赖统一接口。

---

## 选型建议（实践向）

| 场景 | 倾向 |
|------|------|
| 单机调试、算法验证 | `TorchRolloutEngine`：栈简单、易断点 |
| 高吞吐组采样、与 SGLang 生态对齐 | `SGLangRolloutEngine`：吞吐与并发更友好，注意服务版本与 API 字段对齐 |
