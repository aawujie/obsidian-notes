# 剪映专业版草稿工程文件结构

## 1. 草稿文件路径

### Windows

默认路径：
```
%USERPROFILE%\AppData\Local\JianyingPro\User Data\Projects\com.lemon.lv\
```

可在剪映 **全局设置 → 草稿位置** 中自定义。自定义后路径形如：
```
D:\剪映\JianyingPro Drafts\
```

每个草稿是一个独立文件夹，命名规则为草稿创建日期（如 `9月5日`、`0808`）或用户自定义名称。

### Mac

默认路径：
```
~/Movies/JianyingPro/User Data/Projects/
```

同样可在全局设置中自定义。

### CapCut 国际版

- **Windows**: `%USERPROFILE%\AppData\Local\CapCut\User Data\Projects\`
- **macOS**: `~/Movies/CapCut/User Data/Projects/`

> **注意**: macOS 版 CapCut 国际版的核心文件叫 `draft_info.json`（而非 `draft_content.json`），但结构相同。

---

## 2. 草稿目录结构

```
草稿文件夹/
├── draft_content.json      # 核心：时间线、轨道、素材、特效等所有数据 (Windows)
│   (或 draft_info.json)    # macOS CapCut 国际版使用此文件名
├── draft_meta_info.json    # 元信息：草稿ID、创建时间、版本、分辨率、帧率、云包信息
├── draft_cover.jpg         # 封面缩略图
├── draft_settings          # 草稿设置（部分版本）
└── assets/                 # 素材资源（部分版本会将素材复制到此目录）
    ├── video1.mp4
    ├── audio1.mp3
    └── ...
```

**最小可识别草稿**只需要两个文件：
- `draft_content.json` — 包含 `id`、`tracks`、`materials` 等核心字段
- `draft_meta_info.json` — 包含 `draft_id`、`draft_name` 等元信息

剪映会自动补全缩略图和其他缓存文件。

## 3. 关键配置文件 JSON 结构解析

### 3.1 draft_content.json — 核心数据结构

#### 顶层字段总览

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | UUID | 草稿唯一标识 |
| `name` | string | 用户可见的项目名称 |
| `duration` | int | 时间轴总长度（**微秒**） |
| `fps` | int | 帧率：24/25/30/50/60 |
| `canvas_config` | object | 画布配置：`{width, height, ratio}` |
| `platform` | object | 平台信息：`{app_source, app_version, os}` |
| `tracks[]` | array | 轨道列表，数组顺序 = z-order（底层在前） |
| `materials` | object | 所有素材的扁平分类存储 |
| `extra_info` | object | 应用内部数据，不要手动编辑 |
| `cover` | object | 封面帧信息 |
| `new_version` | string | 新版本标识（部分 CapCut 国际版非空） |
| `last_modified_platform` | string | 最后编辑的平台 |
| `free_render_index_mode_on` | bool | 通常为 false |

#### 画布配置 (canvas_config)

```json
{
  "width": 1920,
  "height": 1080,
  "ratio": "16:9"
}
```

常用 ratio 值：`"9:16"`（竖屏）、`"16:9"`（横屏）、`"1:1"`（方形）、`"4:5"`。

#### 平台信息 (platform)

```json
{
  "app_source": "lv",        // "lv" = 剪映中国版; "cc" = CapCut 国际版
  "app_version": "5.9.0",
  "os": "windows",
  "device_id": "...",
  "hard_disk_id": "...",
  "mac_address": "..."
}
```

`app_source` 决定了枚举值的命名空间（转场、滤镜等 slug 不同）。

### 3.2 materials — 素材存储 (扁平化设计)

materials 下按类别扁平存储所有素材，**不嵌套**。每个 segment 通过 `material_id` UUID 引用对应素材。

```json
"materials": {
  "videos":             [...],  // 视频文件 + 图片 (type: "video" / "photo")
  "audios":             [...],  // 音频文件 (VO、音乐、音效、录音)
  "texts":              [...],  // 文本（每个文本 segment 对应一个）
  "stickers":           [...],  // 贴纸（引用 CapCut 素材库 resource_id）
  "video_effects":      [...],  // 视频特效 + 滤镜链
  "material_animations": [...], // 入场/出场/组合动画
  "transitions":        [...],  // 转场效果
  "masks":              [...],  // 蒙版（旧版字段名，≤9.5）
  "common_masks":       [...],  // 蒙版（新版字段名，≥9.6）
  "canvases":           [...],  // 背景模糊/背景颜色
  "speeds":             [...],  // 变速曲线
  "audio_fades":        [...],  // 音频淡入淡出
  "placeholder_infos":  [...],  // 缺失素材占位符
  "vocal_separations":  [...],  // 人声分离
  "sound_channel_mappings": [...],
  "smart_crops":        [...],
  "manual_deformations": [...],
  "beats":              [],     // 节拍标记
  "chromas":            [],     // 色度抠图
  "color_curves":       [],     // 颜色曲线
  "digital_humans":     [],     // 数字人
  "flowers":            [],     // 花字
  "green_screens":      [],     // 绿幕
  "handwrites":         [],     // 手写
  "hsl":                [],     // HSL 调节
  "log_color_wheels":   [],     // Log 色轮
  "loudnesses":         [],     // 响度
  "primary_color_wheels": [],   // 主色轮
  "realtime_denoises":  [],     // 实时降噪
  "shapes":             [],     // 形状
  "text_templates":     [],     // 文本模板
  "video_trackings":    [],     // 视频跟踪
  "vocal_beautifys":    []      // 声音美化
}
```

#### 视频素材结构

```json
{
  "id": "uuid-video-material",
  "type": "video",           // 或 "photo"
  "path": "D:/videos/clip.mp4",
  "material_name": "clip.mp4",
  "category_name": "local",
  "has_audio": true,
  "extra_type_option": 0,
  "width": 1920,
  "height": 1080,
  "duration": 10000000       // 微秒
}
```

#### 音频素材结构

```json
{
  "id": "uuid-audio-material",
  "type": "audio",           // "music" / "sfx" / "recording"
  "path": "D:/audio/bgm.mp3",
  "material_name": "bgm.mp3",
  "category_name": "local",
  "duration": 15000000
}
```

## 4. 时间线、轨道、片段、转场、字幕的表示

### 4.1 核心设计模式：扁平化解耦

```
Segment (在 track 中)  ──material_id──▶  Material (在 materials 中)
         │
         └──extra_material_refs[]──▶  Companion Materials (转场/动画/蒙版/变速/淡入淡出)
```

- Segment 不包含素材内联数据，只通过 `material_id` UUID 引用
- 伴侣素材（转场、动画、蒙版等）通过 `extra_material_refs[]` 数组引用
- 这种设计使版本兼容和合并更容易

### 4.2 轨道 (Tracks)

```json
{
  "id": "track-uuid",
  "type": "video",       // video | audio | text | sticker | effect | filter | subtitle | image
  "name": "",
  "segments": [...],
  "attribute": 0,
  "render_index": 0,
  "muted": false,
  "locked": false
}
```

轨道类型：
| type | 用途 | 说明 |
|------|------|------|
| `video` | 视频 + 图片 | 大多数片段在此；CapCut 把图片也放在 video 轨道 |
| `audio` | 音频 | `seg.clip` 必须为 `null` |
| `text` | 文本/字幕 | 每个 segment 对应一个 text material |
| `sticker` | 贴纸 | 引用 CapCut 素材库 resource_id |
| `effect` | 特效/滤镜 | 应用到画面的特效 |
| `filter` | 滤镜链 | 不直接暴露 |
| `subtitle` | 自动字幕 | CapCut 自动字幕专用 |
| `image` | 静态图片 | 仅剪映，CapCut 国际版用 video 轨道 |

### 4.3 片段 (Segment) — 最核心的数据结构

```json
{
  "id": "segment-uuid",
  "material_id": "material-uuid",

  // 时间控制
  "target_timerange": {
    "start": 0,             // 在时间轴上的起始位置（微秒）
    "duration": 5000000     // 在时间轴上的持续时长（微秒）
  },
  "source_timerange": {
    "start": 0,             // 从素材的哪个位置开始（微秒）—— 用于裁剪
    "duration": 5000000     // 截取素材的时长（微秒）
  },

  // 伴侣素材引用
  "extra_material_refs": [
    "uuid-speed-material",
    "uuid-mask-material",
    "uuid-animation-material",
    "uuid-transition-material",
    "uuid-audio-fade-material"
  ],

  // 画面属性
  "clip": {
    "rotation": 0,
    "alpha": 1.0,
    "scale": {"x": 1.0, "y": 1.0},
    "transform": {"x": 0.0, "y": 0.0},
    "flip": {"horizontal": false, "vertical": false}
  },

  // 基础属性
  "speed": 1.0,
  "volume": 1.0,
  "visible": true,
  "render_index": 0,
  "render_uniform_index": -1,

  // 混合模式
  "mix_mode": null,         // "screen" / "multiply" / "overlay" 等

  // 其他
  "group_id": "",
  "track_attribute": 0,
  "track_render_index": 1,
  "source": "segmentsourcenormal",
  "state": 0,
  "template_id": "",
  "template_scene": "default",
  "hdr_settings": null,
  "reverse": false,
  "uniform_scale": {"on": true, "value": 1}
}
```

**四个关键字段**：
1. `material_id` → 定义这个 segment 是什么
2. `target_timerange` → 在时间轴上的位置（微秒）
3. `source_timerange` → 从素材中截取哪一段（微秒）
4. `extra_material_refs[]` → 关联的伴侣素材 UUID 数组

**时间单位**：剪映内部全部使用**微秒**（microseconds）。1 秒 = 1,000,000 微秒。pyJianYingDraft 等库提供了 `tim("1.5s")` 这样的便捷转换函数。

**素材截取与变速的关系**：
- `source_timerange` 控制从素材中截取哪一段
- `target_timerange` 控制在时间轴上占多少时长
- `speed` 控制播放速度
- 最终呈现 = `source_timerange.duration` / `speed` 时长，放在 `target_timerange` 的位置

### 4.4 转场 (Transitions)

转场作为**伴侣素材**存储在 `materials.transitions[]` 中，通过 segment 的 `extra_material_refs[]` 引用。

```json
// materials.transitions[]
{
  "id": "transition-uuid",
  "type": "transition",
  "name": "信号故障",
  "category_name": "基础",
  "duration": 500000,           // 转场时长（微秒）
  "resource_id": "..."          // CapCut 素材库中的转场 ID
}
```

转场添加在**前一个**视频片段上（即 `video_segment.add_transition(...)` 是给前一个 segment 添加转场）。

### 4.5 字幕/文本 (Texts) — JSON-in-JSON 的复杂结构

文本是 `draft_content.json` 中**最复杂的部分**。文本内容不是直接 JSON 字段，而是**嵌入在 JSON 字符串内**。

#### text material 外层结构

```json
{
  "id": "text-material-uuid",
  "type": "text",
  "content": "{\"text\":\"Hello\",\"styles\":[...],\"layer_weight\":1,\"effect\":[]}",
  "font_name": "",
  "font_size": 8.0,
  "text_color": "#FFFFFFFF",
  "border_color": "#000000FF",
  "border_width": 0.0,
  "has_shadow": false,
  "shadow_color": "#000000FF",
  "shadow_distance": 8.0,
  "background_color": "#00000000",
  "text_alignment": 1,          // 0=左对齐, 1=居中, 2=右对齐
  "vertical": false
}
```

#### content 内层结构（JSON 字符串解析后）

```json
{
  "text": "Hello world",
  "styles": [
    {
      "range": [0, 10],                              // UTF-16 字节偏移量，不是字符索引
      "fill": {
        "content": {
          "solid": { "color": [1.0, 0.84, 0.0] }     // RGB 归一化颜色
        }
      },
      "font": { "id": "...", "path": "..." },
      "size": 18,
      "bold": true,
      "italic": false
    }
  ],
  "layer_weight": 1,
  "effect": []                   // 气泡/花字效果
}
```

**关键陷阱**：`styles[].range[]` 是 **UTF-16 LE 字节偏移量**，不是字符索引！
- ASCII 字符：1 字节 = 1 字符，可以直接用字符索引
- 中文/emoji：每个字符 2 字节（BMP）或 4 字节（非BMP）
- 手动编辑 `content` 字符串是导致"文本消失"bug 的主要原因

#### 气泡/花字效果

```json
// content 中的 effect 字段
{
  "effect": [
    {
      "bubble_id": "bubble_heart",
      "bubble_name": "爱心气泡"
    }
  ]
}
```

### 4.6 特效 (Effects) 和滤镜 (Filters)

**片段特效**：通过 `segment.add_effect(type)` 添加到 `extra_material_refs[]`，存储在 `materials.video_effects[]` 中。

**独立轨道特效**：创建 type 为 `effect` 的轨道，添加 segment。

**滤镜**：通过 `segment.add_filter(type, intensity)` 添加，同样通过 `extra_material_refs[]` 引用。

**动画**：入场/出场/组合动画存储在 `materials.material_animations[]` 中。文本还可有循环动画（`Text_loop_anim`）。

```json
// materials.video_effects[]
{
  "id": "effect-uuid",
  "type": "video_effect",
  "name": "模糊",
  "category_name": "基础",
  "resource_id": "...",
  "adjust_params": [
    {"name": "intensity", "value": 50}
  ]
}
```

### 4.7 关键帧 (Keyframes)

关键帧嵌入在 `clip` 对象中，支持对 `transform`、`scale`、`rotation`、`alpha` 等属性设置关键帧曲线。

### 4.8 音频淡入淡出

```json
// materials.audio_fades[]
{
  "id": "audio-fade-uuid",
  "type": "audio_fade",
  "fade_in_duration": 500000,    // 淡入时长（微秒）
  "fade_out_duration": 1000000   // 淡出时长（微秒）
}
```

通过 `segment.extra_material_refs[]` 引用。

## 5. 版本兼容性与加密

### 版本对照表

| 版本 | draft_content.json | 状态 |
|------|-------------------|------|
| 剪映 5.9.x 及以下 | **明文 JSON** | 所有开源工具链可读写 |
| 剪映 6.0.0 ~ 6.5.x | **加密二进制** | 无法读取，工具链失效 |
| 剪映 7.0.0 ~ 9.x | **加密** | 同上 |
| 剪映 10.0.0 ~ 10.3.x | 加密 + macOS "内容已损坏" bug | 同上 |
| CapCut 国际版（所有版本） | **明文 JSON** | 完全可用，仅 slug 命名空间不同 |

### 加密切换检测

加密后的 `draft_content.json` 是**高熵二进制 blob**，不再是有效的 UTF-8 JSON。capcut-cli 提供 `capcut decrypt` 命令检测加密状态。

### 已知解决方案

1. **降级到 5.9**：阻止 `update.exe` / `VEDetector.exe` 自动更新
2. **使用 CapCut 国际版**：始终保持明文 JSON
3. **第三方解密服务**：如 JyDraft 的云端解密 API（`POST /home/DecryptDraft`）

## 7. AI Skill 直接写草稿文件的原理

### 核心原理：文件注入驱动 (File Injection)

AI Skill（如 jianying-editor-skill、pyJianYingDraft、capcut-cli）能够直接生成剪映草稿，**不需要通过剪映的官方 API 或 GUI 操作**。其原理是：

```
┌──────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  AI Agent    │────▶│  Python/Node     │────▶│  draft_content.   │
│  (Claude等)  │     │  Wrapper 库      │     │  json 文件写入    │
│  生成指令    │     │  解析并转换逻辑   │     │  磁盘             │
└──────────────┘     └──────────────────┘     └────────┬─────────┘
                                                       │
                                              ┌────────▼─────────┐
                                              │  剪映读取草稿    │
                                              │  并渲染到时间轴  │
                                              └──────────────────┘
```

**关键要点**：

1. **剪映的草稿格式是纯 JSON**（5.9 及以下版本或 CapCut 国际版），全部存储在 `draft_content.json` 中
2. **不需要任何 API 密钥或认证** — 直接读写本地文件系统
3. **剪映启动时扫描草稿目录**，自动发现新草稿并加载
4. **刷新机制**：剪映不会实时刷新文件列表，需要重启剪映或点击旧草稿再退出
5. **素材路径必须是绝对路径**，否则剪映无法找到

### 工作流程

```python
# 1. 创建草稿对象
script = Script_file(1920, 1080)  # 设置分辨率

# 2. 添加轨道
script.add_track(Track_type.video)
script.add_track(Track_type.audio)
script.add_track(Track_type.text)

# 3. 添加素材到 materials
video_material = Video_material("D:/videos/clip.mp4")

# 4. 创建片段并添加到轨道
video_segment = Video_segment(video_material, trange("0s", "5s"))
script.add_segment(video_segment)

# 5. 添加特效/转场/字幕
video_segment.add_transition(Transition_type.信号故障)
text_segment = Text_segment("字幕内容", trange("0s", "5s"))
script.add_segment(text_segment)

# 6. 保存到草稿目录
script.save()  # 写入 draft_content.json
```

### jianying-editor-skill 的架构

该项目是当前最完善的 AI 剪映自动化方案，架构分为三层：

1. **AI 层**（Claude/大模型）：理解自然语言指令，生成 Python 调用
2. **Skill 引擎层**（JyWrapper）：Python 封装，提供高级 API
   - `JyProject` — 项目管理
   - `add_media_safe` — 素材导入
   - `add_text_simple` — 文本添加
   - `add_tts_intelligent` — 智能配音
   - `add_narrated_subtitles` — 配音+字幕对齐
   - `asset_search.py` — 特效/滤镜搜索
3. **草稿写入层**（pyJianYingDraft）：底层 JSON 构造，写入磁盘

### 与 WelooAI 的关系

用户提到的 "WelooAI" 可能指 `luoluoluo22/jianying-editor-skill` 项目（该项目的网站域名为 jianyingskill.netlify.app），其核心原理与上述完全一致——通过 Python 直接构造 `draft_content.json` 并写入剪映草稿目录，绕过了剪映的 GUI 操作。

### 局限性

- **剪映 6.0+ 加密**：草稿文件被加密，无法直接解析和写入
- **自动导出受限**：仅支持剪映 5.9 及以下版本的自动导出（通过 UI 自动化模拟点击）
- **实时特效不可用**：智能抠图、美颜等需要 GPU 实时处理的功能无法通过草稿文件控制
- **仅桌面版**：不支持移动端剪映
- **跨平台素材路径**：Windows 和 Mac 的路径格式不同，需注意兼容性
