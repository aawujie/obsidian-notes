LLM 评测体系已从简单的对话质量打分，演进为覆盖编码、智能体工具使用、通用知识三大维度的多维度基准。以下逐一拆解 12 项主流评测。

---

## 🖥 编码 / 软件工程

### Terminal-Bench 2.0
**全称**：Terminal Benchmark 2.0

**测什么**：给定自然语言指令，模型能否在终端中生成并执行正确的命令行操作。涵盖文件操作、文本处理（sed/awk/grep）、进程管理、网络诊断等真实终端场景。

**为什么重要**：这是离工程师日常最近的能力——不用 IDE，不用代码补全，纯靠自然语言操控 shell。Agent 编码的第一步往往是读懂环境、跑对命令。

**评测方式**：在隔离容器中执行，检查命令输出是否正确、副作用是否符合预期。


### SWE-bench Pro
**全称**：Software Engineering Benchmark Pro

**测什么**：从 GitHub 真实 issue 出发，模型需读懂 bug 描述 → 定位代码仓库中相关文件 → 写出修复补丁 → 通过项目原有测试。

**为什么重要**：这是目前最硬核的编码评测。不是从零写玩具项目，而是在真实的大型代码仓库（如 Django、Flask、SymPy）中修 bug。需要代码理解、上下文定位、跨文件推理的综合能力。

**与 SWE-bench 原版的区别**：Pro 版提高了难度——issue 更复杂，代码仓更大，且要求补丁一次性通过所有测试（原版允许多次尝试）。


### SWE-bench Multilingual
**全称**：Software Engineering Benchmark Multilingual

**测什么**：与 SWE-bench Pro 相同的 GitHub issue 修复任务，但代码仓库覆盖多语言——不限于 Python，还包括 Java、Go、TypeScript、Rust 等。

**为什么重要**：单语言评测有盲区。Python 社区 issue 描述风格、代码结构有其特征，模型可能在 Python 上过拟合。多语言版本测试的是**语言无关的编程推理能力**。


### NL2Repo
**全称**：Natural Language to Repository

**测什么**：从自然语言需求描述直接生成完整代码仓库——包括目录结构、多文件模块、依赖管理、配置文件、测试用例。

**为什么重要**：这是长周期编码能力的极限测试。修 bug 只需要局部修改，但 NL2Repo 要求模型完成从需求理解 → 架构设计 → 多文件编码 → 测试覆盖的全链路。考验的是**长上下文规划**和**系统工程思维**，不是单函数生成。

## 🤖 智能体 / 工具使用

### MCP-Atlas
**全称**：Model Context Protocol Atlas

**测什么**：模型面对多个 MCP server 提供的真实工具时，能否正确选工具、传对参数、解析返回值。场景覆盖文件系统、数据库查询、API 调用等。

**MCP 是什么**：Model Context Protocol——Anthropic 推出的开放协议，让 LLM 以标准方式调用外部工具和数据源。

**为什么重要**：这是 Agent 的核心能力——工具不只是"会用"，还要**在该用时用、不该用时不用**，避免幻觉式调用。Atlas 侧重功能覆盖广度，测试模型面对数十个陌生工具时的泛化能力。


### MCP-Mark
**全称**：Model Context Protocol Mark

**测什么**：同上基于 MCP 协议的工具调用评测，但侧重压力维度——CRUD（Create/Read/Update/Delete）全场景覆盖、批量操作、嵌套调用（工具的返回值作为另一工具的输入）、错误恢复等。

**与 MCP-Atlas 的区别**：Atlas 测广度（会不会用各种工具），Mark 测深度（用得好不好、能不能应对复杂链式调用）。


### ClawEval
**全称**：Claw Evaluation Benchmark（OpenClaw 生态）

**测什么**：300 个经人工验证的真实世界任务，模拟浏览器操作、文件管理、API 调用、数据处理等多步骤自主执行。关键特征：**包含完整轨迹审计**，不只是看最终结果，还看中间每一步是否合理。

**为什么重要**：传统评测只管"答案对不对"，ClawEval 把"过程对不对"也纳入评分。Agent 不能靠蒙——中间某一步如果走了弯路、执行了多余操作、或采用了不安全的方式，都会被扣分。


### CoWorkBench
**全称**：Collaborative Work Benchmark

**测什么**：多轮人机协作场景——模型产出一版结果 → 人类给反馈 → 模型根据反馈调整 → 持续迭代。考验**听懂反馈、按需修正、不丢失上下文**的能力。

**为什么重要**：真实工作中几乎没有一次性交付的场景。模型能不能在"这里不对，换个思路"之后正确调整而不忘掉之前讨论的其他约束——这决定了它到底是工具还是协作者。

## 🧠 通用能力 / 知识

### HLE（人类终极考试）
**全称**：Human's Last Exam

**测什么**：100+ 学科的博士级难题，覆盖数学、物理、化学、生物、医学、法律、哲学、经济学等。命题原则：**只要人类专家能稳定答对，模型就不该拿满分**——所以题目极难，旨在探测模型能力的上限。

**为什么重要**：它是目前最全面的"模型天花板探针"。其他评测可能已经饱和（多个模型接近满分），HLE 的设计目标就是**不让你满分**，从而区分顶尖模型之间的微小差距。


### Apex
**全称**：Apex Math Reasoning

**测什么**：高阶数学推理——不限于计算，更重**证明、推导、数学直觉**。覆盖数论、代数拓扑、泛函分析、概率论等。

**为什么重要**：计算可以用代码辅助（Wolfram、SymPy），但数学直觉和证明构造是纯推理能力。Apex 的高分模型通常在需要严密逻辑链的任务上表现更好，从代码审查到架构设计都能受益。


### IFBench
**全称**：Instruction Following Benchmark

**测什么**：给定多约束指令（如"用 JSON 格式回复，包含 3-5 个要点，每个要点不超过 20 字，不要使用被动语态，涉及金额时用美元表示"），检查模型是否精确遵守每一条约束。

**为什么重要**：这是 LLM 最基础也最容易被忽视的能力。模型文笔再好、知识再多，如果我说"只列 3 条"它列了 5 条，就是失效。IFBench 衡量的不是智商，是**遵循指令的纪律**。


### SuperGPQA
**全称**：Super Graduate-Level Performance Qualified Assessment

**测什么**：研究生级别的跨学科知识问答，覆盖物理、化学、生物、地球科学、经济学等。题目深度高于本科通识、低于博士专题，类似 GRE Subject Test 的泛化版本。

**为什么重要**：通用评测（如 MMLU）已经被大量刷分，区分度下降。SuperGPQA 以更难的题目、更广的学科覆盖，重新建立研究生层次的分辨力。

## 当前格局（2026-05）

| 维度 | 领先模型 | 关键差距 |
|------|----------|----------|
| 编码/软件工程 | Qwen3.7-Max | SWE-bench Pro 和 Multilingual 均第一 |
| 数学推理 (Apex) | Qwen3.7-Max | 44.5 vs 第二 38.3，断层领先 |
| 指令跟随 (IFBench) | Qwen3.7-Max | 约束遵守能力最稳定 |
| 智能体协作 (ClawEval, CoWorkBench) | Claude Opus 4.7 | 多步执行和人类反馈适应最强 |
| 极端知识 (HLE) | 接近，各模型差距小 | 题目难度对当前所有模型仍然是天花板 |

Qwen3.7-Max 在 12 项中拿下 7 项第一，尤其在编码和推理维度领先明显。Claude Opus 4.7 在需要持续多步自主执行的 Agent 类任务上保持优势——这与 Anthropic 在 tool use 和 agentic workflow 上的长期投入一致。
