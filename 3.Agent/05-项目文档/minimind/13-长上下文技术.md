# 长上下文技术

大语言模型的"上下文窗口"决定了它一次能看多少文本。怎么把窗口从几千 token 撑到几百万？

---

## 核心问题

Transformer 的 Attention 计算量是 O(n²)——上下文长度翻倍，计算量翻四倍，显存也翻倍。所以"支持长上下文"本质上要解两个问题：

1. **算得动** — 计算量和显存不能爆
2. **效果好** — 长距离的信息真的能被模型"记住"

---

## 技术流派总览

```
长上下文
├── 训练侧：直接用长数据训练（暴力但最有效）
│   ├── 原生长上下文训练（Gemini 1M、Claude 200K）
│   └── 渐进式训练：短→中→长分阶段拉长
│
├── 位置编码外推：训练时短，推理时拉长
│   ├── RoPE 线性插值（PI）
│   ├── NTK-aware Scaling
│   ├── YaRN（minimind 采用）
│   └── LongRoPE
│
├── Attention 工程优化：让 O(n²) 不那么疼
│   ├── Flash Attention（IO 感知，省显存）
│   ├── Ring Attention（多设备环形传递 KV）
│   ├── 稀疏 Attention（只看重要位置）
│   └── Sliding Window Attention（只看局部窗口）
│
└── KV Cache 优化：推理时塞下更多 token
    ├── Multi-Query / Grouped-Query Attention（GQA）
    ├── KV Cache 量化（INT8/INT4）
    └── KV 压缩/驱逐（H₂O, StreamingLLM 等）
```

---

## 各方案一句话

### 位置编码外推

| 方案 | 原理 | 效果 |
|------|------|------|
| **线性插值 (PI)** | 把位置直接除以缩放因子，压进训练范围 | 简单但外推倍数大了效果差 |
| **NTK-aware** | 只缩放 RoPE 的低频分量，高频不动 | 比线性插值好 |
| **YaRN** | NTK 基础上加注意力缩放 + 平滑过渡 | 效果最好的免训练方案之一 |
| **LongRoPE** | 搜索最优的频率缩放因子 | Google 提出，效果好但需搜索 |

**minimind 用的是 YaRN**：训练时上下文 ~768 token，推理时理论可达 32768（16× 外推）。

### 原生长上下文训练

| 模型 | 上下文长度 | 怎么做到的 |
|------|-----------|-----------|
| **Gemini 1.5/2.0** | 1M → 2M | TPU 大集群 + Ring Attention + 直接长文本训练 |
| **Claude 3** | 200K | 渐进式训练 + 工程优化 |
| **GPT-4 Turbo** | 128K | 稀疏 Attention + 长文本训练 |
| **Qwen2.5** | 128K | YaRN + 渐进式训练 |
| **LLaMA 3.1** | 128K | RoPE 频率调整 + 长上下文继续预训练 |

**关键区别**：原生训练的模型在长文本上效果远好于纯外推。外推是"猜"，训练是"见过"。

### Attention 工程优化

| 方案 | 一句话 |
|------|--------|
| **Flash Attention** | 不改数学，只改内存访问模式，省 5-20× 显存 |
| **Ring Attention** | 长序列切段分到多台机器，KV 在设备间环形传递 |
| **稀疏 Attention** | 每个 token 只看附近 + 少量远处关键位置 |
| **Sliding Window** | 每个 token 只看固定窗口大小的邻居（Mistral 用） |

### KV Cache 优化

| 方案 | 一句话 |
|------|--------|
| **GQA** | 多个 Query 头共享 KV 头，Cache 直接缩小到 1/N |
| **MQA** | GQA 的极端版，所有 Query 共享一组 KV |
| **KV 量化** | 把 Cache 从 fp16 压到 INT8/INT4 |
| **H₂O / StreamingLLM** | 只保留重要的 KV，丢弃不重要的 |

---

## minimind 用了哪些

| 技术 | minimind 中的应用 |
|------|------------------|
| **YaRN** | `inference_rope_scaling=True` 时启用，16× 外推 |
| **GQA** | `num_attention_heads=8, num_key_value_heads=4`，2× KV 压缩 |
| **Flash Attention** | `config.flash_attn=True` 时走 PyTorch SDPA 快路径 |
| **RoPE** | 基础位置编码，`rope_theta=1e6` |

## 直觉类比

> 想象你在图书馆找资料——
>
> - **原生长上下文训练** = 你读过整个图书馆，什么都记得
> - **YaRN 外推** = 你只读过一个书架，靠"推理"猜其他书架大概在讲什么
> - **Flash Attention** = 你翻书的速度变快了，但能记住多少没变
> - **Ring Attention** = 你叫了几个朋友一起翻，每人负责一排书架
> - **稀疏 Attention** = 你只翻目录和关键章节，跳过不重要的
> - **KV Cache 压缩** = 你做的笔记越来越精简，腾出空间记更多书
