## 📌 核心观点

**NanoClaw** 是对 OpenClaw 复杂性的反应，定位为轻量级、AI-Native 的替代方案。

| 维度 | OpenClaw | NanoClaw |
|------|----------|----------|
| **代码规模** | 43 万行代码 | 轻量级 |
| **架构理念** | 功能齐全，开箱即用 | AI-Native，可动态改写 |
| **目标用户** | 普通用户（想要全功能助手） | Power Users（想理解掌控全栈） |
| **安全性** | 直接运行在设备上 | 容器化沙盒 |
| **定制化** | 需要手动修改配置 | 可用 AI 直接改写代码 |

## 🏗️ 架构设计

### 容器生命周期

NanoClaw 使用**临时容器**架构：

```
1. 收到消息 →  spawn 容器
2. 挂载持久化目录（memory/等）
3. 处理消息 → 流式返回响应
4. 对话超时 → 容器销毁
```

**比喻**: 像哈利波特的魔法办公楼——每个对话打开一个临时房间，处理完后房间消失。

### 持久化机制

- 容器是临时的，但**状态通过挂载目录持久化**
- 可以配置让容器访问主机上的特定目录
- 记忆和配置保存在挂载的目录中

## ⚙️ 安装与配置

### 快速开始

```bash
git clone <nanoclaw-repo>
cd nanoclaw
claude
/run setup
```

### 配置步骤

1. **选择通信渠道**（Telegram/Discord 等）
2. **配置 Bot Token**（写入 `.env`）
3. **选择沙盒模式**（是否允许访问外部目录）
4. **注册 Chat ID**（与 Bot 建立连接）
5. **可选：配置 Agent Swarm**（需要多个 Bot）

### Agent Swarm 配置

- 需要 3-5 个 Telegram Bot
- 创建群组聊天
- 每个 Bot 可扮演不同角色（Scraper、Researcher、Coder 等）
- Orchestrator 协调各 Agent 工作

## 💡 使用体验

### 优点

✅ **AI-Native 设计** — 让 AI 自己改写和扩展代码  
✅ **轻量级** — 代码库小，易于理解  
✅ **容器化安全** — 沙盒运行，不直接访问主机  
✅ **灵活定制** — 用 Claude Code 直接修改  
✅ **Agent Swarm** — 内置多智能体协作能力  

### 缺点/注意事项

⚠️ **容器会超时销毁** — 长对话可能中断  
⚠️ **需要配合 AI 编程助手** — 建议同时打开 Claude Code 窗口  
⚠️ **渠道支持较少** — 不如 OpenClaw 丰富  
⚠️ **需要手动配置** — 不像 OpenClaw 开箱即用

## 🎯 总结与评价

### 作者结论

> "NanoClaw 是我目前最喜欢的 Claw，甚至可能超过 OpenClaw。"

**核心理由**:
1. **AI-Native 理念** — 代表未来方向
2. **易于定制** — 用 AI 改写 AI 助手
3. **轻量灵活** — 不像 OpenClaw 那样臃肿
4. **Agent Swarm** — 多智能体协作很强大

### 适用人群

- ✅ 想理解和掌控全栈的 Power Users
- ✅ 喜欢用 AI 编程助手定制工具
- ✅ 需要多智能体协作场景
- ❌ 只想开箱即用的普通用户
