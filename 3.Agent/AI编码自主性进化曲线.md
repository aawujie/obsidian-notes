# AI 编码自主性进化曲线

![[ai-coding-autonomy-timeline.jpg]]

> **标题**：Length Of Coding Tasks AI Agents Can Complete Autonomously
> **发布时间**：2025 年 12 月（用于澄清 2025 年 4 月的预测；作者注明该版本已过时，新预测即将发布）
> **横轴**：AI 模型发布日期（2021 → 2028）
> **纵轴**：任务时长（以人类完成同一任务所需时间衡量），对数尺度，80% 成功率门槛

---

## 一、这张图在说什么

METR（Model Evaluation & Threat Research）追踪了一个关键指标：**AI 模型能以 80% 的成功率自主完成多长的编码任务**——这里的"多长"不是 AI 的执行时间，而是**同一任务让人类来做需要多久**。

纵轴采用对数尺度——从 8 秒到 5 年，每一格是一个数量级的跃迁。

核心发现：这条曲线的倍增周期约为 **7 个月**——每过 7 个月，AI 能自主完成的任务复杂度翻一倍。

图中标记了来自 METR 实测的各模型数据点（非理论预测）：

## 四、三个 Agent 里程碑

图右侧标出了三个灰色的 Agent 里程碑（预测，非实测）：

| 里程碑 | 预计时间 | 对应任务量级 | 含义 |
|:---|:---|:---|:---|
| **Agent-0** | ~2025 | ~30 分钟–1 小时 | 模型能在单次会话中使用工具完成多步任务。今天的 Claude Code / Cursor Agent 已基本达到 |
| **Agent-1** | ~2027 | ~1 周 | 能拆分子任务、并行执行、跨会话工作、处理失败重试。相当于能独立推进一个 feature 的 junior engineer |
| **Agent-2** | ~2028 | ~数月 | 长期目标驱动，自主规划-执行-调整，持续数周到数月。相当于能独立负责一个项目的 senior engineer |

从 Agent-0 到 Agent-2，核心变化不是模型能力本身，而是**模型 + 规划 + 工具链 + 记忆 + 自我纠错**的系统性整合。

## 五、四个进化阶段

### Phase 1：代码补全（2021–2023）→ 秒到分钟级

- **代表模型**：gpt-3.5-turbo-instruct、GPT-4 0314
- **能做什么**：单个函数补全、简单 bug 修复、代码解释
- **工作模式**：人类写大部分代码，AI 补全片段
- **80% 成功率任务上限**：~1 分钟

### Phase 2：任务执行（2024–2025 H1）→ 分钟到半小时级

- **代表模型**：o1、Claude 3.5 Sonnet (New)、GPT-5、Claude 3.7 Sonnet
- **能做什么**：完整模块开发、多文件修改、测试驱动迭代、独立调研
- **工作模式**：人类派任务、提供上下文，AI 独立执行
- **80% 成功率任务上限**：~30 分钟

这是**当前所处的阶段**——用 Cursor / Claude Code 写脚本、做模块开发、执行调研任务。

### Phase 3：独立交付（2025 H2–2027）→ 小时到周级

- **代表模型**：GPT-5.1-Codex-Max、Mythos-Preview → Agent-0/1
- **能做什么**：跨模块联调、完整 sprint 交付、自主拆解需求
- **工作模式**：给定方向和约束，Agent 自主拆解-执行-验收
- **80% 成功率任务上限**：数小时 → 1 周

### Phase 4：自主工程（2027–2028+）→ 月到年级

- **代表模型**：Agent-2 及以后
- **能做什么**：从需求到上线的完整产品、长期维护和迭代
- **工作模式**：只给目标，Agent 承担全部工程过程
- **80% 成功率任务上限**：数月到数年

## 六、为什么是指数增长？

在对数尺度下，数据点近似线性排列——这意味着底层增长是**指数级**的。METR 论文拟合出的倍增周期约 7 个月：

```
gpt-3.5-turbo-inst → GPT-4:       8 秒 → 1 分钟       (~8x)
GPT-4 → o1:                       1 分钟 → 8 分钟      (~8x)
o1 → GPT-5:                       8 分钟 → 20 分钟     (~2.5x)
GPT-5 → GPT-5.1-Codex-Max:        20 分钟 → 30 分钟    (~1.5x)
```

加速的本质原因：每一代模型不仅在知识和推理上提升，更在**自主性、上下文窗口、工具使用、长期规划**四个维度叠加进化。这些能力**相乘而非相加**。

---

## 七、预测分歧与不确定性

图中最值得注意的是**五条趋势线的扇形散开**——2026 年以后，不同预测之间的差距越来越大：

| 预测 | 超人编码者到达时间 | 关键假设 |
|:---|:---|:---|
| Daniel's mode | 2027 年 3 月 | Scaling 持续有效，Agent 框架快速成熟 |
| Daniel's median | 2028 年 6 月 | 中间路径 |
| Eli's median | 2030 年 6 月 | Scaling 遇到瓶颈，Agent 落地比预期慢 |

这 3 年的分歧代表了社区对两个核心问题的不确定性：
1. **模型 Scaling 是否触顶？** — 如果 Scaling Law 继续有效，2027 年就能到
2. **Agent 框架能否填补能力缺口？** — 单模型能力有上限，系统能力是否能弥补

---

## 八、对实际工作模式的启示

| 时间窗口 | 工作模式 | 举例 |
|:---|:---|:---|
| **当前**（Phase 2） | 人类拆解任务 → 派给 AI → 验收结果 | "把这个模块重构，加上测试" |
| **1–2 年后**（Phase 3） | 给方向 → AI 自主拆解子任务 → 并行执行 → 汇总 | "整理整个工程架构，出重构方案" |
| **3 年后**（Phase 4） | 给目标 → Agent 自主规划-执行-维护 | "搭建完整的 CI/CD 平台并上线运维" |

## 九、一句话总结

> 以 7 个月倍增的速度，AI 编码能力正从"帮你补全一行代码"进化到"独立交付整个项目"。我们今天的人机协作模式是过渡态——图表上方的 Agent-1/2 才是终局。
