## 核心观点

一个免费开源模型可以同时跑 300 个 Agent、4000 个协调步骤，在真实研究任务上的得分比贵 5 倍的模型还高。但大多数人只用 Kimi 当聊天框，只用了 10% 的能力。

定价：$0.95/M 输入、$4.00/M 输出，缓存命中 $0.16。

---

## 10 步构建自我进化的 Agent Loop

### 01. 写规格，不是写提示词

别写"研究健身App市场"，写清楚要收集什么、什么算有效、允许哪些数据源、输出格式、冲突怎么处理。你定义目标，Kimi 自己分解任务、组建 Agent 组织架构。

### 02. 先看分解计划再花钱

提交 spec 后，Kimi 会先展示执行计划——多少子 Agent、各自的职责、依赖顺序、步骤预算。4000 步是集群总预算，300 个 Agent 平均每个 ~13 步。确认计划对了再跑，省钱。

### 03. 允许浪费——这是设计意图

300 个 Agent 分波并行执行，每个子 Agent 有独立的上下文窗口，不会像单个 Agent 那样上下文爆掉。定价便宜到可以扔掉第一次结果重新跑。

### 04. 要求交付真实文件，不是聊天回答

"一份 40 页 PDF + 一个 2 万行的 CSV + 14 张导出级 PNG 图表" vs "一份综合报告"。明确输出规格 = 明确质量标尺。

### 05. 让诚实模型做验证

用 Claude Opus 4.8 做验证门。Opus 4.8 是第一个对自身代码缺陷零姑息的模型，它的唯一工作是反驳，不是赞美。廉价算力只有在有可信验证时才叫超级能力。

### 06. 保存为 Skill

第一次跑 20 分钟，之后每次 30 秒。把整个工作流保存为可复用技能，系统在变聪明，即使模型权重没变。

### 07. 喂自己的文档

上传你最好的提案/报告/PPT，Kimi 提取结构和风格指纹，300 个 Agent 都能以此为基准生成。输出不再像通用 AI。

### 08. 把验证反馈变成永久规则

Opus 提出的问题不只修补当前输出，写入项目级约束文件，下次自动生效。约束文件变成自动执行的活文档。

### 09. 用新输入重放技能，成本暴跌

第一次做竞品监控需要完整 spec + 验证。第四次只需要 30 秒 prompt 对着保存好的 skill，输出更精准因为它继承了之前所有修复。

### 10. 升级为后台 Agent

稳定后不再手动触发，设定定时/文件变化/竞品网页更新等触发器，自动跑全流程，只推送最终结果和异常。

---

## 结论

问题不是"哪个模型最聪明"，而是"你能同时跑多少个、谁在检查它们的工作、你的系统今天是不是比昨天更聪明"。

这种模式与 DeepSeek 开源时刻类似——一个开源方案重新定义了闭源前沿以为独占的东西，整个领域一夜之间重新校准。
