# 1. 概要

- Prepared是一家专注于为911 / 公共安全与城市非紧急服务中心（如311）提供AI驱动产品的公司。其产品分两大类：
    - 对非紧急、重复性事情实现端到端自动化（例如噪音投诉、罚单、停车问题、311呼叫），以降低话务员负担、消除排队等待；
    - 在紧急呼叫中作为“协同驾驶员”（co‑pilot），提供实时转写、翻译、CAD记录填充与摘要，辅助话务员不遗漏关键信息并快速向响应单位派发准确信息。

# 2. 背景与起点（为什么做这个）

## 创始背景

- 创始人受一起枪击事件影响，从学校安全出发做起，最初开发面向学校的应急通讯应用，后来通过与学校和911中心的接触发现了公共安全通信系统的严重落后与现实缺口（例如系统仍假定呼叫来自固定电话、不能方便地共享图片或文本等）。

## 市场洞察

- 大量呼叫是非紧急的，人力耗费巨大；同时，多语言服务、实时记录与质检覆盖率低，存在显著提升空间。

# 3. 公共安全领域的主要痛点（为何AI有价值）

- 非紧急呼叫占比高，很多城市非紧急热线（311）存在长时间等待（示例：部分城市非紧急呼叫平均排队时间可达40分钟）。
- 多语言沟通瓶颈：人工口译到位前可能造成数分钟延迟，且不同语言响应时间差异明显。
- 质检（QA）覆盖率极低：传统靠人工抽查，可覆盖的呼叫仅约个位数百分点，难以发现与纠正系统性问题。
- 关键细节遗漏风险高：在紧急场景中，少量未被记录或未被识别的描述（如现场有人自闭症等）会影响现场应对策略与安全。

# 4. Prepared的核心产品与实现方式

## 实时转写与即时翻译（首个切入点）

- 立刻为非英语呼叫提供转写与机器翻译，显著缩短等待人工口译的时长，提升快速识别紧急信息的能力。

## 非紧急呼叫端到端自动化（语音AI代理）

- 对常见的311/非紧急来电完成自动问答、表单填写、工单创建与后续跟踪；支持与CAD（计算机辅助调度系统）集成，实现自动生成事件记录或派单。
- 支持“人机并行”模式：运营人员可监看多个呼叫实时转写，必要时随时插入（barge in），保持人类监督。

## 紧急呼叫协同（Co‑pilot）

- 实时摘要、关键词检测、自动填充CAD条目、生成可快速下发给响应单位的简明摘要，保证不遗漏重要细节并提高质检覆盖率。

## 质量保证自动化（QA）

- 将原来人工抽样的质检流程自动化：识别是否完成必检动作（如核实地点、核实事件类型等），并给出AI判断依据，提升到对所有通话的覆盖并实现即时反馈与同日培训。

# 5. 数据安全与合规

- 数据驻留：所有数据保存在美国境内（满足多数公共安全机构对地域性的基本要求）。
- 合规与标准：遵循刑事司法信息安全等行业规范（如CJIS）并通过行业常见合规（如SOC 2等）。
- 训练政策：不使用客户敏感通话数据作为默认训练数据（即不以客户数据训练通用模型），保证呼叫内容不被用于扩展模型训练。
- 责任与透明性：对AI作出的判断提供“原因说明”，便于人工复核与纠正。

# 6. 部署与落地建议（实施步骤与变更管理）

## 典型实施路径

1. 试点阶段：在少数班次或特定非紧急线路上并行部署（可在一天内快速上线转写/翻译监视器）。
2. 验证效果：监控关键指标（见下一节），收集话务员与调度员反馈，调整话术与流程。
3. 扩展自动化：对重复性高、规则明确的呼叫类型逐步启用语音代理并与后端CAD/工单系统集成。
4. 全面推广：在保留人工可插入的前提下，提高自动化覆盖率，并将QA自动化纳入常规管理。

## 落地要点（变更管理）

- 强调最终目的是“解放话务员做更重要的事”，不是替代人类的同理心能力；
- 保持人机可控：初期保留实时监控与人工打断功能；
- 培训与文化：新员工须在入职前90天内实地走访911中心，培养对用户场景的深度理解与同理心；
- 逐步替代而非一次性替换，先从繁重的非紧急工作入手，逐步扩展。

# 7. 运营指标与实际成效（可量化的KPIs）

## 推荐监测的关键指标

- 非紧急呼叫平均等待时间（Hold time）；
- 语音AI处理的非紧急呼叫占比与成功率（端到端完成率）；
- 质检覆盖率（已从传统的 ~3%提升到100%的可实现目标）；
- 多语言呼叫响应延迟（平均从人工口译数分钟降低到即时翻译）；
- 紧急事件中信息完整性（如关键细节被捕获率）。

## 典型成功案例摘要

- 通过即时转写识别到一通曼语呼叫中的“我女儿被枪击”字样，并据此立即派遣警力与EMS，挽救了生命（在采访中被作为真实示例提及）；
- 在大型城市中减少非紧急呼叫的平均排队时间至接近零，缓解了长期超时等待的问题。

# 8. 市场与组织策略（客户采纳路径）

## 采用“以用户为先”的落地策略

- 通过免费或低门槛试用（free tier）先触达一线话务员，证明价值并借助他们推动部门级或市政级采购决策；
- 将技术视为“合作伙伴”（technology partner），以解决具体痛点为导向而非卖技术本身。

## 团队构成与文化

- 成员兼具技术背景与公共安全从业经验，产品/工程团队与911领域专家紧密协作；
- 强调实地调研与同理心（如要求新员工现场观摩非英语通话、质检流程等）。

# 9. 风险与治理建议

- 不应自动化的情况：对话中涉及复杂情绪、严重危机或需要强烈同理心的场景应保留或优先由人工处理。
- 避免孤岛数据：将各类信息（转写、CAD、历史记录、传感器数据等）整合到统一视图，避免多系统割裂导致上下文丢失。
- 透明与可审计：对AI判断提供可审计理由，便于事后回溯与监督，降低误判带来的责任风险。

# 10. 未来展望与建议（5–10年）

## 预期形态

- 911话务员将更像“空中交通管制员”，专注高风险、高同理心的决策工作；
- 非紧急服务（311）将实现广泛自动化，每个城市可实现24/7的即时响应能力，降低人力成本并提高服务可达性；
- 信息展示将从多个屏幕与孤立系统，走向单一智能界面，基于全量上下文做出更准确判断。

## 对政府与决策者的建议

- 优先在公共安全、紧急响应等“需及时帮助”的场景试点AI；
- 建立统一的数据与合规框架（数据驻留、访问控制、审计），为AI在政务中的应用奠定信任基础；
- 在采购与部署时重视用户采纳路径（先让一线人员看到并认可价值），而非仅与传统大厂谈判。

# 11. 小结（可操作要点）

## 优先级建议

5. 先解决“非紧急、高复用”的工作自动化（立即可见成效）；
6. 同时在紧急场景部署协同型AI（实时转写、摘要、QA覆盖），确保“不丢失关键 important information”；
7. 严格数据治理（境内驻留、CJIS/SOC2等合规、默认不以客户通话训练模型）；
8. 采用人机并行与可随时接管的模式，逐步放大自动化覆盖率并持续监测关键指标。
