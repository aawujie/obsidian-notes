下面是对 Brian 的长视频“在 Claude Code / VS Code 中完整演示 BMAD 方法”的中文博客式总结，涵盖关键信息、步骤、命令提示与最佳实践——便于你快速上手并复刻演示流程。\n\n一、前言：什么是 BMAD 方法？\nBMAD（Brian 的方法）是一个以 AI agent 驱动的敏捷开发工作流，目标是把产品从构思（ideation）带到可交付代码。它通过一套角色化的 agent（如业务分析师、产品经理、架构师、Scrum Master、开发者、QA）与模板化的 YAML 指南来协同产出产物（头脑风暴文档、项目简报、PRD、架构文档、故事卡、代码等）。重要特点包括“人机协作式引导”（agent 不替你做所有决策，而是当作教练）与“上下文工程”（shard 与固定加载文件，保证 agent 拿到合适的上下文）。\n\n二、快速安装（在任意目录）\n在终端（演示为 VS Code 内终端）执行：\nnpx bmad-method install\n选择安装目录（例如 ./simple-to-do），按提示选择 BMAD core、是否 shard 文档，以及要集成到哪个 IDE（演示以 Cloud Code / VS Code 为例）。安装完成后，会在项目里生成 BMAD 的指令/模板与命令帮助（供 Cloud Code 使用的 slash 命令）。\n\n三、在 Cloud Code / VS Code 中启动 Claude Code\n在项目根目录中输入：\nclaude\n首次打开会询问信任文件夹（trust）。Cloud Code 中可直接用“/”来调出 BMAD 各 agent 的命令列表（或直接输入 agent 名称部分做模糊匹配）。\n\n四、主要 agent 与工作流（典型 Greenfield 流程）\n下面是视频中演示的顺序与要点。\n\n1) Analyst（业务分析师，例：Mary）——头脑风暴 + 项目简报（可选但推荐）\n- /analyst -> brainstorm：内置 20+ 头脑风暴技巧（如 6 色思考帽、5W、角色扮演等）。agent 会像教练一样问你问题、推进讨论并输出“头脑风暴文档”（Docs 文件夹内）。\n- 作用：把模糊想法变成结构化的洞见，并生成“项目简报”（Project Brief）草稿或辅助章节，作为后续 PRD 的输入。\n- tip：可用语音输入（演示使用“Super Whisper”等），每次生成文档后建议开新 chat（/clear 或关闭会话）以防 context 累积污染。\n\n2) Product Manager（PM）——生成 PRD（产品需求文档）\n- /pm -> create PRD（或 brownfield PRD）\n- 如果已有项目简报，将其作为输入以加速 PRD 生成；PM 会把高层目标、功能/非功能需求、MVP 范围、epics 与 user stories 都拆出来。\n- Advanced elicitation（高级引导）非常关键：例如“挑战范围”、“从不同角度批判性审视”、“如果/只有/后见之明”等，帮助缩减 MVP、发现依赖或风险。\n- 输出会分段生成（利于后续 shard）。\n\n3) Architect（架构师）——生成架构文档\n- /architect -> create backend / frontend / full-stack / brownfield architecture\n- 产出包括：高阶架构图、sequence diagram、数据模型、技术栈（含版本）、编码规范、source tree（项目目录结构）等。\n- 强调：把技术栈、编码规范、source tree 等写清并 shard 成单独文档，能保证后续 developer agent 一直按相同标准执行（避免“漂移”）。\n\n4) Shard（拆分大文档）\n- /shard（或 shard-doc）：把较大的 PRD/architecture 等按 header（如二级标题）拆分成小文件夹（如 /prds、/architecture），方便 agent 按需加载＆避免超大上下文。\n- 目的：更高效、只在必要时提供相关片段给 agent。\n\n5) PO Checklist & Scrum Master（PO / Scrum Master）\n- PO 可运行 run checklist（验证 PRD 与架构的对齐）。\n- Scrum Master 会把 PRD 的 epic→story 转成开发用的细粒度“待办（task）”或 story draft（/scrummaster draft）。\n- “correct_course” 功能：如果中途要改方向，可由 agent 自动评估如何修改 epics/stories/architecture，帮助做 pivot。\n\n6) Developer Agent（开发者，例：James）\n- /developer 或指定“develop story（e.g., draft 1.1）”：会读取 story 的所有上下文（包含 architect 的 source tree、coding standard、tech-stack 文档），然后逐步实现代码并在本地生成文件、package.json、测试脚本等。\n- 可以选择自动执行（unsafe/自动化模式）或半自动（人工 approve 每个步骤）。\n\n7) QA Agent（质量保证，例：Quinn）\n- /qa -> run tests / review story：在开发完成后，QA agent 会检查代码是否满足 acceptance criteria、发现问题或建议改进（建议在这一环节使用更强模型）。\n- 如果通过则标注“ready for review/approved”。\n\n五、重要命令与小技巧速览\n- 安装：npx bmad-method install\n- 启动 Claude：claude（在 VS Code 终端）\n- 常用 slash 命令（在 Cloud Code 下）：\n  /analyst（Mary）、/pm、/architect、/shard、/scrummaster、/developer、/qa、/po、/clear、/res（恢复历史会话）\n- 会话管理：\n  - 每输出一份 artifact（文档）后尽量开新 chat / 清空 context（/clear），避免 compaction 警告或上下文污染。\n  - 若丢失历史，可用 /res 恢复之前的 chat 列表。\n- 模型选择：演示多用 sonnet（$20 plan）即可完成大部分任务；建议在架构／QA 等关键阶段使用更强模型（opus / web Gemini）以提升准确度。\n- 强烈建议把 tech-stack、coding-standards、source-tree 列为 dev_load_always（developer agent 始终加载），保证 agent 的一致性。\n- 对已生成的文档（PRD/architecture）进行 shard，并把不常用的原始材料放到单独文件夹或外部存档，避免干扰正常上下文。\n\n六、brownfield vs greenfield\n- Greenfield：从零开始（空白场地），适合直接生成完整架构与 PRD。\n- Brownfield：已有遗留代码或应用，需额外上下文分析，brownfield 流程会要求更多的现状调查与兼容性考虑。\n\n七、BMAD 的核心价值与心得\n- 人机协同“教练式”头脑风暴：agent 不只是替你写文档，而是引导你深入挖掘、检验假设、提出替代方案，能产出更高质量的产品思路。\n- 文档化与上下文工程：通过 shard + 固定加载文档，确保不同 agent 在相同规则和源树下工作，避免“LLM 漂移”。\n- 可在 IDE（如 VS Code + Claude Code）内完成全流程：安装、brainstorm、brief、PRD、架构、story 拆解、开发、QA 全在本地（不一定要跳去 web）。\n- 灵活与可定制：模板与 YAML 可扩展；如果需要贡献或自定义扩展包，可 clone GitHub 仓库做二次开发。\n\n八、实践建议（快速清单）\n- 先用 Analyst 做头脑风暴，产出 Project Brief（可选但强烈推荐）。\n- 生成 PRD（PM）并用 advanced elicitation 压测/削减 MVP 范围。\n- 架构阶段用较强模型，明确 tech-stack、coding rules、source-tree 并 shard。\n- 在每次生成文档后开新 chat（/clear），保持上下文精简。\n- 把 tech-stack、coding-standards、source-tree 放入 dev_load_always。\n- 在关键步骤（架构、QA）优先使用更高能力模型（避免在关键决策上省资源）。\n- 把不需要常驻上下文的文档移出项目根目录或标记 ignore（.gitignore），避免被 agent 不必要加载。\n\n九、结语\n视频展示了如何在 Claude Code（VS Code）里，用 BMAD 方法从零到一地组织一个小型 To‑Do 项目演示全流程：从脑暴、写 Brief、生成 PRD、做架构、拆故事、开发实现，到自动化 QA。重点在于“以 agent 为角色的流程化协作 + 上下文工程（sharding 与 fixed load）”，能显著提升多人或单人开发的效率与一致性。实践中建议多和 agent 对话、使用高级 elicitation 验证决策，并在关键环节使用更强模型以提升可靠性。\n\n如果你想要我把视频中演示的具体命令与交互（按序的示例对话脚本与文件位置）整理成可复制的步骤清单（含示例命令、文件树与示例 PRD/architecture 模板），我可以把它做成一篇“上手指南”供你直接运行。你想先要哪一种？
