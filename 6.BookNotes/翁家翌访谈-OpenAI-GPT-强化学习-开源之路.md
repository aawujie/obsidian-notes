## 二、童年与数学启蒙

### 2.1 奥数之路

- **一年级开始学奥数**，一直学到初中
- 原因：爸妈让听奥数课和语文课 → 对语文不感兴趣，对奥数很感兴趣
- **做题比别人快**：二年级口算题，别人写到一半，他已经做完
- 自己形容：System 1 思维，"直接表层意识过，看一眼出答案"

### 2.2 学习特点

> **学新东西比别人慢，但理解后用得非常快。**

- 需要花别人 2-3 倍的时间理解
- 一旦理解，建立 shortcut，直接应用
- 比喻：背课文时磕磕巴巴，睡一觉后倒背如流

### 2.3 "投资未来"的思维

**初中就开始提前学高中数学**：

- 初二：学完高中数学
- 初三：开始学微积分

**原因**：
> "与其浪费时间刷题，不如学一点对未来有用的东西。"

- 不是父母推动，是**自发决策**
- 升学压力驱动（非北京学生，上清华北大难如登天）

### 2.4 正反馈循环

用 RL 术语解释自己的成长：

- 奥数 → 正反馈 → 继续投入 → 更多正反馈
- 体育/篮球 → 负反馈（被虐） → 不再投入
- "每次点技能树都有正反馈，就一直走这条路"

## 五、强化学习（RL）之路

### 5.1 RL 入门项目

清华时期第一个 RL 项目：**ViZDoom**（射击游戏）

- 用神经网络在固定地图里通关
- 杀怪、捡血包、避障、到达终点
- **拿了冠军**

### 5.2 RL 的痛苦

> **"我很不享受这个科研过程。"**

**原因**：
1. **任务太单一** → 需要疯狂 overfit
2. **调参难** → 比 CV 难 10-100 倍
3. **全靠 heuristic** → 改算法不是本质
4. **大部分情况下不能 work**

### 5.3 RL 的认知

**环境 vs 算法**：
- 任务对人类简单，对 RL 很难
- RL 需要大量知识（什么是障碍物）
- 环境太单一 → 过拟合 → 无法泛化

### 5.4 转向 Infra

> "我会把重心放到如何帮助这类科研更顺利进展的过程上。"

**大四决定**：造一套 RL infra / library
- 让想卷的人更容易卷
- 这就是后来的 **天授**（TianShou）

## 六、天授（TianShou）：RL 框架

### 6.1 设计理念

**目标**：
- 帮助 RL 研究者更容易做实验
- 减少调参和 heuristic 的痛苦
- 提供方法论，而不是手搓

### 6.2 与其他框架的区别

| 框架 | 定位 |
|------|------|
| Stable-Baselines3 | 通用 RL |
| RLlib | 大规模分布式 |
| **天授** | 学术研究友好、模块化 |

## 九、OpenAI 经历：Post-training Infra

### 9.1 核心贡献

> **"OpenAI 很多 model release 都有我的名字，因为我在内部搭了整个 post-training 的 RL infra。"**

- ChatGPT
- GPT-4o
- GPT-5

### 9.2 Post-training 的本质

**Post-training = RLHF + 其他技术**：

- 预训练：学习语言能力
- Post-training：学习人类偏好、安全、对齐

### 9.3 Infra 的重要性

> "教一个 researcher 如何做好 engineering，远比教一个 engineer 如何做好 research 来的难。"

**原因**：
- 每一家的 infra 都有不同程度的 bug
- 谁修 bug 越多，谁的模型训得越好

## 十、Infra vs Research

### 10.1 角色分工

| 角色 | 工作 |
|------|------|
| Researcher | 提出新算法、新想法 |
| Infra Engineer | 实现系统、修 bug、优化性能 |

### 10.2 现实认知

> **"Researcher 和 infra engineer 完全没有资格去碰的东西。"**

- 有些工程工作，researcher 不应该碰
- Infra 的 bug 和复杂性远超想象

## 十一、开源哲学

### 11.1 代码作为一种慈善

> "把代码工具视作一种慈善。"

**开源的意义**：
- 打破信息差
- 让更多人受益
- 减少重复劳动

### 11.2 开源 vs 发 Paper

> "发 Paper 完全没有意义。"

**观点**：
- Paper 是信息差的一部分
- 代码才是真正有用的贡献
- 开源代码比 Paper 更能帮助人

## 十二、对行业的观察

### 12.1 RL 的现状

- 大部分 RL 算法改的不是本质
- 环境设计比算法更重要

**DeepSeek vs OpenAI**：

- OpenAI：闭源路线，性能强

## 十三、关键观点总结

| 主题 | 观点 |
|------|------|
| **学习** | 学得慢，理解后用得快（建立 shortcut） |
