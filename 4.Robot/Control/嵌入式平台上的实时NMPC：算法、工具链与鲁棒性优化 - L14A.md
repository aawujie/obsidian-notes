# 3. 按照主题来梳理

## 3.1 实时顺序凸规划（Real-Time Sequential Convex Programming / Real-Time Iteration）

- 本小节详细解释实时顺序凸规划（SCP）/实时迭代（RTI）在 NMPC 中的核心思想、索引含义、计算拆分与实现细节，力求读者通过阅读即可充分理解该算法为何能在闭环控制中实现快速决策。
- 问题背景与形式化：在经典的非线性 MPC（NLP）里，我们求解一个随初始状态 s̄（si bar）参数化的非线性优化问题。优化变量通常是未来时域上的状态轨迹 S 和控制动作轨迹 A，合并称为 X。代价由轨迹成本 C（阶段成本）、终端成本 E 等组成，约束包括路径不等式 H（例如输入/状态约束）与终端约束，以及系统动力学等式约束 G(X, s̄) = 0。讲话者强调在很多应用里，代价 C、终端代价 E、约束 H、R 等在设计算法时往往是凸的（常见情形下 C、E 为二次，约束为线性），因此非凸性往往仅由动力学等式 G 的非线性引入。这一点使得基于线性化的顺序凸规划成为自然选择。
- SCP 的基本步骤（离线/单次问题视角）：
    1. 给定当前对轨迹的猜测 X^j（j 为优化器内部迭代索引），在该点线性化非线性动力学 G，得到线性化后关于 X 的子问题（在讲话里通常为凸问题，若原代价/约束已为凸则无需更改）。
    2. 求解该凸子问题，得到新的迭代 X^{j+1}。
    3. 重复上述线性化—求解过程直至收敛（在离线或单次问题求解里可能需要多次迭代以满足收敛准则）。
讲话者采用“fully simultaneous approach”（完全同时化/同时求解）进行线性化，即沿整段轨迹同时线性化系统动力学，而不将轨迹分段为前向模拟与逐步线性化的分离方式，这样可得到一种一致的线性化约束集合。该线性化产生的约束对 X 的表达非常简单且依赖于线性化点 X^j。
- 三个索引的含义（时序与算法层次）：
    - i：最高层索引，对应物理系统运行时刻或每次需要求解的参数化问题，通常伴随实际测量到来的初始状态 s̄_i（也可称为采样周期索引）。
    - j：优化内部迭代索引，表示在固定问题（即固定 s̄_i）下 SCP 的迭代次数（线性化点不断更新并求解凸子问题）。
    - k：轨迹时间步索引，表示优化变量向量中带有的时间维度（例如未来 N 步的每一步状态/控制）。在讲话中约定轨迹内部变量从 0 开始编号以便优化处理。
将这三类索引分清，可以避免混淆：i 对应真实世界/采样，j 对应求解器迭代，k 对应单个优化问题中的时间序列维度。
- 实时迭代（Real-Time Iteration，RTI）的动机与实现思想：
传统 SCP 需要为每个到达的初始状态 s̄_i 在内部做多次迭代（多个 j）以收敛，这在实时控制中往往耗时太长，且在求解过程中实际系统会继续演化，导致求解的结果在应用时已经过时。实时迭代做出的策略性妥协是：对于每个采样时刻只做一次线性化+求解（即仅做一次凸子问题求解并立即应用得到的首个控制量），将“解精确性”让渡为“响应时延”的缩短。具体流程如下：
    1. 持有一条“上一次优化得到的轨迹猜测”（可以直接使用上一轮最优结果的右移/shift 版本，或者进行 advanced step 等小修改）。
    2. 在线性化点处（即上述轨迹猜测）预备好凸子问题的全部结构：计算雅可比、哈希等需要的矩阵，并在可能的情况下做预处理（condensing、构建 QP 数据结构等）。
    3. 在收到最新的状态测量 s̄_i（该值进入等式约束 G 的参数中）时，将该 s̄_i 输入到已经预处理的 QP 数据结构中，迅速解该 QP（通常 QP 可以几毫秒甚至微秒级求解，取决于问题规模与实现）。
    4. 取该 QP 的解的第一步控制作为反馈输出并实际施加于被控系统，同时用该解更新轨迹猜测以备下一采样周期继续使用。
这样做的两个核心要点：一是“每采样期只做一次迭代”，二是“把计算分成与 s̄ 无关的预处理（可以在采样间隔的空闲时间完成）和与 s̄ 相关的快速求解（在测得 s̄ 后尽快完成）”。RTI 的好处是显而易见的：可以显著减小从测量到施加控制间的延时，使得闭环反应更快；代价是每步求解并未求得精确的最优解——这是设计上的折衷。
- 关于线性代数与 QP 求解的工艺细节（与 RTI 的匹配）：
讲话者指出，SCP/RTI 在每次迭代都要进行线性化与准备一个凸子问题（常常是 QP，如果代价为二次且约束线性化后为线性不等式），而这些步骤本质上依赖于高效的线性代数运算（矩阵乘法、因子分解、稀疏/结构化线性系统求解）。因此要在嵌入式平台实现 RTI，需要优化这些线性代数步骤（见后面的 BLASFHO 部分）。另外，在实践中还会使用技巧如 condensing（将带有时序结构的 QP 转化为密集 QP）或部分 condensing（折衷密度与结构化）以选择适合的 QP 求解器（稠密 QP 更适合某些 active-set 风格求解器，而利用 OCP 结构的 HPIPM 更适合结构化内点方法）。
- 实际工程中需要注意的实现细节与可选策略（讲话中提到的但未详细展开的变体）：
    - Trajectory shift（轨迹平移）：通常将上一轮的最优轨迹右移一格作为下一轮线性化的初始猜测，这一步非常常见且能提供较好的初值。
    - Advanced step RTI：在下一个采样时刻到来前，提前使用预测的初始状态做部分预处理，以进一步缩短在线求解时间。
    - 预处理/condensing：可以在不知道当前 s̄ 的情况下进行大量运算，以便在获取 s̄ 后仅需完成很少的在线更新步骤。
    - 注意系统模拟与线性化的开销：对长时域或高维系统，整个轨迹的模拟与雅可比计算本身可能成为瓶颈，因此需要高效的微分与模拟器实现（这也是后面提到的 ACADOS 的设计目标之一）。
- 总结（为何采用 RTI）：RTI 在工程实践中替代“完全求解每个 NMPC 问题”这一理想化做法的原因是现实的时延与计算资源限制。通过牺牲每步求解到严格最优的程度，改为“在每个采样周期做一次线性化并快速求解子问题”，可以显著降低从测量到控制的延时，并且在常见的控制任务中，其所得控制律通常足够好以保持系统性能与鲁棒性（当然这需要对算法收敛性与稳定性进行理论/实验验证，在视频中对此是以工程层面的动机和实现细节为主）。

## 3.2 嵌入式优化的线性代数与求解器基础：BLASFHO（blaspho）与 ACADOS（aados）

- 本小节详尽介绍 blaspho（作者称 BLASPHO 或 Blasphere）作为面向嵌入式优化的线性代数库的设计理念、实现权衡与特性；以及 ACADOS（讲话中写作 aados）作为基于 blaspho 的实时迭代实现和更高层优化工具链的结构、接口与运行方式。
- BLASFHO（blaspho）的定位与设计动机：
    1. 目标场景是嵌入式优化（尤其 MPC），这里的矩阵维度通常是中等大小（例如每块 10×10 或 100×100 的密集块），且矩阵结构稳定已知（固定维度与重复结构）。
    2. 传统的高性能线性代数库（如常规 BLAS）通常在运行时会对输入矩阵进行复制与重排以适配处理器的内存访问模式，从而达到更好的向量化/缓存利用率。但这种复制（reformatting）本身成本为 O(n^2) 的数据搬运，在中等维度的情形下并非可以忽略，尤其在嵌入式环境中复制开销可能相当可观。
    3. Blaspho 采取的做法是采用一种固定的“panel-major”存储格式（讲话中提到 pen and major，可能指 panel-major），并在整个执行过程中保持该内存布局，从而避免在每次调用时进行重复的复制/重排操作。这一设计在中小矩阵场景下可以带来高达十倍左右的性能获益（讲话中提到“快十倍”这一经验性结论）。
    4. 为了达到高性能，还采用了针对不同 CPU 架构的手工优化汇编/C 内核（hand-tailored assembly kernels），并充分利用向量化（SIMD）等硬件特性。核心构建者之一是 Chanduka Frizopostto（讲话中提到的首要作者/发明人），该项目用 BSD-2 许可开源发布，便于学术/工业界使用与扩展。
- Blaspho 的具体特性与权衡：
    - 固化内存格式：与传统 BLAS 抽象不同，blaspho 在用户接口层面暴露矩阵的固定格式，使得上层使用者（例如求解器）可以根据该格式直接进行数据填充与传递，避免了中间复制。
    - 支持多种 CPU：通过定制内核，既支持高端也支持低端 CPU，并在可能时兼容传统 BLAS API（尽力在一些场景下可以替代标准 BLAS 的复制步骤）。
    - 面向 MPC 的稠密块结构：blaspho 针对常见的带有许多小到中等密集块的矩阵结构进行了优化，这与 MPC 中出现的大型稀疏带状结构但内部有多个 dense block 的情形相匹配。
    - 开源与工业资助的可持续发展：讲话者提到该项目既来自科研兴趣也接受工业资助，因此在保持开源（BSD2）的同时，能够按需为特定硬件/行业场景开发额外内核。
- ACADOS（aados）的定位、架构与设计原则：
    1. ACADOS 是 Aados 的继承/后续项目（讲话中称 Aados 是 AO toolkit 的后继），目标是提供一套面向 NMPC 的高性能求解器套装，能够生成问题特定的 C 代码并在嵌入式系统上高效运行。
    2. 与早期通过大量代码生成获得性能的方式不同，ACADOS 的策略是：不通过对全部线性代数做代码生成，而是调用高效的底层库（即 blaspho）来完成线性代数部分，从而在保持性能的同时降低生成代码的复杂性与维护成本。此外，底层 QP 求解器（如 HPIPM）也被集成进来以处理结构化 QP。
    3. 在模型与函数这一层面，ACADOS 仍然使用代码生成工具（讲话中提到 CasADi，写作 Kazadi 但应为 CasADi）来将模型方程与其导数生成成高效的 C 函数。特别地，ACADOS 默认让 CasADi 生成连续时间模型（f、f_c）的代码，然后由 ACADOS 在内部完成离散化、灵敏度传播（sensitivity propagation）等操作。
    4. 高层接口支持 Python/Matlab/Octave，使模型在方便的交互式环境中表达并生成特定的 C 接口与 S-函数（用于 Simulink），从而既保持开发效率又生成可嵌入运行的代码。
    5. ACADOS 中整合了多种求解器策略：针对 QP 的有主动集方法（active-set）、内点方法（interior-point，例如 HPIPM）与一阶方法等；在很多实际应用中，会针对问题规模与稀疏结构选择合适的 QP 类型与 condensing（完全或部分）策略。
- HPIPM（High-Performance Interior Point Method）与 condensing 的角色：
    - HPIPM 是讲话中提到的一个高性能 QP 求解器，被设计为利用 OCP（optimal control problem）结构来提高效率；其既可以以面向结构的稀疏方式求解 OCP-QP，也可以在做了 condensing（把时间维度展开成一个稠密 QP）后作为稠密 QP 求解器使用。
    - Condensing 是一种把带有时序稀疏结构的 QP 转换为稠密 QP 的过程，代价是增大问题的密度但减小决策变量的维数，使得某些类型的求解器（如密集主动集方法）更有效。讲话中还提到“部分 condensing”是一种折衷，其在最近几年被广泛采用以兼顾求解效率与线性代数的稳定性。
- 积分器（integrators）与灵敏度传播：
    - 在 NMPC 中，除了优化器核心之外，对连续系统的数值积分与对积分结果的灵敏度（导数）计算是关键环节。ACADOS 内置对 ODE 和 DAE（微分代数方程）的集成器，支持显式与隐式 Runge-Kutta 方法（例如 Gauss-Legendre/implicit collocation），并能以结构化方式高效计算灵敏度传播。
    - 讲话中特别提到一种“generalized nonlinear static feedback” 的结构化积分方法，该方法适用于系统可以分解为“输入的线性子系统 → 非线性核心 → 输出的线性子系统”的形态，通过在数值积分器层面明确区分并利用该线性部分来预计算大量线性代数，从而把每次 Newton 迭代中需要的非线性运算最小化。这种做法在模型具有该类结构时可以显著降低在线计算量。
- 软件工程与接口设计的重要实践：
    - ACADOS 通过将高层问题描述（Python/Matlab）与低层高效 C 库（blaspho、HPIPM）分离，既保留了用户友好的建模接口，也保证了嵌入式部署时的性能与可移植性。
    - 对于实时控制场景，性能优化不仅仅是算法层面的（选择 RTI、condensing），还包括工程实现层面的预计算、内存布局、手工优化内核与针对不同 CPU 的适配。
- 总结（工具链的协同）：在讲话者的工程路线里，RTI 的快速在线迭代策略需要高效的线性代数支持与专用求解器，BLASFHO 提供了面向中小矩阵与固定结构的高性能内核，ACADOS 则将这些内核与模型代码生成、Q P 求解器（如 HPIPM）和数值积分器结合起来，形成一个用于嵌入式 NMPC 的完整工具链。这一组合在实践中据称能在嵌入式平台上实现优良的计算性能（讲话中强调相较于通用库有数量级的提升），并通过开源许可促进社区/工业的采用。

## 3.3 闭环鲁棒化 MPC 的挑战与近期算法思路（基于 Julian Messer 的博士工作）

- 本小节围绕鲁棒 MPC（Robust MPC）在从确定性 NMPC 推广到含不确定性时带来的规模爆炸问题、“管束（tube）”方法的引入动机、以及讲话者要介绍的近期一个快速闭环鲁棒化算法的基本思路进行详尽说明，力求在不引入额外事实的前提下，完整呈现视频中传达的思路与要点。
- 鲁棒性带来的问题与动机：
    - NMPC 在本质上通常被视为确定性参数化的最优控制问题：给定当前初始状态 s̄，求解一个有限时域的优化问题并应用该问题解的首个控制动作作为反馈。当模型与真实系统一致（无扰动/无模型误差）时，这个做法行为良好——系统沿着求解得到的单一轨迹演化，优化问题的解就是该轨迹。
    - 一旦加入不确定性（随机扰动、模型参数不确定、测量噪声等），问题复杂性急剧上升：在最严谨的鲁棒或随机 MPC 框架中，优化变量往往变成一个策略（policy）而非单条轨迹，或者需要在优化中显式考虑多种未来扰动情形，这会导致问题维度在时间上与场景上爆炸（exponential/large growth），变得难以实时求解。
    - 为了限制复杂度并仍然获得某种形式的鲁棒性，工程上常用“tube”（管束）方法：基本想法是围绕 nominal trajectory（名义轨迹，即确定性预测轨迹）构建一个不确定性集合（tube，通常由线性化或区间包络得到），并在优化中考虑使该管束在约束内保持或以某种方式稳定。该方法将广义的策略搜索问题降为对名义轨迹的优化加上一种基于线性化/约束收缩的鲁棒性保证，从而控制了问题规模的增长，但问题仍然比纯确定性情形更大、更复杂。
- 近期算法的方向与要点（讲话者提到基于 Julian Messer 的博士工作）：
    - 讲话者指出他们将展示一种有趣的、近期被接受（讲话时提到“昨天在 CDC 刚被接收”）的算法，该算法属于闭环鲁棒化 MPC 的范畴。虽然视频未对算法给出完整数学细节，但从讲话脉络可以提取若干关键动机与方法学要点：
        1. 保持 RTI/顺序凸化的实时性思路：即尽可能将鲁棒控制问题的在线部分保持在“单次凸子问题求解”或类似的轻量级算子上，以便适应嵌入式/实时场景。
        2. 采用某种基于 tube 的近似或结构化方法，将鲁棒性要求转换为对轨迹的附加约束或对轨迹周围不确定性半径的约束，使得问题在维度上仍可控（但“仍然很大”——讲话强调 tube 仍会让问题变大，只是比直接考虑所有不确定情形要容易一些）。
        3. 用线性化来近似系统在不确定性上下界附近的行为，从而可以利用之前讨论的 SCP/RTI 流程（因为线性化后问题更接近凸问题）。
        4. 在实现细节上，结合前两部分的软件基础（blaspho、ACADOS、HPIPM）以获得可运行的实时闭环鲁棒控制器。
    - 讲话中特别强调：当处理随机或鲁棒系统时，问题“会迅速变得很大”，因此必须在建模与近似层面做设计选择（例如 tubebased approximations）以避免不可控的规模膨胀。讲话提出的近期算法以实现“闭环鲁棒化”的快速性为目标，显然着眼于将理论上更复杂的鲁棒控制问题转化为可由 RTI 风格方法实时解决的形式。
- 实务层面的考虑与潜在限制（讲话中提到但未完整展开）：
    - Tube 方法的效果依赖于线性化/区间近似的质量：若系统强非线性或不确定性大，线性化管束可能过于保守或失效，从而影响控制性能或导致频繁不可行问题。
    - 算法需要配套的数值工具以便在每一步高效计算关于管束的传播（例如线性系统在不确定性集上的扩展），这又回到线性代数与敏感性传播的效率问题。
    - 讲话中提到该算法基于 Julian Messer 的博士工作，而他们提出的方案是“一个有趣的算法”，并没有在视频中给出严格的稳定性或鲁棒性证明的细节；因此在推广到新的系统或应用场景时，需要做更多理论分析与大量实验验证来量化其表现。
- 总结（对读者的可操作建议）：从视频传达的信息看，如果你的目标是在带有中小规模模型的嵌入式系统上同时实现实时 NMPC 与一定程度的鲁棒性，合适的工程路线是：
    1. 在建模上尽可能保留代价与约束的凸性（便于利用 SCP/RTI 的凸子问题），把非凸性尽量限制在动力学部分；
    2. 采用 tube 或类似的近似策略将不确定性封装为轨迹周围的约束，避免在控制器中直接求解高维的随机最优控制问题；
    3. 使用 RTI 风格的一步线性化并在采样周期外做尽可能多的预处理（condensing、矩阵构建），在测得最新状态后只做尽可能少的在线计算；
    4. 借助像 blaspho、ACADOS 与 HPIPM 这样的工具链来保证线性代数与 QP 求解的效率。

# 4. 框架 & 心智模型（Framework & Mindset）

- 框架一：实时优化的“分工与最小在线工作量”框架（Real-Time Work-Splitting Framework）
    - 框架概述：该心智模型提倡将整个优化过程根据“是否依赖当前测得的初始状态 s̄”划分为两类工作：可在采样周期间隙或事先完成的“与 s̄ 无关”的离线/预处理工作（包括对当前轨迹猜测的线性化点的雅可比计算、QP 的数据结构构造、condensing 的预处理等），以及必须在获得最新 s̄ 后完成的“在线”工作（将 s̄ 注入到子问题并求解一次 QP，返回动作）。目标是极小化在线阶段的计算量，从而缩短从测量到控制的延时。
    - 详细阐述与步骤：
        1. 轨迹猜测准备：持有上一轮求解得到的轨迹（或其右移/shift 版本）作为下一轮的线性化点；若可能，使用 advanced-step 技术在下次测量到来之前对轨迹做前瞻式更新。
        2. 预处理（与 s̄ 无关）：在采样到来之前，基于轨迹猜测线性化动力学、构造子问题的稀疏矩阵模板并（若选）执行 condensing 或部分 condensing，将尽可能多的线性代数运算排到此阶段以减少在线计算。
        3. 在线注入测量：在测得最新的初始状态 s̄_i 后，仅将它注入已经准备好的子问题结构，更新相关约束右端项或初值条件（这些更新通常是向量/少量矩阵的替换）。
        4. 快速求解与施用：调用高性能 QP 求解器（如 HPIPM）以尽可能快地求解一次子问题，立即取解的首个控制作为输出并施加于系统；随后，用该解更新轨迹猜测继续下一周期。
        5. 持续迭代：不断重复上述步骤，在每个采样周期只做一次内循环迭代，从而确保反馈延迟最小化。
    - 适用场景与权衡：该框架适合需要严格实时响应的嵌入式控制场景，代价是在收敛精度与最优性上做折衷（每步仅一迭代）。其成功依赖于预处理能够大量削减在线计算，且系统动力学在连续采样间不会发生剧烈变化（否则单步线性化精度可能不足）。
- 框架二：嵌入式优化工具链的“结构化利用与特化实现”心智模型
    - 框架概述：在嵌入式优化中，最大化性能的核心不仅在于选择正确的高层算法（如 RTI、SCP），更在于从底层到上层系统地利用问题的结构并在实现层面进行特化（包括内存布局、手工优化内核、针对性 condensing、模型代码生成等）。这是将理论算法变为实用、可部署系统的关键心智模式。
    - 详细阐述与步骤：
        1. 识别结构：在模型与优化问题中识别可利用的结构（例如代价/约束的凸性、时间序列的 OCP 结构、局部稠密块分布、线性子系统-非线性核心的分解等）。
        2. 在数据布局上特化：选择一种在目标硬件上能最大限度减小复制/缓存开销的矩阵存储格式（如 blaspho 的 panel-major），并保证上层代码直接以该格式填充数据以避免重复转换。
        3. 利用专用内核：为关键线性代数操作（小到中矩阵乘法、分解）采用手工调优的汇编或 C 内核，以获得比通用库更好的性能。
        4. 选用合适求解器并做折衷：根据问题是否稠密或能否 condense、是否有大量不等式约束等因素，在主动集、内点或一阶方法之间做选择，或采用 HPIPM 这样的结构化内点方法，必要时使用部分 condensing。
        5. 代码生成与数值核分离：对非线性模型与其导数采用代码生成（例如 CasADi）以获得高效的函数实现，但对线性代数与求解器调用则依赖于高度优化的库（blaspho、HPIPM）以保持灵活性与可维护性。
        6. 工程可移植性与开源策略：保持底层库开源（例如 BSD2），以便对不同 CPU/平台做定制，并允许工业资助以扩展至特定硬件，同时保持社区可用性。
    - 适用场景与权衡：该心智模型在嵌入式实时控制领域尤为适用。其代价是需要跨学科的工程能力（数值线性代数、低层优化、生成代码、嵌入式系统适配），但回报是能把看似不可实时的高级控制算法变为可部署的产品级控制器。
- 框架三：鲁棒控制的“近似—收敛—实现”思路（针对含不确定性的 MPC）
    - 框架概述：在面对不确定性时，直接解决完整鲁棒或随机最优控制问题通常不可行。可行的心智模式是：先通过可控的近似（如 tube）把原问题转化为规模可管理的形式；然后在该近似框架下采用结构化/实时优化方法（如 RTI + 线性化）求解；最后在实现上利用高效线性代数与求解器来保证实时闭环实施。该思路的关键在于平衡保守性（approximation conservative）与实现性（computational feasibility）。
    - 详细阐述与步骤：
        1. 近似设计：依据系统特性设计合适的不确定性近似（例如线性化得到置信区间、构建状态/输入 tube），使问题在表达上仍为带附加约束的优化问题。
        2. 结构化求解：把近似后的鲁棒问题写成可被顺序凸化/线性化的方法处理的形式，为 RTI 留出空间，尽可能将非线性/非凸部分限制在动力学层面。
        3. 实时策略：在每个采样周期仅做一次线性化与子问题求解（RTI），并在事先完成与不确定性传播相关的可预处理工作（例如对某些线性传播算子做离线 factorization）。
        4. 性能验证与保守性评估：通过仿真/实验评估所选近似在各种扰动场景下的表现，量化保守性与鲁棒性能，必要时调整 tube 大小或线性化策略以获得更好平衡。
    - 适用场景与权衡：此心智模型适用于不确定性不可忽略但对实时性有严格要求的场合。其核心代价是近似带来的保守性与可能的次优性，需要通过系统化的仿真与实测评估来校准。

# 总结

本视频从算法思想（实时顺序凸规划/RTI）出发，结合面向嵌入式优化的线性代数实现（BLASFHO/blaspho）与求解器/工具链（ACADOS/aados、HPIPM）给出了一条工程化路径：在保证实时性的前提下，通过每次采样仅做一次线性化并解一个凸子问题、把计算分为可离线预处理与必须在线完成的最小部分、以及使用专门化的高性能线性代数内核和结构化 QP 求解器，可以在嵌入式平台上实现高效的 NMPC。对于含不确定性的鲁棒 MPC，讲话提出使用 tube 等近似策略并将其与 RTI 思路结合，进而提出并实现了一类近期的闭环鲁棒化快速算法（基于 Julian Messer 的工作）。整体心智模型强调“结构化利用、分工以减小在线负担、以及实用近似以控制复杂度”。
