# 3. 按照主题来梳理

## 3.1 为什么要把 RL 和 MPC 结合

- 动机与问题陈述：在控制领域，用模型去计算基于模型的控制器（如 MPC）是常态。MPC 通过某个动力学模型 fθ 和阶段代价 L（或 RL 社区称作 reward）在有限或截断时域上求解最优动作序列，取首个动作作为闭环控制动作。常见实践是基于数据不断更新模型参数 θ，再把新模型放回 MPC 中运行，从而期望获得更好的闭环性能。然而，这个基于“把模型做得更好就会得到更好控制”的想法并非总是成立：在实际系统中，模型往往不能完美描述系统（系统可能存在随机性、隐藏状态难以观测、复杂无法精确建模等），有些情况下基于不完美数据继续在线自适应反而会降性能（这在实时优化和自适应控制领域早有发现）。因此，若一味复杂化模型来逼近真实系统，MPC 的复杂度和运行成本会显著提升，有时代价远超性能增益。
- 思路转变：与其无限制提升模型保真度（导致 MPC 极其复杂、计算代价高），更务实的目标是，在固定 MPC 结构和可接受复杂度（即已做出建模与资源的选择）下，尽可能挖掘出该 MPC 结构能达到的最佳闭环性能。也就是说，把目标从“把模型做得尽量精确”转换为“在所采用的模型结构/控制架构下，最大化闭环性能”。把 RL 与 MPC 结合，提供了自然的框架去直接优化闭环性能：保留 MPC 的结构化、约束处理和初始化优势，同时用 RL 的数据驱动优化去调整 MPC 的参数（不只是模型参数，还可调整代价、终端代价与约束松弛等），以期在真实系统的闭环行为上获得提升。
- 与纯 ML/NN 策略对比：纯粹用深度神经网络表示策略或价值函数在很多 RL 工作中广泛使用，但存在结构选择（architecture）、初始化（通常随机）与显式满足约束（物理/安全约束难以直接编码）等问题；同时许多网络设计带有“黑箱/巫术”成分，工程师不容易解释或保证性能。相比之下，MPC 提供了明确的结构、物理约束的显式编码路径、以及合理的初始化（基于已有模型与代价）。因此，MPC 可被视为“有结构的策略/价值近似器”，在 RL 中作为带约束、可解释且更容易保证安全性的策略表示方式具有明显吸引力。
- 总结：结合 RL 与 MPC 的核心优势在于，把 MPC 作为策略与价值函数的结构化近似器，利用 RL 的学习能力在闭环层面直接改进性能；这既避免盲目追求不可行的高保真模型，也利用 MPC 在约束与初始化上的工程优点，从而在资源受限场景下更高效地提升控制效果。

## 3.2 基本记号、MDP 与 MPC 的对应关系

- MDP 表示法与目标：使用强化学习惯用记号，状态 S、动作/输入 A、转移概率密度 p(s' | s, a)（在连续空间用概率密度表述）。阶段代价 L(s, a)（RL 中有时写作 reward r，但本讲中以 cost L 表示）。目标是最小化折扣累积代价 J(π) = E[Σ_{k=0}∞ γ^k L(s_k, a_k)]，对策略 π（可能是确定性或随机策略）进行优化。若系统随机性存在，则在期望下定义上述成本与价值函数，需明确初始状态的取法（固定或随机）。
- 价值函数、动作价值函数与优势函数：介绍 Vπ(s)（从状态 s 开始在策略 π 下的期望折扣代价），Qπ(s,a)（从状态 s 先采取 a, 之后跟随 π 的期望折扣代价），以及 advantage Aπ(s,a) = Qπ(s,a) - Vπ(s)。最优对象记为 V*(s), Q*(s,a), π* 表示最优策略，且有 V*(s) = E_{a~π*}[Q*(s,a)]（若 π* 是确定性，则取最小化 a 对应的 Q*），以及 π*(s) = argmin_a Q*(s,a)（对于代价最小化形式）。
- MPC 的形式化与作为策略的视角：在 MPC 中，我们有一个（通常）近似模型 fθ(·)，一个有限时域的最优控制规划问题（含阶段代价L及可能的终端代价 V_f），求得未来状态/动作序列并采用首个动作。因此每次求解 MPC 实际上隐式定义了一个策略 π_MPC(s) = first_action( argmin_{sequence} Σ L(...) + terminal_cost, subject to dynamics/constraints ), 即 MPC 可以被看作一个从当前状态映射到动作的策略函数。相应地，从 MPC 的最优规划结果也可以定义类似于值函数（即该优化问题的最优总费用）与动作价值函数（把首动作固定为 a 后的总费用）。
- MDP 与 MPC 的一体化情形（理想化假设下的等价）：如果把 MPC 的预测时域延展到无穷，且 MPC 所用模型与 MDP 的真实动力学一致且为确定性，同时在 MPC 中使用与 MDP 相同的折扣 γ，则 MPC 输出的策略可与 MDP 的最优策略相匹配。这是一个理论上清晰的联接点，但现实中这类强假设（无限时域、完美模型、确定性）通常不成立，因此 MPC 通常仅能近似 π*。若把随机性也显式嵌入 MPC（stochastic MPC），可以缓解确定性假设，但计算量大。
- 通过 MPC 建立的值/动作价值函数满足 RL 中的关系：从 MPC 解得的值函数 V_MPC 和动作价值函数 Q_MPC 也满足 V_MPC(s) = E_a[Q_MPC(s,a)]（均值或最小化关系，取决于策略形式），且 π_MPC(s) = argmin_a Q_MPC(s,a)。这说明 MPC 内部的优化与 MDP 中的 Bellman 关系在形式上是一致的，从而为将 RL 算法直接作用于 MPC 提供理论基础。

## 3.3 折扣因子 γ 的含义与不同代价形式（折扣、平均、偏差）

- 折扣 γ 基本解读：折扣因子 γ∈(0,1) 在 MDP/强化学习问题中常用来确保无限期累加和的收敛性并体现对未来回报的重要性衰减。视频对折扣的两种工程意义进行了讲解：一是把 γ 理解为系统的“寿命”模型——以概率 1−γ 在每一时间步发生不可逆失效（death）的情形，则较远的未来可能不会实现，因此权重大致按 γ 衰减；二是把 γ 理解为财务时间价值模型——未来收益按折现率 r 减少，γ 与 r 的关系体现未来价值的折现。一些工程系统（如采样 1 秒、寿命几十年、年折现率或失效概率很低）会导致 γ 非常接近 1，这是工程问题中的常态。
- 折扣、平均回报（gain optimal）与 bias-optimal：在控制文献中还有另一种常见表述，即平均代价随时间均值化后取极限（gain optimal），该形式强调长期稳态性能且忽略瞬态（transient）表现，往往会鼓励“尽快到稳态”的策略，这可能导致策略在 transient 上的行为不理想且最优策略未必唯一。相比之下，bias-optimal（偏差最优）方法通过从代价中减去适当常数（例如长期平均代价）来明确刻画 transient 性能，得到更符合工程直觉的最优策略。视频指出，在工程控制场景下，bias-optimal 可能比纯粹的 gain-optimal 更合适，且存在一些强化学习算法可处理这类目标。
- 工程启示：由于工程系统常见的高 γ（接近 1），折扣的选择应结合系统寿命、采样率以及经济折现等考量。理论上各种形式（折扣、平均、bias）之间可以相互转换或有对应理论，但在实际 RL+MPC 应用中应根据想要强调的性能（瞬态 vs 长期、稳态）选择合适的目标函数与折扣设定，并注意不同设定在学习算法与稳定性分析上的差异。

## 3.4 中心理论结果：用修改后的 MPC 代价/约束恢复最优策略（核心定理与含义）

- 结论陈述（非严格证明）：在一定技术假设下（例如模型在 π* 下的行为使得代价不会以超指数速度膨胀等数学条件，保证后续分析可行），存在一种对 MPC 的阶段代价与终端代价（以及由此隐含的约束）做出修改的方式，使得用该修改后的 MPC 所定义的策略、值函数与动作值函数能够精确地匹配 MDP 的全局最优策略 π*、V* 与 Q*。这里的“修改”意味着不仅修改模型参数，也可修改代价函数 L̃ 与终端代价 Ṽ（必要时可把硬约束吸收到代价中，即用罚项表征不可行区域）。
- 主要含义与直觉解释：直观地，这个定理说明 MPC 本身（作为一个带结构的在线优化映射）有足够的表示能力，在代价/约束适当设计下可以产生与全局最优策略相同的闭环行为。即便 MPC 使用的是不完全准确的模型，只要你对 MPC 的目标代价和约束进行恰当“欺骗性”调整（修改代价/约束），MPC 的输出可以被引导到等价于全局最优的行为轨迹。换句话说，通过改变 MPC “让它相信”某些代价/约束，MPC 在其内部优化过程中将产生希望的动作选择，从而补偿模型的不准确性。
- 限制条件与可行性：该结果并非没有条件。理论证明需要对问题、模型及代价的生长性、有界性、折扣 γ 等做出适当假设（例如在最优策略下阶段代价不能增长得比 γ^{-k} 更快等），以保证 Bellman 型方程和相关算子收敛及代数操作合法。因此并不是任意模型都能通过简单修改代价完美复原最优策略。再者，虽然存在 L̃、Ṽ 使得 MPC 与 π* 一致，但这些函数通常是通过求解 Bellman 方程等“动态规划”手段得到的，在高维或复杂系统中直接计算是不现实的。
- 对学习的启示（为何 RL 有价值）：尽管直接解析求得这些修正代价不可行，但在学习情境下可以用数据来逼近或学习 L̃ 与 Ṽ（或其参数化形式）。也就是说，在实践中用 RL 在闭环数据上学习合适的代价/终端项（或直接学习 MPC 中的参数 θ）是可行路线。该理论为这种做法提供了形式上的正当性，说明若学习到合适的修改，MPC 可实现接近或等价于全局最优的策略。
- 概括：这个中心结果给出一个强而有力的观点：MPC 不是“天生受限无法逼近最优”，而是可以通过修改代价与约束被调谐为与 MDP 最优行为一致；在实践中，这一调整通过数据驱动的 RL 来完成，从而把 MPC 的工程结构优势与 RL 的学习能力结合起来。

## 3.5 实践细节：把 RL 应用于 MPC（参数化、梯度、可微性与敏感性）

- 参数化思路：在实践中要把 RL 应用于 MPC，一般把 MPC 的所有可调部分参数化为 θ（包括模型参数、阶段代价的权重、终端代价、某些约束松弛或约束参数等）。优化目标是最小化闭环成本 J(θ)（期望折扣累计代价）在真实系统或仿真系统下的表现。重要区别是：这里不一定是拟合模型到数据，而是直接调整参数以提升闭环性能——模型可能被“调糟”以换取更好的闭环性能（即模型在 MPC 中的作用是工具而非目标）。
- 需要的计算量与可微性：若要使用梯度型或基于敏感性的 RL 方法（如策略梯度、基于值的梯度法），需要对 MPC 的输出（动作与 MPC 的值/动作价值函数）关于参数 θ 的导数。MPC 是通过求解非线性规划（NLP）得到解的，因此需对 NLP 解关于参数的变化做灵敏度分析。实践上这可通过对 Karush-Kuhn-Tucker (KKT) 条件做隐函数定理求导来实现：对 KKT 条件关于参数微分并解线性方程组可获得解对参数的导数；对 MPC 的值函数导数可直接由拉格朗日函数的导数评估得出。
- 关于不可微点与活跃集变换的担忧：NLP 解在活跃集发生变化时可能不可微（非光滑），这在理论上可能带来问题。但讲者指出，在期望（在随机 MDP 下）意义上，这些不可微集合通常是测度为零的“几乎处处可微”，即在期望运算下这类不连续性会“被平均掉”。因此在多数实际情况下通过对 KKT 条件做导数计算并应用在期望/样本上是可行的，且工程上已有自动微分工具与灵敏度代码能实现这些求导操作。
- 无导数的替代方法与限制：还有无导数或黑盒优化方法（如基于代理的优化、进化策略、贝叶斯优化等）可以直接优化闭环代价 J(θ) 而不求导数，但它们在高维参数空间上效率低下，数据需求通常非常大，因此在 MPC 参数维度不是很小时并不总适用。常见方法为结合有导数的策略（对 MPC 求解器做可微化处理）与无导数方法在低维参数上做粗调。
- 实践建议：1) 优先使用结构化参数化（明确哪些 MPC 组件可调）并用已有模型/成本初始化 θ，避免从随机初始化开始；2) 若采用梯度法，确保 MPC 求解器能提供 KKT 灵敏度或使用支持可微编程的求解器/自动微分工具；3) 在设计学习过程时要注意安全（把硬约束或高罚项放入 MPC 形成封闭安全集），并在真实系统上慎重进行在线学习，先在仿真/高保真模型上训练与验证。

## 3.6 数据流、双模型策略与工程流程

- 数据难题：真实系统上的数据昂贵且采样慢（尤其工程系统），单靠在线 RL 从真实系统直接学习往往需要太多时间与风险。常见 RL 做法是先构建高保真仿真环境（用数据训练的黑箱高保真模型或仿真平台），在其上进行大量离线或在线训练，然后把学得的策略迁移到真实系统上（例如自动驾驶仿真训练）。这种方法在 RL 社区很常见。
- 双模型建议（来自讲者的实践思路）：在 MPC+RL 的情境里，建议同时维护两类模型（或两套模型用途分离）：一是供 MPC 在线使用的“简化模型”（MPC model），必须足够简单、光滑、可在优化器中高效求解，承载实时决策与约束；二是用于数据生成、离线学习和策略优化的“高保真模型”（simulator），可用复杂、非光滑、几乎任意的工具构建（甚至昂贵的物理仿真），因为它仅在线下或离线使用，不用于实时优化。这样在高保真模型上进行大量策略迭代、估计必要的代价修正或学习潜在的 L̃，再把学到的参数或策略迁移并在简化 MPC 模型上验证与部署。两模型划分的优点是：保留 MPC 在线可解性，同时能利用高保真模型进行数据高效的 RL 学习。
- 工程步骤示例（流程化描述）：
    1. 根据物理理解与可在线计算资源建立初始 MPC 简化模型与代价（参数 θ 初始化）。明确约束并用罚项或硬约束表达安全限制。
    2. 用历史数据或试验数据构建高保真仿真器（用于大规模数据产生与策略评估）。
    3. 在高保真仿真器上用 RL 算法（策略梯度、Q-learning、基于模型的方法等）学习或拟合需要的代价修正/参数调整策略，获得候选 θ。
    4. 把候选 θ 部署到简化 MPC 上进行小规模或受保护的在线试验，监控闭环性能与安全性，必要时回退或进一步调整。
    5. 循环迭代：将在线试验数据补充回高保真仿真器以细化学习，或直接在真实数据上做小步更新（以保证安全）。
- 小结：数据流设计应权衡样本效率、计算可行性与安全性。双模型策略提供了兼顾这三者的可行路线，并与前述理论结果（通过学习代价/约束可以恢复/接近最优）相契合。

# 4. 框架 & 心智模型（Framework & Mindset）

- 框架一：MPC 作为“结构化策略与价值近似器”的心智模型（详细展开）
    - 问题观：把控制问题视为在受约束、物理知识和实时性要求下的策略学习问题。传统 RL 往往用通用函数逼近器（如深度神经网络）来表示策略/价值函数，但这忽视了工程问题中普遍存在的约束、已知动力学结构与对初始化可靠性的需求。
    - MPC-as-approximation：将 MPC 看成一个参数化函数族 π_θ(s)，该族由模型、代价、终端项与约束参数化。MPC 本身隐含了物理模型与约束并在在线优化中保证约束满足（或通过高罚项形式近似），因此它是一个具有强先验结构的策略类，比无结构的网络更能保证合规性与解释性。
    - 学习目标：不是单纯追求模型的拟合精度，而是直接优化闭环 J(θ)。这意味着学习可以通过调整模型参数、代价权重、终端成本、约束松弛等来改善闭环表现，而非仅把模型的预测误差最小化。换言之，参数学习以“闭环性能”为准绳。
    - 操作步骤建议：
        1. 以工程知识与资源约束建立初始 MPC 结构与初值 θ_0（确保安全约束）。
        2. 定义可调参数集（模型参数较少、代价/约束权重等），保持参数维度在可学范围内。
        3. 在仿真/离线阶段用 RL 或梯度方法学习 θ 以最小化估计的 J(θ)，在学习过程中保留安全约束或使用保守策略保证安全。
        4. 小步在线部署并监控，必要时回退并再次调整。
    - 心态与工程考量：接受模型永远不完美的现实，把精力放在“在已选结构下尽可能提升闭环性能”，利用 MPC 的可解释性与约束处理能力来避免纯 NN 方法的不可控风险。把优化目标从“拟合真是世界”转为“达到任务指标”。
- 框架二：双模型数据流心智模型（详细展开）
    - 核心想法：区分用于在线实时控制的“简化 MPC 模型”与用于离线学习/数据增强的“高保真模型/仿真器”。两者职责不同，相互补充。
    - 理由：真实世界数据成本高且采样慢，直接在线学习往往不可行；而把高精度模型纳入在线 MPC 会造成实时求解不可行或过于昂贵。通过两模型策略可以把“可用性”和“精确性”分开优化：在线模型保持可解性与安全，高保真模型用于生成大量训练数据并在离线环境中做策略验证与改进。
    - 实施步骤：
        1. 构建 MPC 在线模型：更偏向结构化简洁、可微、适合 QP/NLP 求解器的模型，明确约束与终端条件，并用此做实际部署与仿真验证。
        2. 构建高保真仿真器：可包含复杂信号、非线性、随机性、详细物理过程，用于批量数据生成、策略优化与鲁棒性测试（无需实时运行效率）。
        3. 在高保真仿真器上用 RL 训练或搜索最优代价修改/参数 θ，生成候选控制器或参数。
        4. 在真实系统或 MPC 在线模型上逐步验证与在线微调，收集真实数据用于更新高保真仿真器或直接用于策略改进（闭环回路）。
    - 风险控制与工程提示：在从高保真到真实系统的迁移中要采取保守策略（限制参数变化幅度、采用安全约束、使用基线策略回退机制），并在真实系统小范围测试后再全量部署。
    - 思维益处：该模型鼓励把问题分解成“可以在线实现的控制架构”与“可以离线大规模优化的学习环境”，在保证安全与实时性的同时获得样本效率与更高的策略性能。

# 总结

本讲围绕将 RL 与 MPC 结合展开，从动机、记号、MDP-MPC 的对应关系，到折扣的工程含义，再到一个核心理论结论：在一定假设下，通过修改 MPC 的代价与约束可恢复 MDP 的最优策略与价值函数。实践层面则强调把 MPC 作为结构化的策略近似器来参数化与学习，使用可微化的 MPC 求解器或灵敏度分析支持梯度方法，并提出双模型的数据流策略（在线简化模型 + 离线高保真仿真器）兼顾实时可解性与数据效率。整体心智模型是：接受模型不完美，以闭环性能为目标，通过在 MPC 结构内学习代价/参数来获得可解释、可控制且高效的工程化控制策略。
