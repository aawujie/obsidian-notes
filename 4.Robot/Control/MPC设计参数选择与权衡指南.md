# 2. Overview

本视频聚焦于模型预测控制（MPC，Model Predictive Control）设计中的关键参数选择问题，涵盖采样时间、预测范围（预测时域）、控制范围（控制时域）、约束（硬约束与软约束）以及目标函数中的权重设置。核心结论是：这些参数会同时影响控制器性能与在线优化问题的计算复杂度，因此需要在响应性能与计算负载之间权衡，遵循若干经验法则（例如采样时间在开环上升时间内对应10–20个采样，预测范围为20–30个采样，控制范围为预测范围的10%–20%且至少2–3步），并偏好将输出约束设为软约束以避免不可行性，同时通过权重配置在跟踪精度和控制平滑性之间取得平衡。

# 3. 按照主题来梳理

## 3.1 采样时间（控制器执行速率）

- 采样时间定义了控制器执行控制算法的速率，也就是控制器多久计算一次新的控制输入。选择合适的采样时间直接影响控制器对扰动和设定点变化的响应速度与每步优化的计算量之间的平衡。
- 如果采样时间太大，控制器更新太慢：当出现扰动或设定点变化时，控制器不能足够快地对其作出反应，系统可能出现较大的超调、延迟或暂态性能变差。视频中以直观推理说明：过长的采样间隔会导致控制动作滞后，从而错过及时纠正的窗口。
- 相反，采样时间若太小，控制器可以更迅速地应对扰动或设定点变化，这提高了跟踪性能与鲁棒性，但会带来更高的计算负担。更短的采样时间意味着在同样的物理时间内需要求解更多次在线优化问题，导致每个时间步的计算资源受限或实时性要求难以满足。
- 为了在性能与计算量之间找到合适平衡，视频给出一个经验规则：将采样时间设置为“开环系统上升时间”内的10到20个采样（即在系统开环响应的上升过程内应该包含约10–20次采样）。这里“上升时间”指的是系统从某一初始值到稳态附近的主要响应时间尺度。按照这个建议，采样既足够密以捕捉系统动态，又不会过于频繁以致计算量过大。
- 在实际应用上，采用该规则时需要先通过开环试验或系统建模得到一个合理的上升时间估计，然后据此计算出每个采样应该的时间间隔。若系统具有多个重要时间尺度（例如快、慢两套动态），应优先覆盖影响控制性能的主要动态，同时注意不要被短时高频噪声驱动去选择过短的采样时间。
- 总结要点：采样时间是一个在响应速度与计算负荷之间权衡的参数；经验建议是使开环上升时间包含约10–20个采样；选择时应结合系统主要动态特征与控制器实时计算能力来决定。

## 3.2 预测范围（预测时域）的选择与权衡

- 预测范围（预测时域，prediction horizon）是指MPC在每个时间步对未来对象输出进行预测的时间步数，字面上即控制器“向前看”多远。预测范围决定了控制器能够预见未来事件并据此优化当前到未来的一系列控制输入的能力。
- 预测范围太短可能带来严重后果。视频以驾车制动为例：在以每小时50英里（50 mph）的速度行驶时，踩下刹车需要约5秒才能将车停下。如果你的预测范围只有2秒，那么当看到红绿灯变红并开始制动时，预测范围不足以覆盖车辆的制动距离，控制器不会提前规划足够的减速动作，结果可能在红灯处无法停下。该例子强调了预测范围需要至少覆盖系统重要的停机或减速等关键动态，以保证可行且安全的控制行为。
- 那么为何不把预测范围设置得非常长？视频指出过长的预测范围也有负面影响：虽然看似增加了对未来的规划能力，但随着预测时间变长，不确定性和外部意外事件（例如前方掉落的障碍物、行人、路况变化等）会使长时间后计划的有效性下降，控制器可能需要频繁丢弃或重规划先前的长期计划，从而浪费计算资源。此外，预测越长，在线优化问题的变量和约束越多，计算复杂度显著上升。
- 基于前述折衷，视频给出预测范围的经验建议：预测范围设置为覆盖开环系统瞬态响应的20到30个采样时间（即若按已选采样时间计量，预测时域应包含约20–30步）。这个范围旨在既能抓取重要瞬态动态，又避免过长预测带来的过度计算和不确定性弱化效应。
- 在实际设计中，选择预测范围时应考虑：系统的主要调整或停机时间常数、控制目标的时域特性、安全或约束事件需要的预见时间、以及可接受的计算延迟。若系统遇到突发事件频繁或系统高度非线性，可能偏好较短预测并增加重规划频率；若系统动态平稳且预测模型可信，较长预测可以带来更优的长期规划。
- 总结要点：预测范围决定了控制器能预见多远并规划未来输入；太短导致在关键事件上措手不及，太长则增加不确定性和计算量。经验建议是预测范围为采样时间的20–30步，以覆盖开环瞬态响应。

## 3.3 控制范围（控制时域）的含义与经验设置

- 控制范围（control horizon）指的是在MPC优化中被允许为优化器生成自由控制动作的未来步数。换言之，控制范围内的每一步控制输入都被视为优化变量；在控制范围之后的输入通常被假定保持不变（或按某种策略冻结），以减少自由度。
- 控制范围与预测范围并不必然相等：可以把控制范围设得很小以降低优化问题的维度和计算复杂度，也可以把控制范围设大以获得更多的机动性和更细致的未来输入规划。视频中强调的关键考量是：控制范围越小，在线优化的变量越少，计算越快；但若控制范围过小，可能无法生成足够复杂或及时的输入序列来实现期望的控制目标。
- 那么为何不总是把控制范围设为1（只优化一个未来控制动作）以最小化计算量？视频指出虽然这是可行的，但它可能无法提供最佳机动性或对未来复杂动态的充分应对。通过增加控制范围，可以获得更好的动态响应和更有前瞻性的输入分配，但代价是优化问题更复杂计算更多。
- 另一方面，视频提醒实际影响的分布并非均匀：通常只有前几步控制移动对预测输出有显著影响，后续控制移动对输出行为的影响逐渐变小。因此选择非常大的控制范围会带来很多几乎无效的自由变量，既增加计算开销又不显著改进控制性能。
- 给出的一个实用经验法则是：将控制范围设为预测范围的10%到20%，并且至少设为2到3步（即控制范围最小应为2–3个采样时间）。例如，如果预测范围为20步，则控制范围可在2到4步之间；若预测为30步，则控制范围可在3到6步之间。此法既能保证控制器在最关键的短期内拥有足够的机动性，又限制了优化问题的规模。
- 在实际实施中，设计者还可以根据系统的相对惯性（慢动态或快动态）、可用计算资源和期望的闭环性能进行调试与仿真验证，必要时调节控制范围与其他参数（采样、预测）配合优化。
- 总结要点：控制范围决定优化器必须计算的自由控制移动数量；经验建议是控制范围占预测范围的10%–20%，并至少为2–3步；选择时需均衡机动性与计算复杂度，注意多数影响集中在前几步。

## 3.4 约束类型：硬约束与软约束及其设计注意事项

- MPC 的强项之一是能够直接在优化问题中处理约束。常见约束类型包括对输入（控制量）、输入变化率（delta u）以及输出（被控变量）的约束。这些约束既可以是硬约束（hard constraints），也可以是软约束（soft constraints）。
- 硬约束（不可违背）：这类约束必须在所有时间步都满足，优化器不可允许任何违反。硬约束适合那些由物理极限或安全法规严格限定、绝对不能超出的界限。例如视频中把油门踏板的位置限制作为硬约束的例子：由于油门踏板的物理行程是有限的，需要强制保持在该范围内。
- 软约束（允许违背但受罚）：软约束允许在必要时被违反，但优化器会将违反的量作为优化目标的一部分进行最小化（通过给出违反的惩罚或引入松弛变量并在目标中加权）。软约束适用于那些在极端情况下可以被打破但应尽量避免违反的限制，比如期望的速度范围或舒适性相关的输出边界。
- 关键设计注意事项：对输入和输出同时施加硬约束可能导致优化问题不可行（no feasible solution）。视频用一个车在高速公路爬坡的场景说明这种不可行性如何出现：车以50 mph行驶，当上坡导致速度自然下降时，控制器尝试通过增加油门（输入）来维持速度。若对速度和油门均设为硬约束，且在重载爬坡的情况下即便施加全油门也无法满足速度下限，那么优化器找不到同时满足这些硬约束的解，从而变为不可求解。这种情况在现实控制中会导致控制器失效。
- 因此，视频建议：尽量将输出约束设为软约束，以避免由于不可控外部干扰或模型不匹配而使优化问题变得不可行；同时避免同时对输入和输入变化率都施加硬约束（或至少谨慎设置），以免引起冲突。对于那些绝对不能违背的物理限制（例如执行器行程极限、阀门完全开闭的边界等），应保留硬约束；而对性能类或安全裕度类的输出约束，采用软约束并通过惩罚项控制其违反程度，是更稳健的做法。
- 在采用软约束时，设计者应为软约束的松弛变量选择合适的惩罚权重，使得在正常工况下优化器倾向于不违反约束，而在极端或不可控工况下也能找到可行解并最小化违反程度。过低的惩罚会经常导致约束被放弃，过高的惩罚会与硬约束类似造成潜在的不可行性或数值问题。
- 总结要点：约束的类型选择直接影响优化可行性与闭环安全，建议将输出约束设为软约束以增加鲁棒性，并谨慎处理对输入及其变化率的硬约束。

## 3.5 权重设置：在跟踪与平滑之间的权衡

- MPC 的优化目标通常包含多个相互竞争的子目标，例如追踪被控量的设定点（输出误差最小化）与控制输入平滑（避免过大的控制机动或频繁变化）。通过在目标函数中对不同项赋予权重，设计者可以在这些目标之间进行权衡。
- 视频以生活中平衡“睡觉、吃饭和社交”的比喻说明权重的直观含义：如果睡觉对你更重要，你会给睡觉更高的权重；同理，在MPC中如果某个输出跟踪比另一个更重要，就给它更高的权重。通过调整权重的大小和比率，我们能控制优化器更偏好哪类目标。
- 权重通常分为两类：对输出误差（tracking error）的权重和对输入或输入变化率（control effort / delta u）的权重。将输出误差权重加大，会使控制器更积极地将输出推向设定点；将输入变化率权重加大，会使控制动作更平滑、减少剧烈的操纵动作，但可能牺牲一些跟踪速度或精度。
- 在多变量系统（例如视频举了一个2x2系统）中，输出之间常有相对重要性差异。如果第一个输出比第二个输出更重要，就为第一个输出分配更大的权重，使它在目标函数中的相对权重比大于1。类似地，输入之间或输入与输出之间也可以按重要性配置权重，以达到预期的控制偏好。
- 设定权重时的实践步骤可以是：先定义性能优先级（哪些输出必须严格跟踪，哪些可以有较大允许误差）；然后设置输出权重以反映优先级；接着基于期望的控制平滑性设置输入和输入变化率的权重；最后通过仿真迭代调整权重直至满足性能与可实现性。在这个过程中，注意权重的量级和相互比值往往比绝对值更关键。
- 需要注意的是，不恰当地设置权重可能导致控制器行为极端：例如过度偏重输入平滑会使系统响应迟缓；过度偏重跟踪精度会引起控制抖动或对噪声敏感。因而权重调整通常需要结合仿真和实验验证。
- 总结要点：权重是MPC在不同目标之间实现折衷的工具，通过调整输出权重与输入/输入变化率权重，可以平衡跟踪精度与控制平滑性；多变量系统中还需调整输出之间的相对权重以反映优先级。

# 4. 框架 & 心智模型（Framework & Mindset）

- 总体心智模型：将MPC设计视为在“性能目标”与“计算/可行性约束”之间的多维权衡问题。设计流程不是单次选择，而是一个迭代的工程步骤，需结合系统动态特性、可用计算资源、约束的物理/安全性质以及控制目标的优先级来反复调整参数并通过仿真验证。
- 可执行的设计步骤框架：
    1. 系统动态识别与重要时间尺度估计：通过建模或开环试验确定系统的上升时间、瞬态响应及主要动态模式。这一步是后续采样时间、预测范围和控制范围选择的基础。
    2. 选择采样时间（sampling time）：依据第一步得到的上升时间，将采样时间设置为在开环上升时间内包含约10–20个采样。这能在不造成过高计算负担的前提下捕捉到系统主要动态。
    3. 选择预测范围（prediction horizon）：以采样时间为单位，将预测时间设置为覆盖开环瞬态响应的约20–30个采样。这步确保控制器对关键未来动态有足够预见，但又不过度扩展以致受不确定性影响过大。
    4. 选择控制范围（control horizon）：将控制范围设置为预测范围的10%–20%，且至少为2–3步。该步骤旨在保证前几步控制动作具有优化自由度，同时限制优化问题的规模。
    5. 约束策略制定：识别哪些约束是物理/安全上绝对必须的（设置为硬约束），哪些是性能或舒适性约束（建议设置为软约束并在目标中惩罚违反量）。避免同时将输入和输出的关键约束都设为硬约束，以降低不可行性的风险。
    6. 权重配置与目标层级：明确控制目标的优先级（哪个输出更重要、对控制平滑性的要求等），在目标函数中设置输出误差权重和输入/输入变化率权重。对多变量系统，设置输出之间的相对权重以反映重要性。
    7. 仿真与迭代调整：将上述参数投入仿真场景（包括可能的扰动、模型误差和约束极限情况），观察闭环性能与求解可行性，根据结果调整采样、时域、权重与约束策略。
    8. 现实运行监控与在线修正：在实际部署后，持续监控控制性能、求解时间与约束违反情况，必要时调整软约束惩罚、控制范围或采样率以适应运行环境变化。
- 心态与原则：
    - 保守优先：在存在不确定性时，倾向于采用较短的预测范围与软约束，以保证优化可行性和稳健性；把绝对不可违背的限制保留为硬约束。
    - 以影响力为导向：集中自由度在最有影响的前几步（前述控制移动通常对输出影响最大），避免过度扩展优化变量数以带来微小收益却极大增加计算负担。
    - 迭代为王：不追求一次性找到“最优”的参数组合，而是通过仿真—部署—监控—调整的循环逐步逼近满足性能与实时性的配置。
    - 权衡透明：在设计文档或团队交流中明确每个参数选择的权衡理由（例如为何选择某个控制范围或将某个约束设为软），以便后续维护和再调整。
- 应用示例心智：当面临实时计算资源有限的系统时，优先考虑减少控制范围和/或预测范围，同时通过增大输出误差权重来补偿潜在追踪性能下降；若系统遭遇频繁外部扰动且计算资源充足，可以适当缩短采样时间并扩大预测范围以提高前瞻性。
- 结语式提醒：MPC 参数选择并非孤立问题，而是一个系统工程决策集合，需要根据系统动态、实时性、可行性与安全性在多个维度上进行协同设计与反复验证。
