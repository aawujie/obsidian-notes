# 2. Overview

本视频核心在于解释模型预测控制器（MPC，Model Predictive Control）的基本思想与运作流程：控制器使用被控对象的数学模型预测未来输出，在预测范围内通过求解带约束的优化问题，最小化预测输出与参考信号之间的误差并平滑控制输入变化，从而决定当前时刻应施加的控制动作。视频以一辆自动驾驶汽车保持车道中间为示例，演示了MPC如何在有约束和扰动情况下，通过滚动时域（receding horizon）反复预测和优化来实现对被控系统的实时控制。此外，视频指出若系统状态不能直接测量，可通过状态估算器（例如卡尔曼滤波器，Kalman filter）提供反馈。

# 3. 按照主题来梳理

## 3.1 MPC 的基本目标与思想（控制目标与预测思路）

- 在控制问题中，控制器的根本目标是计算能够使被控对象输出（output variable）跟随期望参考信号（reference signal）的输入。模型预测控制器的独特之处在于“预测”：它不是仅基于当前误差直接给出控制，而是利用被控对象的数学模型去预测未来若干个时间步（预测范围，prediction horizon，记作 P）内的输出行为，然后在这些预测情形中寻找能最好地跟踪参考信号的控制输入序列。
- 具体而言，MPC 先假设一组未来的控制动作序列（例如方向盘角度随时间的变化序列），然后用系统模型逐步仿真（simulate）这些动作对未来输出的影响，得到对应的预测路径。对于每一组候选控制序列，都能得到一条预测输出曲线。MPC 的任务是从这些候选结果中选择一个最优序列，使得预测输出和参考轨迹的偏差在某种意义下最小。
- 这里的“某种意义下最小”通常通过构造目标函数 J 表达，目标函数会把预测误差（prediction error）与控制输入变化量（control input increment）等项进行加权并求平方和，从而同时考虑跟踪精度和平滑性。将控制变化量加入目标函数的目的，是避免控制动作在相邻时间步之间发生剧烈变化，保证控制的实际可实现性和乘客等的舒适性（在汽车示例中尤为明显）。
- MPC 的一个核心特性是它的基于模型的多步规划能力。相较于只用当前时刻信息作出决策的控制器，MPC 在决策时考虑了未来有限时域内的影响，因此能够更好地处理有延迟、约束以及需要权衡短期与中期目标的问题。但同时，这也依赖于模型的准确性和优化器求解速度——模型误差或计算延迟会影响控制效果。
- 在工程术语中，控制器输出发送给被控对象的信号称为“操纵变量”（manipulated variable），而被控对象的响应称为“输出变量”（output variable）。MPC 的决策依赖对未来输出的预测，因此对模型（以及必要时的状态估计器）的依赖性很强。这一点在随后的段落中会结合实际汽车示例详细展开。

## 3.2 汽车示例：如何用模型进行多步预测（模型与预测范围 P）

- 视频以一辆由 MPC 控制的自动驾驶汽车为例，目标是让车辆在车道中间行驶。为了简化说明，假定车辆纵向速度（forward speed）和加速度固定，只通过改变方向盘角度来调整车辆的横向位置（lateral position）。这种简化把控制问题变成单输入多输出（在此例中其实主要是单输入单输出的横向控制），便于展示 MPC 的预测与优化流程，但视频也提到 MPC 可以处理 MIMO（多输入多输出，multi-input multi-output）系统。
- 在画图说明中，纵轴表示时间轴，当前时刻位于图中的某一水平线左侧，左边部分代表过去，右边代表未来。图中以绿线标示车道中心线作为参考轨迹（reference）。当前时刻，方向盘被假设为某种给定角度或将以某种变化序列动作，MPC 使用车辆动力学模型把当前状态和候选的未来方向盘动作序列输入到模型中，向前仿真 p 个时间步骤，从而得到未来 p 步内车辆横向位置的预测路径。
- 预测范围 P（prediction horizon）是 MPC 向前看的时间长度或时间步数。它决定了控制器在优化时考虑未来的深度。较长的 P 可以让控制器更早“看到”未来的偏差趋势，从而可能做出更前瞻性的控制，但也会增加计算量和对模型准确性的需求。反之，较短的 P 计算量小、对模型误差鲁棒性可能更好，但可能看不清更远的变化，从而导致短视控制行为。
- 在仿真过程中，MPC 通常不是以随机或穷举方式随意生成预测路径，而是通过求解优化问题系统性地确定最优控制序列。优化器在候选控制空间内搜索使目标函数 J 最小的控制序列，并受到变量约束的限制（例如方向盘角度极限、车辆不得离开车道等）。
- 重要的是，虽然 MPC 在优化时计算出了一整段未来的控制序列，但在实际实施时，控制器只把这个序列的第一步应用到实际车辆上。应用后，车辆按照该控制动作运行一段时间到下一个采样时刻，然后控制器接收新的状态测量（或估计），再以新的当前状态为起点，向前再次进行 P 步预测并重新优化。这种不断向前、滚动更新预测范围的方式，被称为滚动时域控制（receding horizon control），是 MPC 的典型实施策略，能在系统受到扰动或模型不完全匹配时进行闭环修正。

## 3.3 优化问题、目标函数 J 与约束（如何衡量“最优”以及约束的作用）

- MPC 把控制任务转化为一个带约束的优化问题，优化变量通常是未来若干步的操纵变量序列（在示例中是方向盘角度随未来时间的变化序列）。目标是最小化一个定义良好的目标函数 J，同时满足关于操纵变量与输出变量的约束条件。
- 视频中给出的目标函数 J 包含两类常见项：一是预测误差项（prediction error），衡量预测的输出轨迹与参考轨迹之间的偏差；二是操纵变量增量项（control input increment），衡量相邻时间步之间操纵量的变化大小。通常这些项以加权平方和的形式出现，即对每一步的误差取平方并乘以权重，再将所有步的加权平方和相加得到总和。把操纵变量增量纳入目标函数的理由有两个：一是让控制平滑，避免剧烈动作带来的不适或机械磨损；二是作为调节器，防止在预测误差微小的情况下仍做出不必要的大动作。
- 数学上，目标函数 J 可以写为 J = sum_{k=1..P} [ w_e * (y_pred(k) - y_ref(k))^2 ] + sum_{k=1..P-1} [ w_u * (Δu(k))^2 ]，其中 y_pred(k) 是第 k 步的预测输出，y_ref(k) 是该步的参考，Δu(k) 是操纵量的增量，w_e 和 w_u 是对应的权重（weight）。视频并未给出具体权重数值，但强调权重用于在跟踪性能与控制平滑性之间进行权衡。
- 除了目标函数，MPC 在求解时必须满足约束（constraints）。常见约束包括：操纵变量本身的上下界（例如方向盘最大转角）；操纵变量变化率的限制（例如每个采样周期内方向盘能转动的最大角度变化）；输出变量的物理或安全界限（例如车辆横向位置必须保持在车道范围内，以防交通事故）。约束是 MPC 相较于许多传统线性控制方法的一个重要优势，因为它能在优化过程中直接将物理与安全边界嵌入到控制决策中。
- 在每个采样时刻，控制器求解这个带约束的优化问题并得到一条预测路径与对应的操纵量序列。具有最小 J 的序列被视为当前时刻的最优解。随后，控制器只实施该最优序列的第一步动作。实际中，这一步通常通过求解二次规划（QP，Quadratic Programming）或非线性规划（如果模型或约束是非线性的）来实现。求解器的选择取决于问题的结构与实时性要求；视频强调优化器在 MPC 中的关键角色但未详细阐述具体求解算法。

## 3.4 滚动时域（receding horizon）与扰动/状态估计（反馈循环与鲁棒性）

- MPC 的执行采用滚动时域（receding horizon）策略：在每个控制间隔（采样时间）内，MPC 以当前时间为起点，向前考虑 P 个时间步，求解最优控制序列；然后只实施序列的第一步；系统按此动作演进到下一采样时刻；控制器读取新的测量值或估计值，更新问题并重复求解。这种滚动与重复求解使得 MPC 在面对模型不准确性与外部扰动（disturbance）时能不断修正，从而实现闭环鲁棒性。
- 视频举例说明：由于无法测量或预测的扰动（如侧风、路面湿滑等），实际车辆的横向位置在下一采样时刻可能与先前预测存在偏差。MPC 不会一味依赖之前的长期预测；相反，在下一个采样时刻它会使用实际测量到的新状态重新求解优化问题，从而调整后续动作计划，弥补前一轮预测与现实之间的差异。这就是 MPC 对扰动的自适应修正能力的来源。
- 反馈环路中可能包含状态估算器（state estimator）。在视频的汽车示例里，假设车辆横向位置可以直接测量，因此直接作为反馈。但在很多实际系统中并不能直接测得所有需要的状态（state），这时需要状态估算器例如卡尔曼滤波器（Kalman filter，卡尔曼滤波器）来基于测量值和模型估计完整状态并反馈给 MPC。状态估算器的准确性也会影响 MPC 的效果：估计误差会成为模型误差的一部分，从而影响预测质量与最终控制表现。
- MPC 的循环特征意味着它的实时性能依赖于计算能力：每个采样周期必须在时间限制内完成模型预测与优化求解，否则控制会滞后或失效。因此在工程应用中，常要在模型复杂度、预测范围 P、采样时间以及求解器性能之间做折衷，以满足实时性与控制性能的需求。视频在结尾提示，后续会讨论这些设计参数（采样时间、预测与控制范围、约束与权重等）的具体选择与影响。

# 4. 框架 & 心智模型（Framework & Mindset）

- 框架一：MPC 的“预测—优化—实施—滚动”闭环框架（步骤化表述）
    1. 建模：建立被控系统的动态模型（可线性或非线性），该模型能从当前状态和未来控制序列预测未来输出。模型的选择影响预测精度与计算复杂度。
    2. 设定参考与约束：明确要跟踪的参考信号（reference）以及系统必须满足的约束（操纵变量范围、输出安全界限、操纵速率限制等）。
    3. 构造目标函数 J：把跟踪误差项与控制平滑项等写入目标函数，并设置各项权重以在性能与舒适/平稳性之间进行权衡。
    4. 在线求解优化问题：在每个采样时刻，以当前状态为初始条件，向前仿真 P 步并在约束下求解最小化 J 的控制序列。求解器可为二次规划（QP）或非线性规划（NLP），取决于问题结构。
    5. 实施并滚动：将最优序列的第一步控制动作应用到系统，等待系统演进到下一个采样时刻。读取新的测量或状态估计，回到第 4 步重新求解。这就是滚动时域（receding horizon）实施策略。
    6. 持续监测与调整：根据实时表现调整模型、权重、约束或预测范围，保证在不同工况与扰动下系统仍能满足需求。
该框架强调 MPC 是一个持续闭环的决策过程，而非一次性规划。它能将未来信息嵌入当前决策，同时通过滚动更新应对不确定性。
- 心智模型一：将控制问题视为受约束的短期规划问题
    - 把每个控制时刻理解为一次短期的规划任务。在有限的未来范围内评估可能的行动序列，其结果既要满足即时的安全约束（例如不出车道）也要兼顾未来短期性能（例如保持平稳）。这种心态促使工程师在设计 MPC 时既关注局部即时最优，也重视可实现性与约束合规。
    - 在此心智模型下，模型的角色不是提供绝对精确的“未来真相”，而是作为预测工具用于生成合理候选情形。由于模型不可能完全准确，心智模型要求控制器设计者接受并利用滚动时域的反馈特性——通过频繁更新和重优化补偿模型误差和突发扰动。
    - 同时，这个心智模型提醒设计者将计算资源视为稀缺资源：预测范围 P、控制和采样频率以及模型复杂度需要在控制性能与实时计算能力之间权衡。短采样周期和长预测范围能提高性能但增加计算负担；模型越复杂预测越精确但求解越慢。因此设计时应优先满足安全与实时性，并通过权重与约束调节性能目标。
- 心智模型二：约束驱动的安全优先策略
    - 在许多实际应用（如车辆控制）中，安全约束往往比最小化误差更重要。MPC 的优势之一就是能在优化过程中直接嵌入这些约束。因此在设计与调试 MPC 时，采用“先保证约束，再优化性能”的心态：确保操纵变量与输出变量的硬约束在任何时候都被维护，然后在可行域内尽量提高跟踪精度与舒适性。
    - 这一策略还包括考虑约束松弛（constraint relaxation）或软约束的使用，以在紧急情况下允许有限违例但附带惩罚，从而避免不可行性。例如在极端扰动下若硬约束会导致优化问题无解，则可以允许小幅违例并通过目标函数的大罚值来衡量其后果。
    - 最后，这个心智模型建议在设计权重（weights）时与安全需求保持一致：对可能导致事故的输出约束应赋予非常高的权重或设置为硬约束，而对舒适性或能耗等次要指标可相对放松权重。

# 总结

本视频通过自动驾驶汽车的横向控制示例，系统地说明了模型预测控制（MPC）的核心流程：利用系统模型进行多步预测（预测范围 P），在预测区间内构造并最小化包含跟踪误差与操纵变化量的目标函数 J，同时满足操纵与输出的物理与安全约束；在每个采样时刻仅实施最优序列的第一步并在下一个时刻以新的测量值重复这一过程（滚动时域），从而在扰动与模型误差存在时持续调整并保持闭环性能。视频还指出了状态估算器（如卡尔曼滤波器）在无法直接测量全部状态时的必要性，以及 MPC 设计中需要权衡的参数（采样时间、预测/控制范围、约束与权重），这些将在后续视频中详细讨论。
