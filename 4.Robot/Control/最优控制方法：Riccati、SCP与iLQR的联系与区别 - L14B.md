# 2. Overview

视频核心论题是比较和解释三类在最优控制/轨迹优化中常用的方法：线性二次（LQ）问题与 Riccati 回归得到的线性反馈律、基于 Sequential Convex Programming（SCP，序贯二次/凸规划）或 Gauss–Newton 的线性化 QP 子问题，以及 iLQR（iterative LQR，迭代线性二次调节）及其实时迭代（RTI）变体。结论是：线性二次问题有封闭的线性反馈结构并可通过 Riccati 向后回扫精确求解；SCP/高斯-牛顿通过在当前轨迹处线性化把非线性问题化为时变 LQ（QP）子问题并借助结构化 QP 求解；iLQR 则在前向传播中使用线性反馈但用非线性动力学推进，从而得到可行迭代（每次迭代产生满足原始动力学的轨迹），三者在可行性、收敛性质、对不等式约束的处理能力与实时实现策略上各有优劣。

# 3. 按照主题来梳理

## 3.1 线性二次（LQ）问题与 Riccati 解法的基本结构与结论

- 问题与假设：讲稿从一个没有不等式约束的最优控制问题出发，只把非线性源头归为系统动力学 f(s,a)。代价 C 和 E（轨迹代价与终端代价）被假定为二次且凸的（例如 s^T Q s + a^T R a 的典型二次型）。为避免矩阵记号混淆，讲者用简化记法，但强调若系统是线性的：f_i(s_i,a_i) = A_i s_i + B_i a_i + c_i（A、B 可随时间变化，c_i 为向量），且代价二次凸，那么问题为线性二次型（LQ）问题。
- Riccati 的重要结果：在上述线性二次设定下，最优反馈是线性的。对起始状态 s0（或 s0_bar 作为当前测量/约束），最优控制可以写成 a_i^* = K_i s_i + v_i（讲稿中称 K_i * s_i + v_i，其中 v_i 是因非齐次项出现的向量偏置）。这是来自向后 Riccati 递推（backward Riccati sweep）的经典结果。Riccati 递推同样给出一系列 P 矩阵（代价二次项相关）以及每步的 K、v，这些参数可存储供在线控制（如 MPC）使用。
- 求解与两次扫（forward/backward）：解 LQ 问题的典型数值流程包含向后回扫来计算 Riccati 方程并获得 K_i、v_i 等，然后前向一次从初始状态使用该线性反馈生成整个状态与控制轨迹（forward simulation）。对于线性系统，这样生成的轨迹就是问题的“精确解”——反馈律与轨迹相互匹配，不存在近似误差。
- 结构要点与可利用性：讲者强调，这是“漂亮”的、能显式写出的结果。Riccati 给的不只是在时刻 0 的反馈律，还隐含给出整段时域上每一时刻的线性律（若系统线性、代价二次则精确）。因此在 MPC 中经常只需存储 K、v 即可实时计算控制输入；也可以用这些反馈律对线性系统做前向仿真以恢复状态轨迹。
- 注：讲稿里有对符号细节的纠正（例如某次误把代价向量写成 CI，后改为 B_i 以避免混淆）。同时提到 LQR（线性二次调节）和 LQG（含估计器的线性二次高斯问题）：LQR 常指无穷时域情形的稳定反馈合成，而 LQG 是 LQR 加卡尔曼滤波/估计器（KMA filter）以处理噪声/部分观测。

## 3.2 SCP / Gauss–Newton 子问题：线性化、QP 构造与解法流程

- SCP 的基本思路与 Gauss–Newton 等价：当面对非线性系统时，SCP（Sequential Convex Programming，序贯凸规划）或在特殊情况下的 Gauss–Newton（高斯-牛顿）做法是：在当前轨迹处对非线性动力学 f 进行一次一阶泰勒展开（线性化），把原始非线性约束转化为线性的等式约束，从而把原问题近似为一个时变线性二次（即 QP，若代价保留二次）子问题。视频里把这一步的线性化运算表示为 f_l(s_i,a_i; sbar, abar) = f(sbar, abar) + (∂f/∂s)|*{sbar,abar} (s_i - sbar) + (∂f/∂a)|*{sbar,abar} (a_i - abar)。
- 变量与线性化点：讲者习惯把线性化点写作带横线的 s̄、ā̄（或上标 J 作迭代编号），并说明该线性化点可以是可行轨迹也可以是不可行轨迹——这反映出“序贯”（sequential）与“simultaneous”（同时）方法之间的差别：序贯方法不强求线性化点是严格满足动力学的可行轨迹（可用上次迭代的轨迹或任意猜测）；simultaneous 方法更倾向把状态/控制作为一体变量在内层 QP 里同时优化以保持对约束更严格的处理。
- QP 子问题与 Riccati 结构利用：线性化后形成的 QP 子问题保留时域上每步的线性化矩阵（因此是“时变 LQ”），可以借助结构化解法（Riccati 回扫）高效求解——这需要一次向后回扫（计算 K 与相关矩阵）和一次线性前向展开（用线性系统推进以得到控制与状态变量在 QP 解中的值）。讲者强调，求解 QP 的过程即所谓的准备（preparation）阶段，包含线性化计算 Jacobian、做 Riccati 向后回扫、以及基于线性系统做前向仿真以展开解。
- SCP 的完整迭代（full-step SCP）：完整的 SCP 迭代过程是：以当前轨迹为线性化点构造 QP，解该 QP 得到新的全集合变量 x^{j+1}（包含 s 和 a 的整条轨迹），然后把 x^{j+1} 作为下一轮线性化点继续迭代。这里的 QP 解通常并非直接等同于对原非线性问题的精确解，但 Gauss–Newton 型方法在良好正则性下会表现出快速（通常线性或次二阶）收敛。
- 可计算成本与准备-反馈划分：重要的工程视角是把迭代分为“准备阶段”（线性化 + Riccati 回扫 + 前向线性仿真等，可能耗时）和“反馈阶段”（在收到新的实际测量 s_0 或 s_j+1 时，仅做一次 K_0 * s + v_0 的矩阵乘法输出控制）。如果准备阶段耗时较长，可以在保持当前反馈律的同时重复应用这个低层反馈以应对扰动，直到下一次准备完成（多级迭代或多层控制架构）。

## 3.3 RTI（Real-Time Iteration）SCP 与 full-step SCP 的差别与实现要点

- RTI 的动机与操作策略：Real-Time Iteration（RTI，即实时迭代）策略在视频中被解释为对 full-step SCP 的实时化、工程化改写。主要思想是：在每个控制周期，利用上一次准备阶段（线性化 + Riccati 回扫）得到的反馈律 K、v，当最新时刻的实际状态测得后（s_0^{j+1} 或 s_j+1 的测量值），立即把控制设置为 u = K_0 * s_meas + v_0 并把该控制施加到系统。与此同时在后台继续进行下一轮准备（线性化、回扫）以更新下一次的反馈律。这样把“准备阶段（offline/后台）”与“反馈阶段（实时/在线）”分离，尽量保证控制输入的低时延。
- 关键点：RTI 在准备阶段已经做完线性化、Riccati 向后回扫并得到了所有 K_i、v_i（这些 K、v 是基于某个线性化轨迹 s̄、ā̄ 计算出来的）。但准备阶段无法知道未来真实测量的 s_0，因此在测得新的 s_0 后只需把该新的 s_0 代入 K_0，得到实时控制。这也是 RTI 在 MPC 等场景下广受欢迎的原因：把高开销的最优化准备放在后台，而把低开销的矩阵运算放在实时路径上完成。
- 可实现性与局限：RTI 的表现依赖于准备阶段所用线性化点的质量，若系统发生较大扰动或偏离准备时假设的轨迹，得到的线性反馈可能效果不佳。因此工程上常结合多级迭代（在准备阶段做多次 Newton / Riccati 趋近）或在低层持续应用现有反馈以保证某种安全性。RTI 可显著降低各周期在线计算负担，但对非线性强烈、或不等式约束复杂、或控制可达性在某些线性化点受限的场景，需要谨慎设计并配合约束处理策略。

## 3.4 iLQR（iterative LQR）与 single shooting 的区别、可行性与迭代方式

- iLQR 的前向-后向两步逻辑：iLQR 与 SCP 在“线性化 + Riccati 回扫”这一点上相同，但在前向展开上采用不同策略。iLQR 在求解子问题后并不去求解线性 QP 完整解（即用线性系统前向仿真得到的 s），而是“在非线性系统中以线性反馈作为控制律直接前向传播”来得到新的可行轨迹：a_i^{j+1} = K_i * s_i^{j+1} + v_i，并用真实的非线性 f 推导 s_{i+1}^{j+1} = f(s_i^{j+1}, a_i^{j+1})。换言之，前向传播是基于非线性动力学但使用线性化得到的反馈律。
- 与 single shooting 的对比：single shooting（单射法）通常会先求一个控制序列（例如通过一轮线性系统前向得到的控制），然后用该控制在非线性系统上进行前向仿真得到状态轨迹，再作为下轮线性化点；这等于把状态变量强制为“由控制导出”的结果，而不是在内层同时优化状态与控制。iLQR 在实现上更紧密地将控制生成与非线性仿真结合：它在前向传播阶段每一步都用线性反馈调整控制，使得前向仿真能在一定程度上抵消非线性带来的误差，从而比单射法更鲁棒、产生收敛更好的可行轨迹（每一次迭代的迭代跡均满足原始非线性动力学，换句话说得到的是“可行的”中间解）。
- 可行性与收敛属性：iLQR 生成的每次迭代轨迹都是满足原始动力学的可行轨迹（这是它与 full-step SCP 主要不同点之一，full-step SCP 的中间迭代往往不可行，因为它解的是线性化的 QP）。可行性在实际工程（必须满足状态模块、约束或安全边界）中是很重要的，iLQR 的可行性使其在 RL（强化学习）和控制设计中广受欢迎。然而如果存在硬性状态约束（例如严格的 terminal equality，零终端约束）或边界不等式，iLQR 在满足这些约束方面并不天然优越，SCP 类方法（直接求解带约束的 QP）对这些约束的处理能力更强。
- 收敛比较与线性化累积误差：iLQR 在每轮用线性反馈推进非线性系统，这意味着在某些情况下线性化的误差不会像 full-step SCP 那样完全被 QP 内修正，长期迭代中误差可能累积。但 iLQR 的局部收敛通常良好，且在许多无约束或弱约束问题上比简单的 single shooting 更稳健。与此同时，如果在某一线性化点处系统的可控性受限，iLQR 可能出现发散或远离期望轨迹的情形，因此在此类边界问题上需谨慎或结合其它机制（回退步长、信赖域、线搜索或约束处理）。

## 3.5 不等式约束、Interior-Point（内点）方法与 QP 服务器的整合

- 不等式约束的影响：当问题包含不等式（例如路径约束、输入饱和、状态界限、严格终端等）时，iLQR 与仅基于 Riccati 的纯结构化方法的适用性受限。SCP 的优势在于把原始非线性问题在当前轨迹处线性化得到“带不等式的 QP”并交给强大的 QP 求解器，这样可在每步迭代中直接处理活动集（active set）或边界信息，保证约束的严格满足或在内点方法的路径下逐步逼近边界。
- Interior-Point Method（IPM，内点法）与结构化 QP 解法：对于具有稠密时域结构的 QP（特别是带有动态约束、稀疏带状矩阵结构），现代 QP 求解器（例如基于内点法的实现）会在每次迭代里需要解一个线性方程组；该线性方程组本质上涉及到与 Riccati 递归等价的带状稀疏系统，因而内点法内部会利用前向-后向（forward-backward）结构化回扫来高效处理。这意味着把非线性问题转化为一系列 QP 并由 IPM 处理在实现上仍然会涉及大量的 Riccati 式回扫，但通过障碍参数（barrier parameter）与同伦/路径跟踪（homotopy）策略逐步缩小障碍，能在边界附近稳健收敛。
- 在工程上的权衡：若问题对不等式高度敏感或包含严格的边界条件（如精确终端约束），倾向于使用 SCP/内点法这类能直接处理约束的方案；若主要关注在无约束或约束弱影响情形下的快速实时控制，则 iLQR/RTI 等更轻量的结构化方法更易实现。讲稿也提到一个折中思路：在 iLQR 循环里嵌入 barrier 函数（障碍函数）或做内点式同伦，这样可让 iLQR 在一定程度上兼容不等式约束，但这使得算法更像是“结构化的内点法”，并要求在前向传播中仍要处理 barrier 引起的代价变形。
- 实际 QP 服务器的作用：工业与研究实现中，QP 服务器（尤其是能利用动态稀疏性的实现）会把“子问题求解”这一重任务放在专门模块里，可能通过多次前后回扫（对应不同 barrier 参数）才收敛到一个高精度的 QP 解；对于实时系统可以只做有限次回扫以得到近似解，但要注意近似解对整体收敛性与约束满足性的影响。

# 4. 框架 & 心智模型（Framework & Mindset）

下面抽象出几个可复用的 framework（框架）与 mindset（心智模型），把视频里讨论的算法结构化为可操作步骤与决策要点。每个框架均尽量详尽、分步说明以便直接用于思考或实现。

框架 A：RiccatiBased LQ 求解框架（适用于线性或线性化子问题）

- 适用场景：动力学为线性或已线性化、代价为二次（或二次近似）、不等式约束可以通过外部 QP 求解器处理或不存在。
- 输入：时间序列长度 N，系统矩阵序列 {A_i, B_i, c_i}（c_i 为非齐次项），代价矩阵序列 {Q_i, R_i, q_i, r_i}（终端代价对应 E），初始状态 s_0（或 s̄_0）。
- 步骤：
    1. 向后 Riccati 回扫（backward pass）：从终端 i = N 开始向后计算代价到达矩阵 P_i（或其等价量），并计算每步的最优反馈增益 K_i 与偏置 v_i（若代价或动力学含非齐次项）。
    2. 存储反馈律与相关矩阵（K_i, v_i, P_i 等），这些构成“策略”或在 MPC 中的离线准备阶段。
    3. 向前仿真（forward pass）：从 s_0 开始，用 a_i = K_i s_i + v_i 推进状态 s_{i+1} = A_i s_i + B_i a_i + c_i，得到完整的状态与控制序列。这一步在纯 LQ 中给出精确最优轨迹；在线性近似场景下给出 QP 的线性前向解。
- 输出与使用：K_i & v_i 作为实时控制器或 MPC 的策略使用；向前轨迹用于评估、更新线性化点或作为下一迭代的初值。
- 设计要点与局限：若存在不等式约束，Riccati 方案需嵌入到 QP 求解器/内点框架中，或仅做为近似控制；Riccati 本身要求二次凸代价与无约束或线性约束以保持解析性质。

框架 B：SCP / Gauss–Newton 子问题迭代框架（适合处理不等式约束）

- 适用场景：原问题为非线性系统最优控制，代价可近似为二次或本身二次；系统与约束需要通过凸子问题逐步逼近。
- 输入：当前轨迹 guess（s̄, ā），非线性动力学 f，代价函数，约束集（含不等式）。
- 步骤：
    1. 线性化：以 s̄、ā 为线性化点，计算各时刻的雅可比矩阵 ∂f/∂s、∂f/∂a，并构造线性动力学近似 f_l。
    2. 构造 QP 子问题：把代价二阶近似（若使用 Gauss–Newton，保持二次项）与线性动力学约束以及原问题的不等式约束放入 convex QP 中（可能包含松弛或正则化项以确保数值稳定）。
    3. QP 求解器（可能是内点法 IPM）：利用稀疏结构化求解器，通过多次前后回扫与线性代数步骤求解 QP（内点法会使用 barrier 参数同伦策略逐步逼近边界），并得到新的轨迹 x^{new}（包含 s 与 a）。
    4. 更新与迭代：把 x^{new} 作为下一轮线性化点（full-step）或结合线搜索/信赖域策略进行步长调整，重复上述过程直到收敛或满足停止准则。
- 输出与使用：最终轨迹满足原问题（在可行性与收敛条件下），能严格处理不等式约束。
- 设计要点与工程考虑：QP 求解器效率关键在于能否利用问题稀疏性、带状结构并做结构化的线性代数；若要实时化，需把“准备阶段”与“反馈阶段”分离以在测量到新的 s_0 时能快速响应。

框架 C：iLQR / RTI 框架（适用于无/弱约束实时控制）

- 适用场景：非线性但无或弱不等式约束的实时控制情形，需要低延迟且期望每次迭代生成可行轨迹。
- 输入：当前控制或状态轨迹（可仅为控制序列），非线性动力学 f，代价函数。
- 步骤（标准 iLQR）：
    1. 线性化与二次近似：在当前轨迹处对动力学与代价做一阶/二阶展开，得到时变线性动力学和二次代价（相当于构造 LQ 子问题）。
    2. 回扫计算线性反馈律：做 Riccati 向后回扫，得到 K_i、v_i。
    3. 前向仿真（非线性）：从 s_0（通常为真实测量）开始，用 a_i = K_i s_i + v_i 代入原始非线性动力学 f 推进，得到新的可行轨迹（s^{new}, a^{new}）。
    4. 以该可行轨迹作为下一轮线性化点，重复（可结合线搜索、步长缩放等）。
- RTI 实时化：把回扫（准备）放在后台循环执行，测得新的状态后立即用已得到的 K_0、v_0 生成控制并施加；后台接着继续迭代以更新 K、v。这允许在计算尚未完成时提供实时控制响应。
- 优缺点与注意事项：
    - 优点：每次迭代都产生满足原始动力学的可行轨迹，鲁棒于实时应用；前向非线性仿真有助于避免线性化误差的无约束累积。
    - 缺点：对硬性不等式约束支持弱；在线性化点处若出现不可控或弱可控情况，可能导致迭代发散；需配合步长或信赖域策略在困难情况下收敛。

心智模型：何时选用哪种方法（决策流程）

- 如果系统近似线性或代价严格二次且实时性要求极高，优先使用 Riccati/LQR 类型方法并预先计算反馈律（离线或半离线）。
- 如果问题含有重要的、硬性的约束（终端等式/不等式或路径约束），选择 SCP / Gauss–Newton + QP（内点或活动集方法），因为它能在每一次子问题中直接处理这些约束。
- 如果需要实时控制、系统非线性强但约束不多，iLQR / RTI 是折衷之选：既能生成可行轨迹又能在资源受限时实现低时延反馈。
- 实际工程常把三者结合：用 SCP/IPM 在后台准备更精确的策略，同时在前端用 iLQR/RTI 风格的低层反馈处理测量误差与短时扰动；或者在内点法中利用 Riccati 式结构以提高子问题求解效率。

# 总结

视频系统性地讲述了从经典 LQ/Riccati 结构、到非线性问题的线性化与 SCP（Gauss–Newton）子问题、再到 iLQR 与 RTI 等实用变体之间的联系。要点包括：线性二次问题可由 Riccati 精确解出线性反馈；SCP/高斯-牛顿通过在轨迹处线性化将非线性问题转为结构化 QP 并可利用内点法等求解不等式约束；iLQR 在前向传播中使用线性反馈但以非线性动力学推进，能生成可行轨迹并适合实时实现（RTI 风格）。工程上对是否存在硬性不等式、实时性要求与可控性状况的判断，决定了采用哪种方法或它们的混合。若有不确定的符号或记号，本文保持了原讲稿含义并在必要处说明了符号修正（如 CI → B_i 等）。
