## 第一部分：Mimic——合成数据生成

### 为什么需要合成数据

物理AI面临**大数据缺口**：真实采集高质量操作数据需要大量时间、人力和硬件成本。机器人学习通常需要百万级轨迹，远超人工上限。

仿真合成数据的核心价值：模拟人类和机器人动作 → 批量生成百万级高覆盖操作轨迹 → 结合强化学习/模仿学习做闭环仿真验证。

### 三种物理AI数据来源

| 层级 | 数据来源 | 用途 |
|:---|:---|:---|
| 底层 | 互联网数据 | 提升视觉语言基础模型的理解能力 |
| 中层 | 人类示范视觉数据 | 为模仿学习提供高质量动作基准 |
| 顶层 | 合成数据+仿真RL | 规模化数据扩展 + 闭环物理高保真验证 |

### 遥操作支持

三件事：
1. **Local Manipulation全身遥操作**：机器人边走边做任务
2. **真机Holonomic全身遥操作**：VR设备+动补设备，单臂/双臂精确控制
3. **灵巧手操作**：VR + Manus手套完成复杂手部操作

**关键原则**：支持的遥操作设备越丰富越易用，数据质量越高，合成数据效果越好。

### Mimic Gen（基础版）

核心原理（出自NVIDIA Research论文MimicGen）：
1. 将完整任务切分为多个**object-centric子任务**（如叠物块：抓取1→堆叠1→抓取2→堆叠2）
2. 对每个子任务，根据随机初始化的物体位置做轨迹变换
3. 通过任务空间线性插值完成新轨迹生成
4. 保证物理一致性+多样性+可规模化

**三步流程**：
1. 专家轨迹录制（空间鼠标/键盘/AVP眼镜等）——**质量决定生成数据上限，只需少量高质量示范**
2. 数据标注——系统自动/人工半自动切分子步骤
3. 批量生成——几分钟内生成上百上千条轨迹

### Dex Mimic Gen（双臂扩展）

对Mimic Gen的双臂任务扩展：
- 支持多个末端执行器适配
- 左右手动作同步或顺序执行
- 解决双臂协作的时序、协同、物理接触一致性问题

### Skill Gen（增强版，v2.3）

Mimic Gen的强化版，核心改进：
- **基于CuRobo集成**：实现碰撞可控的轨迹路径规划
- **更精确的子任务起始标记**：不能用自动标注，只能手动打标
- **动态世界表达**：对周围环境有动态建模能力
- **无碰撞轨迹规划**：不再使用线性插值，而是调用CuRobo做规划

**对比Mimic Gen**：Skill Gen在场景变化大、堆叠多物体、障碍物多的场景下表现更好，成功率更高，轨迹质量更好。

**技术实现**：
- USD资产的四边形网格自动三角化→直接作为CuRobo的碰撞网格
- 添加Rerun可视化工具：实时可视化轨迹规划效果

### Local Manipulation SDG（v2.3新功能）

从静态上半身操作录制 → 自动生成导航+操作的完整全身行为数据集。

适用：人形机器人 + 移动平台+机械臂复合机器人。

流程：静态录制操作序列 → 任意Mimic算法做轨迹增广 → 随机化场景 → 自动导航+操作结合。

### 四种Mimic算法对比

| 算法 | 适用场景 | 特点 |
|:---|:---|:---|
| **Mimic Gen** | 单臂桌面操作 | 最基础版本，线性插值 |
| **Dex Mimic Gen** | 双臂协作 | 多末端执行器，灵巧操作 |
| **Skill Gen** | 复杂场景、有障碍物 | CuRobo碰撞规避，更高质量 |
| **Local Manipulation SDG** | 移动+操作复合任务 | 自动融合导航和操作 |

## 第二部分：GR00T——VLA基础模型与后训练

### VLA模型生态

业界已收敛到共同范式：**视觉语言基础模型 → 扩展加入Action模态**。代表：Google Gemini Robotics、Physical Intelligence Pi 0.6、Figure、字节、智元等。

NVIDIA GR00T定位：**完全开源、跨硬件、跨具身的机器人基础模型**。

### GR00T N1.5架构回顾

标准的快慢系统架构：
- **System 2（慢）**：基于预训练VLM的Backbone（冻结），负责理解
- **System 1（快）**：基于DiT的Action Expert，负责动作执行

**N1.5 vs N1的关键增强**：
1. **冻结VLM**：预训练和微调阶段保持冻结，保留预训练能力，提升语言指令跟随稳定性和泛化
2. **更大VLM基准模型**：增强理解物理关系的能力
3. **Flair集成**：从视频中学习，基于World Modeling学习对未来轨迹的推断
4. **DreamGen集成**：生成神经轨迹作为虚拟动作加入训练，扩展数据多样性

**一句话总结**：N1.5通过冻结语言Backbone+World Modeling+神经轨迹数据加持，让VLA模型学习更长更复杂的任务。支持zero-shot迁移到未见过的物体和不同机器人平台。

### GR00T N1.6 最新发布

刚发布的关键增强：
- **更好的VLM Backbone**：NVIDIA Cosmos Reason的VLM变体
- **更多导航数据**：操作数据集引入导航数据
- **更多具身数据集**：仿真+真机数据混合
- **更大的DiT Action Expert**：扩展尺寸
- **动作空间改进**：从绝对动作→相对动作，效果更好
- **RL+VLA混合部署**：VLA提供高层目标，RL底层控制跟踪

### 后训练四步法（经验分享）

#### Step 1: 数据采集

- 支持多种遥操作设备（键盘鼠标、Manus手套、主从臂、VR眼镜等）
- **数据质量 > 数据量**：轨迹干净、无冗余、模态间（语言/图像/状态）保持同步
- **数据质量决定后训练策略模型成功率的*上限***

#### Step 2: 策略训练

- **GPU需求低**：VLM Backbone冻结，参数量不大，**单H100节点即可完成复杂任务后训练**
- **动作空间设计 = Tokenizer设计**：绝对vs相对、关节空间vs任务空间的选择非常重要
- **归一化/标准化方法**很关键
- 通过**多样化数据设计**防止过拟合，提升泛化

#### Step 3: 开环评估（离线）

在真机闭环验证之前，先做快速离线测评：
- 比较模型预测轨迹 vs Ground Truth轨迹的误差
- 用Action Chunking评估连续预测能力

**关键发现**：
- **低MSE ≠ 高成功率**
- 成功率峰值通常出现在**轻微过拟合**时
- 不同训练轮次之间，低MSE区域的成功率方差极大
- **结论：MSE只能参考，不能替代真机Rollout实验**

#### Step 4: 闭环验证

| 方式 | 优点 | 缺点 |
|:---|:---|:---|
| **仿真闭环** | 成本低、可重复 | Sim-to-Real Gap、偏差大 |
| **真机闭环** | 偏差小 | 噪声大、成本高、机器人易损坏 |

真机部署进阶路径：
1. **先同步Rollout跑通**（起点）
2. 发现抖动卡顿后→加入Receding Horizon Control
3. 异步执行、Real-time Chunking等控制策略tricks
4. →轨迹更优、更丝滑

## 第三部分：Isaac Lab-Arena——策略评估平台

### Isaac Lab vs Isaac Sim 分工

```
Sim ←→ [机器人rigging] → [Lab/Arena: 训练+测评大脑] → [Sim: Software-in-Loop部署测试]
```

- **Sim**：跟中间件（ROS等）结合 → 选Sim
- **Lab/Arena**：RL训练、并行环境策略测评 → 选Lab/Arena

### Arena 解决什么

未来机器人策略从单一任务→通用型，需要同时处理成千上万种环境。单任务无法验证可靠性和泛化性，需要能在短时间内运行数千种多样化评估场景的基础设施。

**传统策略评估三大痛点**：
1. 任务创建繁琐：每个场景手工搭建，重复度高
2. 任务多样性不足：复杂场景定义和随机化不足 → Sim-to-Real Gap严重
3. 系统割裂：不同团队维护不同代码库，开发成本高

### 成功的评估系统五要素

1. 简单任务定义（0→1）
2. 自动化多样化扩展（1→1000）
3. 多GPU并行评估
4. 稳定Benchmark套件
5. 跨平台无缝部署（PC/云端/CICD/Leaderboard）

### Arena 核心架构

```
                  ┌─ Task Config ──────────┐
                  ├─ Robot Config ─────────┤ ← 社区共建Benchmark
                  ├─ Scene Config ─────────┤
                  └────────────────────────┘
                            ↑
              统一评估框架（Arena）
                            ↑
              Isaac Lab Manager-Based API
```

**三层**：
- 底层：Isaac Lab基础API
- 中层：Arena统一评估框架（环境编译器+并行策略评估）
- 顶层：任务定义接口 + 生态伙伴共建Benchmark数据集

**Lab负责RL训练，Arena负责策略闭环测评。**

### Arena v0.1核心创新：可组合环境构建API

**解决场景组合爆炸**：传统方式下，N个机器人 × M个物体 × K个任务 = N*M*K个独立环境配置，指数级代码膨胀。

**Arena方案**：将场景、机器人、任务解耦为独立组件，运行时通过**Arena Environment Builder编译器**自动组装。

三大组件：

| 组件 | 定义 | 关键设计 |
|:---|:---|:---|
| **Scene** | 场景+物体+姿态 | Object类带**Affordance属性**（可供性） |
| **Embodiment** | 机器人模型+观测+动作空间 | USD路径、控制方式、观测配置 |
| **Task** | 成功/失败条件+Reset+Metrics | 基于Affordance方法，高度模块化 |

### Affordance系统

物体不仅仅是几何+碰撞网格，还有**Affordance（可供性）**——定义物体可以被如何交互：

| Affordance | Query方法 | Action方法 |
|:---|:---|:---|
| **Pressable** | `isPressed()` | `press()` |
| **Openable** | `isOpened()` | `open()` / `close()` |

示例：微波炉继承 `LaboratoryObject + Openable` → 系统自动理解"这个关节可以被打开" → 可用于开关门任务。

**任务通过Affordance定义 → 不再重复写交互逻辑 → 不同场景间复用 → 高度模块化。**

与光轮合作扩充Affordance物体数据库。

### 三步构建环境（代码示例）

```python
# 1. 定义Scene（物体+初始位置）
# 2. 定义Task（基于Affordance）
# 3. 编译
builder = ArenaEnvironmentBuilder(scene, embodiment, task)
env_config = builder.build()
```

### Arena路线图

| 版本 | 时间 | 内容 |
|:---|:---|:---|
| **v0.1** | 已开源 | 环境编译器（Scene+Embodiment+Task），支持模仿学习工作流 |

## Q&A 精选

### Skill Gen vs Mimic Gen
Skill Gen是Mimic Gen的**增强版**，不是下一代产品。已在Isaac Lab最新版开源。调用CuRobo替代线性插值，实现避障+更优轨迹。

### Loco Manipulation轨迹生成
分两步：①静态录制操作序列→②Segmented Local Manipulation算法解耦上半身操作和全身行走。行走时上身保持姿势不动，只需考虑导航避障。

### Action Space怎么选
没有定论。N1.6从绝对→相对动作效果更好。建议：**观测空间和动作空间对齐**——观测是任务空间就用任务空间动作，观测是关节空间就用关节空间动作。对有接触力反馈的任务，任务空间可能有提升。

### Arena是否开源
v0.1已开源，v0.2确定开源，v0.3还在路线图构想阶段。

### 如何参与Arena开发
直接GitHub提PR或Issue。早期只开放给合作伙伴（光轮、NV内部），但社区贡献非常欢迎。

### Mimic原子任务切分
关键原则：**object-centric**，根据操纵物体个数切分。**子任务越少越好，不是越细越好**。过多的子任务→更多不必要的线性插值→更多冗余动作。

切分方式：Auto模式（配置subtask config）或手动模式（按键标记起始/终止点）。Skill Gen只能用**手动模式**（要求更精准）。

### N1.6 RL+VLA
N1.6本身还是监督学习/模仿学习VLA算法。与RL结合是双系统架构：VLA提供高层目标→RL底层控制器（Holonomic Control）执行。

### 一定要用CuMotion？CarRose可以吗？
可以。当前用CuRobo是因为它在模拟器Python环境中更方便。CarRose也可以集成。跟ROS相关的都要用Isaac Sim。
