## 1. MuJoCo 仿真基础

### 知识点
- **MJCF/XML 模型描述**：body、joint、actuator、sensor 的层级关系
- **物理引擎核心**：接触模型（软接触 vs 硬接触）、积分器（Euler/RK4）、时间步长选择

### 面试考点

- 自由度怎么算？Humanoid 模型有多少 DOF？→ **通常 21-28 个关节**

## 2. 强化学习核心

### PPO 算法（必考）

**核心公式：**
$$L^{CLIP}(\theta) = \mathbb{E}[\min(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t)]$$

- `r(θ)` = 新旧策略概率比
- `Â` = 优势估计（通过 GAE 计算）
- `ε` = clip 范围，通常 0.2

**GAE（Generalized Advantage Estimation）：**
$$\hat{A}_t = \sum_{l=0}^{\infty}(\gamma\lambda)^l \delta_{t+l}$$
$$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

**策略网络输出：** 高斯分布 → `action = μ + σ·ε`

### 面试考点
| 问题 | 答案要点 |
|------|----------|
| PPO vs TRPO？ | TRPO 用 KL 硬约束 + 共轭梯度，PPO 用 clip 近似，更简单 |
| 为什么不用 DQN？ | 连续动作空间，DQN 只能离散 |
| 为什么不用 SAC？ | SAC 也行，但 PPO 在 locomotion 上更稳定、更主流 |
| GAE 里 λ 的作用？ | λ=0 高偏差低方差，λ=1 低偏差高方差，典型 0.95 |
| entropy bonus？ | 鼓励探索，防止策略过早收敛 |
| V(s) 的作用？ | 作为 baseline 降低方差 |

## 3. 奖励函数设计（重中之重）

### 核心奖励项

```python
reward = (
    w1 * v_x              # 前进速度奖励
    + w2 * alive           # 存活奖励（每步 +1）
    - w3 * energy          # 能量惩罚：Σ|τ|²
    - w4 * torso_tilt      # 姿态惩罚：躯干倾斜角
    - w5 * height_dev      # 高度偏差惩罚
    + w6 * foot_contact    # 脚部交替触地奖励
    - w7 * joint_limit     # 关节限位惩罚
)
```

### 课程学习策略
1. **Phase 1**：站稳 → 高存活奖励 + 姿态惩罚
2. **Phase 2**：行走 → 加前进速度奖励
3. **Phase 3**：跑步/跨越 → 提高速度目标 + 加障碍

### 面试考点
- 奖励塑形 vs 稀疏奖励的取舍？→ **塑形更快收敛但可能局部最优**
- 各项权重怎么调的？→ **实验 + 直觉，没有银弹**
- 为什么不直接用模仿学习？→ **需要参考轨迹数据，RL 更通用**
- 遇到过奖励 hack 吗？→ **比如原地抖动骗存活奖励，需加运动惩罚**

## 4. 状态空间 & 动作空间设计

### 观测空间（Observation）~40-70 维

| 类别 | 内容 | 维度 |
|------|------|------|
| 躯干 | 高度、倾斜角（roll/pitch/yaw）、线速度、角速度 | ~13 |
| 关节 | 各关节角度 + 角速度 | ~34-56 |
| 可选 | 上一步 action、接触力传感器 | ~17-21 |

### 动作空间（Action）~17-21 维
- 各关节的**目标位置**（不是直接力矩）
- 底层 **PD 控制器**：`τ = Kp·(θ_target - θ) + Kd·(0 - θ̇)`

### 面试考点
- 为什么用 PD 控制器而不是直接输出力矩？→ **更稳定、更像真实机器人**
- 观测里要不要加历史帧？→ **可以加 2-3 帧，或用 LSTM/Transformer**
- 动作空间归一化？→ **[-1, 1] 映射到实际力矩范围，必须做**

## 5. 训练技巧

### 关键技巧
- **并行环境**：vectorized env，几千个环境同时跑
- **Observation Normalization**：running mean/std，不做的话值域差异大
- **课程学习**：任务太难直接学不会，需要递进
- **Domain Randomization**：随机化质量、摩擦、关节阻尼

### 面试考点
- 训练多久收敛？→ **通常几百万到几千万步，几小时到一天**
- observation normalization 不做会怎样？→ **值域差异大，网络难学**
- 怎么判断训练好了？→ **奖励曲线 + 实际 rollout 看步态自然度**

## 6. Sim-to-Real（加分项）

### 三大方法
1. **Domain Randomization**：训练时随机化物理参数，让策略对不确定性鲁棒
2. **System Identification**：测量真实机器人参数回填仿真
3. **Teacher-Student**：仿真用特权信息训 teacher → 蒸馏给只用传感器的 student

### Sim-to-Real Gap 来源
- 接触模型不精确
- 控制延迟（真实 5-20ms）
- 传感器噪声
- 执行器建模误差

## 7. 网络结构

### 典型架构
```
Actor:  obs(67) → MLP(256, 256) → ELU → μ(21), log_σ(21)
Critic: obs(67) → MLP(256, 256) → ELU → V(1)
```

### 面试考点
- 为什么用 MLP 不用 CNN？→ **状态是低维向量不是图像**
- Actor 和 Critic 共享参数？→ **不共享更稳定，locomotion 通常分离**
- 为什么不用更深的网络？→ **状态空间不复杂，过拟合风险**

## 9. AMP（Adversarial Motion Priors）— 进阶核心

### 核心思想
PPO 只靠手工奖励很难让步态"像人"，AMP 引入一个**判别器**来约束风格：
- 收集人类运动捕捉数据（MoCap）作为参考
- 训练一个判别器 D(s,s')：区分「策略产生的状态转移」和「MoCap 参考的状态转移」
- 策略的奖励 = 任务奖励 + **风格奖励**（骗过判别器）

### 公式
$$r_{total} = w_{task} \cdot r_{task} + w_{style} \cdot r_{style}$$
$$r_{style} = -\log(1 - D(s_t, s_{t+1}))$$

判别器目标（类似 GAN）：
$$\min_D -\mathbb{E}_{MoCap}[\log D(s,s')] - \mathbb{E}_{\pi}[\log(1 - D(s,s'))]$$

### 和纯 PPO 的对比

| 维度 | 纯 PPO | PPO + AMP |
|------|--------|-----------|
| 步态自然度 | 靠手工奖励项约束，容易怪异 | 判别器自动学习风格，步态像人 |
| 奖励设计 | 需要精心调多项权重 | 任务奖励可以简化，风格由 AMP 兜底 |
| 数据需求 | 不需要参考数据 | 需要 MoCap 参考动作 |
| 训练复杂度 | 单纯 RL | RL + 判别器联合训练，类似 GAN |
| 稳定性 | 稳定 | 判别器训练需要平衡，略复杂 |

### 实现要点
1. **参考动作数据**：从 CMU MoCap 数据库获取，或用 DeepMimic 数据集
2. **状态转移对**：`(s_t, s_{t+1})` 作为判别器输入，不是单帧
3. **Gradient Penalty**：判别器加 GP 防止训练崩溃（参考 WGAN-GP）
4. **判别器特征**：用关节角度 + 角速度 + 躯干姿态，不用原始 qpos

### 面试考点
| 问题 | 答案要点 |
|------|----------|
| AMP 和模仿学习的区别？ | 模仿学习直接克隆动作，AMP 只约束风格、不限制具体动作 |
| 为什么不直接用 GAIL？ | AMP 是 GAIL 的改进版，用状态转移而非状态-动作对，更稳定 |
| 判别器过强怎么办？ | 策略完全模仿参考失去任务性能，需要平衡 w_task 和 w_style |
| 判别器过弱怎么办？ | 步态不自然，退化成纯 PPO |
| MoCap 数据不够怎么办？ | 少量参考也能用，AMP 对数据量要求不高（几十秒的动作即可） |
| AMP 能处理新任务吗？ | 能，同一个风格先验可以迁移到不同任务（走/跑/跳） |

### 训练 Pipeline

```
MoCap 数据集 ──┐
               ├──► 判别器 D(s,s') ──► r_style
策略 rollout ──┘                          │
                                          ▼
                           r_total = r_task + r_style
                                          │
                                          ▼
                                    PPO 更新策略
```

### 参考论文
- **AMP 原论文**：Peng et al., "AMP: Adversarial Motion Priors for Stylized Physics-Based Character Animation", SIGGRAPH 2021
- **ASE**：Peng et al., "ASE: Large-Scale Reusable Adversarial Skill Embeddings", SIGGRAPH 2022（AMP 的扩展，学习可复用技能库）
- **DeepMimic**：Peng et al., 2018（AMP 的前身，用参考轨迹做逐帧跟踪）

## 10. 课程学习（Curriculum Learning）

### 策略
```
Level 0: 平地站稳（5M steps）
    ↓ 奖励 > 阈值
Level 1: 平地行走（10M steps）
    ↓ 速度达标
Level 2: 平地跑步（10M steps）
    ↓ 速度达标
Level 3: 随机地形行走（15M steps）
    ↓ 成功率达标
Level 4: 障碍物跨越（15M steps）
```

### 地形课程（Terrain Curriculum）
- **平地** → **缓坡（5°）** → **陡坡（15°）** → **台阶（5cm）** → **台阶（15cm）** → **碎石地形**
- 每种地形按成功率自动升级/降级

### 面试考点
- 为什么需要课程学习？→ **直接学最终任务太难，策略初期全是摔倒，学不到有效信号**
- 怎么定义"通过"当前 level？→ **平均奖励/成功率超过阈值，保持 N 个 epoch**
- 课程设计的原则？→ **每级难度增量不能太大，要保证策略能拿到正向奖励**

## 11. 完整算法组合（面试版叙事）

> **算法栈：PPO + AMP + Curriculum Learning**
>
> 「我的人形机器人控制项目用了三层算法：
> 1. **PPO** 作为底层 RL 算法，负责策略优化
> 2. **AMP** 引入人类运动先验，让步态自然——不需要逐帧跟踪参考动作，只约束运动风格
> 3. **课程学习** 从站立到行走到复杂地形，渐进式提升任务难度
>
> 这三者的关系是：PPO 负责"学会做"，AMP 负责"做得像人"，课程学习负责"学得会"。」
