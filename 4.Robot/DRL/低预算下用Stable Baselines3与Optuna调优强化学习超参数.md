# 3. 按照主题来梳理

## 3.1 初始实验：低预算下的失败与直观观察

- 实验设置与目标：讲者以 Pendulum（摆）环境为第一个示例，使用 Stable Baselines3（SB3）里的 PPO 算法，设定非常小的训练预算（示例中以 4,000 steps 为例），目标是让读者看到在极低预算下即使用经典算法也很难收敛。讲者提到当用 PPO 在该预算训练时，最终 reward 典型地停在约 -1000（远未解决环境）。这是用来说明“默认超参数在某些小预算/困难情形下并不适用”的直观证据。
- 尝试切换算法：为了检验是否只是算法问题，讲者快速把算法从 PPO 换成 A2C（仍是 SB3 的接口），演示复制训练与评估代码后的运行结果。观测到即便换成 A2C，在同样小的训练预算下依旧无法解决 Pendulum，说明简单换算法未必能解决问题。讲者强调若改为 off-policy 算法（例如 DDPG、SAC 等），情况会改善，但这里目标是展示如何在 on-policy 框架（如 PPO/A2C）内做优化。
- 增加训练预算的效果：接着讲者将训练预算放大 10 倍（例如从 4,000 提升到 40,000 steps），但仍然有可能不足。通过这一连串尝试，视频传达出两点：(1) 在某些任务上，尤其是随机性大或样本效率低的情形，短时间训练无法得到好的网络；(2) 一味增加训练步数并非总能解决问题，尤其当超参数不合适时，更多步数可能只是浪费资源。
- 小结与引出：在观察到“默认设置 + 小预算”失败后，讲者引出需要“调参（hyperparameter tuning）”的主题，并指出后续会演示手动调参的效果以及如何用自动化工具（Optuna）高效完成搜索。

## 3.2 手工调参示例与关键超参数说明

- 手工调参的出发点：在确定增加训练预算仍不充分时，下一步是改动超参数。讲者在视频里提供了“已验证有效”的两个超参数配置（在代码仓库或示例里已有），把这些配置用于相同的训练预算后，环境能够被成功解决（即 Pendulum 收敛）。由此说明在许多情况下，正确的超参数组合比简单增加样本预算更加关键。
- 哪些超参数可调：讲者列举并解释了在 A2C/PPO 等算法中常见且影响显著的超参数：
    - 网络结构（policy 和 value network 的层数与每层神经元数量）：例如两层网络或一层网络等架构会影响表示能力与样本效率。
    - 激活函数（activation）：例如 tanh（双曲正切）或 relu（修正线性单元）等，不同激活函数会影响训练稳定性与梯度传递。
    - 学习率（learning rate）：影响模型权重更新幅度，高学习率可能加速收敛但导致不稳定，低学习率更稳定但训练慢。
    - 折扣因子（discount factor，gamma）：决定算法更偏重即时奖励还是长期回报。缩小 gamma（例如更靠近 0）会优先短期收益，通常能更快学到某些行为但可能陷入局部最优。
    - 梯度裁剪阈值（max grad norm）：控制梯度更新的最大范数，较高的阈值允许更大参数变动，可能促进探索但也可能不稳定。
    - 熵系数（entropy coefficient）：用于鼓励策略探索，较高熵系数会使策略探索性更强。
    - 收集步数（n_steps 或 batch size）：影响梯度估计的噪声程度与样本利用率，较大的 n_steps 有助于更稳定的梯度估计但也增加每次更新的样本成本。
- 手工调参示例细节：讲者在 CartPole-like（带杆子的 cart）任务上示范手工调参。初始默认超参数在有限预算（例如 20,000 steps）下，训练所得的 episodic reward 大约在 120（远低于最大 500）。通过逐项修改超参数（例如降低 gamma，增加熵系数，调整学习率到更合适的范围、增大梯度裁剪、增加收集步数等），可以显著提升最终表现。讲者特别提到在一组手工成功的配置中存在更高的 gradient norm（允许更强参数更新），以及较高的 learning rate，这使得模型能更快地改变策略、偏向即时奖励，进而在短预算内取得好成绩，但也承认这类改动可能牺牲稳定性且更容易陷入局部最优。
- 随机性与可重复性（seed）：讲者强调固定随机种子（seed）可以重复得到相同结果，但好的超参数应对多个 seed 才稳定。经常会出现某组参数在一个 seed 上表现优秀，但换 seed 后性能大幅波动，因此调参目标应关注跨 seed 的稳健性而非单次 trial 的最好成绩。

## 3.3 自动化超参数优化：使用 Optuna（示例流程与关键点）

- 自动调参的动机与目标：手工调参耗时且不可靠，尤其当超参数空间维度较高或复杂交互存在时。视频引入 Optuna 作为自动化超参数优化工具，用以在有限实验预算内系统探索超参数空间并进行早期剪枝（pruning），提高找到高性能参数组合的效率。
- Optuna 配置要素：讲者展示了构建 Optuna study 的关键配置项：
    - sampler（采样器）：决定如何基于已有试验选取下一组超参数，典型的选择是 TPE（Tree-structured Parzen Estimator）等能够利用历史信息的启发式采样器，而也可以选择随机采样器做 baseline。
    - pruner（剪枝器）：用于在试验中途根据中间评估结果提前终止可能低效的试验，从而节省预算。剪枝依据通常是中期评估（例如若中期 episodic reward 远低于当前最优）的比较。
    - 最大试验次数（max_trials）与每次试验的最大预算（例如 max steps 或 max timesteps）：这两个参数决定总计算预算。
    - search space（搜索空间）：需要为每个待调参数定义采样策略（例如对数尺度的学习率、分类型的网络结构、布尔或离散选择等）。
- 示例实现要点与流程：视频讲者一步步演示实现细节：
    - 定义 search space：例如学习率从 1e-5 到 1e-1 以对数分布采样（log scale）；网络结构采用 categorical（例如 ["64,64", "32,32"]）；激活函数为 categorical（如 "tanh", "relu"）；梯度裁剪与熵系数等也以合理区间定义。
    - 构造 objective 函数：Optuna 的核心是 objective(trial) 函数。该函数的流程通常为：从 trial 中采样超参数 → 用这些超参数构建并实例化 RL 模型（如 A2C）→ 训练模型（或训练到一定步数）并在若干中期点运行评估（evaluate_policy）→ 将评估结果通过 callback 或 trial.report 上报给 Optuna → 若满足剪枝条件则中止当前试验并返回中间结果，Optuna 根据 pruner 决定是否真正剪枝。
    - 评估与剪枝的具体实现：视频里使用 EvalCallback（或自定义 callback）每隔一段训练步进行评估（如 10 个 eval episodes），将平均 episodic reward 报告给 Optuna。Optuna 在达到设定的中期检查点时，会基于历史试验构建的 surrogate model 判断该试验是否值得继续（若表现太差则 prune）。
    - 分布式/多进程搜索：讲者提到 Python 的 GIL 限制多线程效率，但 Optuna 支持多进程或多节点并发地写入同一个数据库（例如 RDB 后端），以实现分布式并行优化。这使得在多机或多进程环境下加速搜索成为可能。
- 实验结果与可视化：通过运行多次试验（视频中示范了几十次 trial），可以观察到随着试验次数增加，surrogate model 更准确，采样器倾向于在高性能参数附近采样，从而越来越频繁得到接近最大分数（例如接近 500）的试验。视频展示了试验结果的散点（trial dots）、剪枝情况与参数重要性（parameter importance）统计，提示在该次运行里 gradient norm 对性能影响最大，但讲者强调这一结论并非对所有运行都成立，需更多试验以验证稳定性。

## 3.4 实践建议、迁移性讨论与调度策略

- 超参数迁移（transferability）讨论：观众提出问题：是否可在简化任务或替代 simulator 上调好超参数，然后迁移到真实或复杂任务。讲者的立场是：通常在“同一类任务”或“相似模拟器/同任务不同仿真细节”上，找到的超参数常常可迁移并发挥效用，但没有严格保证。若能在简化 reward 或简化物理的相似拓扑上做预调，会比完全不同任务上迁移效果好。讲者强调这是实践中常用但并不完美的策略。
- 随机性与稳健性：调参时要关注多个 seed 下的表现。单次试验可能因随机性而产生误导性的高分，真正可靠的超参数需要在多个随机种子（multiple seeds）上表现稳定。
- 学习率与调度（scheduler）：讲者提到常用的做法是使用学习率调度器（如线性衰减），而不是恒定学习率。SB3 支持在构造器中传入函数而非常量，从而实现线性递减等策略。类似地，熵系数也可以用调度策略，但可能需要手动实现或使用自定义版本。
- 实验预算分配与早期停止：在有限资源下，应合理设置每个试验的最小预算（min_budget）与最大预算（max_budget），并启用剪枝以快速放弃表现不佳的配置。这样可将更多资源集中在有潜力的超参数组合上。
- 分享参数与协作：讲者鼓励如果发现好的超参数组合应共享出来（例如在会议或代码仓库中），这样其他人可以复用。也提到可通过在 Optuna 的数据库中保存试验信息实现长期的协作和重复实验。
- 总体心得与注意点：重要的一点是：超参数搜索能在有限预算下显著提升训练效果，但要注意抽样策略、剪枝策略与评估频率的选择。评估噪声大时需要更多重复或更稳健的评估策略（例如更多 eval episodes 或更长评估窗口），否则优化器可能被噪声误导。

# 4. 框架 & 心智模型（Framework & Mindset）

- 框架一：有限预算下的调优工作流（Budget-aware Tuning Workflow）
    - 问题识别：首先确认训练失败是否因预算不足、算法选择问题、还是超参数不合适。通过对比不同算法、不同预算的初步实验来判定。
    - 预算分层设定：为每个试验指定 min_budget（用于能否初步判断是否有效）和 max_budget（试验的最大资源上限）。min_budget 应足以让优秀配置露出端倪，但不能太大以免浪费资源。
    - 初步筛选（采样 + 早期评估）：使用随机或启发式采样器在 search space 中采样若干配置，配合中期评估与剪枝（pruner）机制快速淘汰表现不佳的试验。中期评估频率要与环境波动性匹配（噪声大的任务需更稳健的评估策略）。
    - 深度验证（多 seed 与长期训练）：对筛选出的最优候选，在多个随机种子和较长训练预算下进行复测，以确认其稳定性与可重复性。若候选在短 budget 下表现好但在多 seed 或长训练中退化，则视为不稳健。
    - 迁移与泛化测试：尝试将找到的超参数在相似任务或相近的 simulator 上复用，检验迁移性。若迁移性差，则需要在目标任务上重新搜索或进行更细致的局部微调。
    - 文档化与共享：将成功的超参数与实验设置记录并共享，便于团队复现和后续优化。使用数据库（如 Optuna 的 RDB）能帮助长期积累试验数据。
这个框架强调将有限计算资源分层分配、把早期评估与剪枝作为加速器、并通过多 seed 与长训练确认稳健性。
- 心智模型二：噪声下的决策与优化（Noise-aware Optimization Mindset）
    - 接受评估噪声：强化学习评估天然带有高方差（环境随机性、探索行为、seed 差异等），因此单次评估不可作为最终判定。优化流程必须内建对噪声的容忍策略。
    - 使用统计与重复来减少误判：在关键评估节点上，采用多次评估（多 eval episodes）或多 seed 平均来估计真实性能，而非单次峰值。尽量用置信区间或均值而不是极值做为试验的评价标准。
    - 结合模型化采样（surrogate）与探索—利用采样器（如 TPE）基于历史结果建立代理模型，从而更智能地在高维空间里偏好潜在优解；同时保留一定随机性以避免陷入早期误导的局部最优。
    - 早期停止与资源重分配：采用剪枝策略在中期就停止表现糟糕的试验，把剩余资源分配给更有希望的试验。剪枝阈值要平衡保守与激进，过早剪枝可能丢失后来回升的试验，过保守则浪费资源。
    - 可复现性优先于瞬时最优：在实际工程里，寻找在多个 seed 与多场景下稳定工作的超参数，通常比找到一组只能在单次试验中爆发的“最优”更有用。故在优化目标设定上，应把“稳定高平均表现”作为首选指标。

总结以上两个心智模型：在有限资源和高噪声条件下，系统化的分层预算、早期筛选与多尺度验证策略能显著提高超参数调优的效率与可靠性。同时，评估噪声应被正视，优化过程要通过统计手段与代理模型来降低被噪声误导的风险。

# 总结

视频通过具体示例（Pendulum、CartPole-like 任务）演示了在低预算场景下默认超参数往往不够用，简单换算法或增加训练步数并非总能解决问题。手动调参虽能找到有效配置，但费时且对随机性敏感。借助 Optuna 类的自动化超参数优化工具，可以通过智能采样、代理模型与试验剪枝在有限预算内更快定位高性能参数组合。最终建议是在实际工程中采用分层预算、早期剪枝、多 seed 验证与学习率/熵等参数调度策略，并记录与共享成功配置以便迁移与复用。
