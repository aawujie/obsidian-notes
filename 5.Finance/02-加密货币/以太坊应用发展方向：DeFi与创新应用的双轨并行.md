# 1. Metadata

- Title: 路边对话：以太坊上的应用该如何发展？
- Author: 路边对话（对话中提及的发言者包括 Vitalia/Vitalik 等）

# 2. Overview

本视频是一段在香港/新加坡的路边对话记录，核心论题是围绕“以太坊（Ethereum）及类似区块链上面应用的发展方向与策略”。结论可以概括为：区块链应用大体分为两类（以比特币代表的单一用途和以以太坊为代表的面向应用的平台），当前以太坊生态正同时迎来两类重要机会——一类是已经趋向成熟、风险较低并能广泛带来金融价值的 DeFi（去中心化金融）产品；另一类是新颖、有创造力但尚处于早期的非金融应用（如预测市场、去中心化社交、ZK 身份等）。未来的发展会更多地将金融与非金融应用相结合，L1/L2 的界限和 B2B/B2C 的传统划分会变得模糊，去中心化与部分中心化（或半去中心化）之间需要务实权衡以保护用户并发挥链的优势；同时，AI 与区块链在小额支付、Agent-to-Agent（代理之间）支付等场景会有尝试，但高价值决策仍需谨慎。

# 3. 按照主题来梳理

## 3.1 应用的两条主线：低风险 DeFi 与创造性新应用

- 视频中首先把区块链世界按用途分为两类：一类像比特币那样主要做单一用途（价值储存/转移）的链；另一类以以太坊为代表，本身为了“推动开发者和用户在链上构建应用”而存在，是一个通用的应用平台。围绕以太坊上应用的发展，发言者提出当前有两条主要方向值得关注：低风险（low-risk）DeFi 和富有创造力的非金融应用。
- 低风险 DeFi 的定义与价值：所谓“低风险 DeFi”是指那些在以太坊上长期存在、经过时间考验、漏洞与攻击风险大幅下降、能够稳定服务用户并带来金融回报的去中心化金融产品。具体类型包括代币交易（token swaps）、借贷与放贷（lending/borrowing）、兑换（DEX）等，这些在传统金融中也存在，对用户的吸引点并非完全新颖的金融功能本身，而在于区块链带来的三个优势：全球可达性（全球用户可参与）、开源透明（协议公开，可审计）、人人可参与（既是用户也可作为开发者参与生态）。视频举例提到一些项目（如 Ave、Morpho、文件币等，按原文）并指出这些项目为许多用户提供了实际收益（例如提供美元或欧元计价的稳定收益率 3%-4% 这种数据在对话中被提及作为示例），并强调在全球大部分地区，能获得这种金融服务并不容易，因此 DeFi 提供了真实价值。
- 风险与成熟度的演进：对话指出早期（约三、四年前）DeFi 整体仍属于高风险新技术，漏洞与黑客事件频发（提到2019年黑客盗窃占 TVL 的约 5% 的数量级作为早期现象），但经过多年发展与安全审计、N 年的治理实践后，当前的低风险 DeFi 场景的损失率已经大幅降低（对话中提到现在可能不到 0.1% 或更低的百分比），显示出生态在走向成熟。发言者强调成熟不一朝一夕，需要时间，而现在“等久了”，低风险 DeFi 已经开始稳定发挥作用并扩大用户基础。
- 创造性非金融应用的崛起：另一类重要方向是那些并非直接金融的、但极具创造力的新应用，如去中心化社交（decentralalsocial）、预测市场（Polymarket 类型）、域名系统（ENS）、ZKID（零知识身份）等。对话指出这些应用在过去几年里发展较慢，但 2024 年出现了一些“突破”或“能见度提升”的例子（例如预测市场在主流媒体出现大量截图传播，从而体现出更广泛的社会关注度）。这些应用尽管目前规模普遍较小，但任何一种若找到合适的产品市场匹配（PMF）都有可能变大。发言者强调两类路线（低风险 DeFi 与创新非金融应用）对于以太坊生态都同等重要，且互为补充。
- 为什么两类并重很关键：对话强调，DeFi 的成熟一方面为很多用户带来直接可衡量的金融收益，另一方面为生态提供了基础的金融设施；而非金融应用则带来多样性与长期的“新用例”创新空间，两类合力能够吸引不同类型的用户与开发者，推动生态整体繁荣。视频中也表明，预测市场和 ZKID 等看似非金融的创新最终也可能与金融深度结合，从而催生新的金融模式或产品，这种金融—非金融的融合被认为是未来重要的发展方向。

## 3.2 ZKID（零知识身份）与金融+非金融融合的具体想象

- 什么是 ZKID（零知识身份）及其重要性：视频中多次提到“ZKID（零知识身份）”或“零知识证明（ZK）”相关的概念，强调其核心作用是“证明某些关于身份或历史的信息，而无需泄露细节”。在当下互联网与社交环境中，判断“谁是真人、谁是机器人、某人说的话是否属实”成为重要问题。ZK 技术提供了在不暴露敏感数据的前提下，证明某些属性（例如信用历史、教育背景、收入记录等）的能力，因此对建立信任、保护隐私非常关键。
- ZKID 在金融场景的应用举例：发言者特别用“UnderCollateralized Lending（无或低抵押贷款）”作为示例来阐明 ZKID 的潜在价值。传统的链上借贷多为 overcollateralized（超额抵押），即需要借款人先提供大量资产作为抵押，才能借到资金。这种模式限制了真正需要资金但缺少抵押品的人群（例如想创业但尚无资产的个人）。无抵押或低抵押贷款的关键挑战是信用判断：如何在全球去中心化平台上判断谁更可能还款？ZKID 可以让借款者以零知识证明的方式证明其某些可信信息（例如过往还款记录、收入的某个统计特征、受雇情况等），而不必把所有隐私暴露在链上，从而为信用评分与风险评估提供去中心化可验证的依据。结合 AI（例如用 AI 分析数据模型），可以用已有的数据与隐私保护的证明来评估借款信用，从而支持更大范围的无/低抵押贷款。
- 金融与非金融结合的更多想象：视频指出很多未来的区块链应用并非单纯金融或非金融，而常常是两者结合。举例：去中心化社交平台表面上是非金融的，但可以与代币化、粉丝经济（例如发售个人代币）结合，进而有金融属性；预测市场是信息产品，但其价值发现功能可以衍生金融化工具；而 ZKID 则是一个桥梁，把可信的身份/历史信息转化为可以在金融场景中使用的证据，从而打通更多应用。例如，一个来自阿根廷的创业者可能通过在链上基于 ZKID 的可验证信用，向全球募集早期资金（通过代币出售），这可能替代或补充传统 VC 路径。
- 现实中已有的早期端倪与风险：发言者提到链上曾出现过个人或主播通过发售个人代币获得收入（对话中举了 POMFAR、主播卖币的例子），这类现象展示了金融化与社交/内容创作结合的潜力，但同时也指出这并非完全等同于传统投资：购买个人代币既是情感/支持行为也带有投机投资的成分，存在很大风险。此外，发言者不回避 ZKID 与无抵押贷款这类创新的挑战：信用模型建构需要大量数据与谨慎设计，AI 的分析也可能出错或被攻击，因此在实践中需要逐步探索与严格的风险控制。
- 总结与前景判断：视频中总体判断是，ZKID 和零知识证明类技术在未来非常重要，既能直接应对当下互联网身份与隐私问题，也为新的金融服务（特别是跨境、去中心化的信用服务）提供基础设施。金融与非金融的结合将是许多未来应用的共同特点，新的融资模式（代币化早期融资，链上信用证明等）可能在数字化时代替代或补充传统 VC/投行主导的路径，但这需要时间与谨慎实践。

## 3.3 B2B / B2C 的模糊化：在区块链世界里的 L1、L2 与用户关系

- 传统互联网的 B2B 与 B2C 划分对比：在 Web2 时代，应用层通常明确分为面向企业（B2B）或面向消费者（B2C）的产品，许多平台通过提供 API（面向 B）和官方界面（面向 C）来区分角色与权限。视频提出问题：在 Web3 / 区块链领域，这种传统划分是否仍适用？以太坊等公链对开发者的定位究竟是面向企业还是面向消费者？
- 公链上的“平等地址”与权限同质性：视频强调区块链的一个核心特征是“任何参与者（个人或机构）在链上本质上就是一个地址，没有传统的特权差异”。无论是个人钱包地址、机构的多签（safe）地址、还是合约地址，链上交互的基本单元是一致的，机构并不会在协议层面拥有比个人更多的内建特权（尽管实际上他们可能通过规模或信誉享有优势）。这种“平等性”是区块链相较于 Web2 的一个根本差异，也导致 B2B 与 B2C 的界限变得不那么清晰。
- L1（Layer 1）与 L2（Layer 2）并非简单的 B2B/B2C 分工：对话中提出一种曾流行的看法：L1 作为基础层更像是 B2B，L2 更像是做消费者导向的扩展（B2C）。但发言者认为这种划分过于简单化。L1 与 L2 的选择更应基于“什么样的应用或用户更适配哪一层”，而非单纯把 L1 当作企业层、L2 当作用户层。实际上，L1 依然能支撑很多直接的用户应用（有用户直接在 L1 上使用钱包与合约），而 L2 也能同时为企业级或机构级服务提供扩展能力。因此，开发者应根据性能需求、成本、隐私、可验证性等具体要素来决定使用 L1 还是 L2。
- 对开发者与用户的实际影响：这种平等性与层的灵活选择给开发者和用户带来好处与挑战。一方面，任何组织都可以在同一生态下构建与参与，降低了进入壁垒；另一方面，界线模糊使得选择架构的决策更复杂，开发者需要根据用户类型（高频小额用户、机构级大额交易、跨链需求等）权衡使用哪一层并设计相应的安全与用户体验。
- 小结：视频强调不要用传统的 B2B/B2C 思维硬性套用到区块链中，L1/L2 的关系更像是工具箱里的不同工具，目标是根据场景匹配合适工具。区块链的开源和平等特性会继续削薄传统企业与个人在接入层面的差距，但应用层仍需考虑用户体验、合规与信任机制等具体设计问题。

## 3.4 去中心化、半中心化与用户保护：务实的权衡与现实案例

- 去中心化的理想与现实：视频里讨论去中心化时强调一个核心观点：基础协议层（L1）更应追求去中心化，以保持中立性、安全性与抗审查性；但在应用层面，完全去中心化并不总是最符合用户需求的做法。很多具体场景（如某些贷款、交易撮合、客服与合规需求）为了保护用户体验、合规与效率，可能会采用某些中心化或半去中心化的设计。
- 半中心化的合理性举例：发言者举例说明在实际应用中常见的情况：稳定币（stablecoin）通常涉及中心化的资产托管或发行实体（如公司或托管机构），因此并不能宣称是百分之百去中心化；类似地，一些需要人工判断或信任中介的金融服务（特别是无抵押贷款）在实践中往往需要某种形式的信任机制或中心化组件来初期运作。发言者认为这并非完全丧失区块链价值，而是现实中务实的选择：如果把 L1 的去中心化优点放在一边完全忽视应用层发生的事情，可能会导致 L1 的优势名存实亡。
- 电子邮件类比说明去中心化的落地难题：视频里用电子邮件协议（理论上去中心化）做类比：尽管 SMTP 等协议允许任何人运行邮件服务器，但现实中小型邮件服务器往往被大型平台（如 Gmail、Outlook 等）所主导，小服务发送的邮件常常被标记为垃圾邮件或被拒收。这个例子说明，即使协议是去中心化的，现实中的生态规则、信誉体系与用户习惯会导致去中心化效果受限。对区块链而言，若应用层完全放任不管，也可能出现类似问题：小型 L2 或服务若治理与退出机制设计不当，用户资产可能难以保护。
- L2 失败与用户退出权：视频指出 L2 作为扩展解决方案有实用优势，但历史上已有许多 L2 或扩展方案失败的案例（对话中提到“很多L2在很多年内失败”的经验），关键问题在于在 L2 失败时用户能否安全地把资产提到 L1。如果 L2 设计允许用户在合约层面直接凭证据在 L1 上提取资产，那么即便中心化运营方失败，用户仍有自救路径，这正是链上与链下设计结合的安全优势。也就是说，在应用层采用某些中心化或运营化实践时，需要在协议层保留足够的用户保护机制（如对用户的退出权、链上可证明的提款路径）以避免对用户造成无法挽回的损失。
- 总结性的权衡立场：视频提出一种务实观点：L1 必须尽力保持去中心化，但应用层可以视场景采用部分中心化以改善用户体验与合规性；关键在于设计透明的权责与技术保障，确保用户在运营方失误或恶意时仍保有基本的救济手段与资产安全。最终目标是既不放弃去中心化带来的结构性优势，也不盲目拒绝实际环境下可行的中心化机制。

## 3.5 AI Agent 与链上支付：小额自动化与高风险谨慎

- Agent-to-Agent（代理到代理）支付标准与趋势：视频最后讨论了近期一些机构（例如 Google、EF 等）联合发布的 Agent-to-Agent 支付标准（在对话中被称为 “Agent to Agent 的 Payment”），并探讨 AI 在未来支付流程中扮演的角色。发言者认为在未来 5-10 年内，AI 会在许多“常规/低风险”的自动化任务中发挥巨大作用，但对于“大额、高风险”的直接自动化付款则需非常谨慎。
- AI 在支付中的适用场景与风险控制：具体而言，AI 可以很好地处理小额、频繁、可规则化的支付确认（例如定期订阅、微支付、自动补货付款等），并作为一种额外的风控（类似 2FA）来检测异常或潜在的欺诈行为。然而，把 AI 赋予直接支付高额资金的权限会带来巨大的安全风险：AI 模型可能被对抗性输入欺骗（视频举例提到某些研究者不断发现主流 AI 的漏洞），因此不适合完全自动化处理高价值交易。
- 实践上可采用的混合模式：发言者建议一种折中策略：AI 可作为决策支持或初步检查工具，对小额交易直接认可；对于高额或敏感交易，引入额外的人类确认、多方签名、链上多重签名（multi-sig）或 2FA 等机制，或将 AI 的判断作为参考而非最终授权。这种“AI + 人/多签”的混合模式能在提高效率的同时保留必要的安全阀。
- 对区块链与 AI 的结合前景判断：总体上，视频里对 AI 与区块链结合持乐观但谨慎的态度。AI 能提升很多流程自动化与可扩展性（如自动化合约执行、风险评估、信用评分辅助等），但若过早放开自动化权限则可能带来被攻击或误判的后果。因此未来十年将是探索与逐步放权的阶段，边界的划定与监管/安全实践会非常关键。
- 小结：AI 与链上支付结合会先从小额、自动化场景切入，随着技术与攻防理解的成熟，再扩展到更高价值的领域，同时始终保留人为或多重签名等安全措施作为最后防线。

# 4. 框架 & 心智模型（Framework & Mindset）

- 框架一：双轨并行的应用策略（Two-Track Application Strategy）
    - 核心思想：在以太坊等通用链上，生态应同时扶持“成熟的、低风险的 DeFi 基础设施”与“富有创造力的非金融创新”。这不是二选一的关系，而是互为补充、协同演化的两条主线。
    - 步骤/要点：
        1. 识别已趋稳的“低风险 DeFi”领域：选择那些经过时间检验、安全事件显著下降、并对用户带来明确金融价值的产品（如稳定收益、可靠的借贷/兑换服务）。优先投资于安全性、流动性与合规性，降低系统性风险。
        2. 保持长期耐心扶持新型应用：对预测市场、去中心化社交、域名系统（ENS）、零知识身份（ZKID）等创新要有长期视角。虽然短期规模小，但可能带来颠覆性的用户体验或新的金融—非金融融合场景。
        3. 促进两者融合：探索 DeFi 基础设施如何支持非金融应用的货币化（如社交代币、去中心化创作激励），以及非金融应用如何为 DeFi 提供新用例（如信息发现、身份验证）。
        4. 风险管理并行：对成熟 DeFi 继续强化安全审计与保险机制；对新兴应用做分阶段试验，制定可控的上线与资金规模限制，避免系统性扩散风险。
    - 心态：既要对成熟基础设施“稳健保守”，又要对创新领域“耐心开放”，把时间与资源分配为短期可收回价值与长期潜在爆发并重。
- 框架二：协议层去中心化，应用层务实混合（Protocol Decentralization + Application Pragmatism）
    - 核心思想：保持 L1 的去中心化中立性是区块链价值的根基，但在应用层可以采用半去中心化或中心化的机制以满足用户体验、合规与效率需求，同时在协议层设计必要的用户保护机制来防止运营方失误或恶意行为侵害用户资产。
    - 步骤/要点：
        1. 在设计 L1 时优先保证中立性、安全性与可验证的退出/救济路径（例如在 L2 失败时用户能在 L1 上提取资产）。
        2. 在应用层评估是否需要中心化组件：若基于效率/合规需要引入中心化元素（例如 KYC、托管、人工仲裁），同时明确这些组件的责任边界并在合约层保留链上可审计与退款/撤出的技术保障。
        3. 设计透明的信誉/白名单体系：让市场与其它参与方可以基于公开信息判断中心化组件的可靠性，从而减少单点信任风险。
        4. 在用户教育与 UX 层面清晰标注去中心化程度，避免用户误认为某些中心化机制具有“链上的不可变性”。
    - 心态：务实、透明与以用户资产安全为第一优先项；在权衡中心化时始终考虑“可退出性”和“对用户的最坏情形保护”。
- 框架三：技术与治理并行演化（Tech + Governance Co-evolution）
    - 核心思想：区块链应用的成长不仅依赖技术创新（如 ZK、L2 扩展），也需要治理机制（社区治理、代币经济、法律合规）与用户行为的演化同步改进。
    - 步骤/要点：
        1. 在引入新技术（如 ZKID、自动化 Agent 支付）时，同时设计相应的治理流程——谁有决策权、如何升级、如何处理滥用。
        2. 在代币化和融资模型（如发售个人或项目代币）中，明确权益与信息披露规则，防止投机驱动的道德风险。
        3. 通过分阶段试点、审计与社区反馈来迭代治理规则，确保新机制在真实环境下可适应并可纠错。
        4. 把 AI 的引入视为治理工具的一部分：AI 可用于监测异常、辅助合规，但应当有明确的人类干预路径与责任分配。
    - 心态：技术乐观但治理敏感；新机制需同时接受技术安全与治理审视，才能长期健康发展。

# 总结

本次对话围绕以太坊与区块链应用的未来，提出了“并轨发展”的观点：既要稳健推进低风险的 DeFi 成熟化与普惠金融价值，也要持续扶持富有创造力的非金融应用（预测市场、去中心化社交、ZKID 等），并关注金融与非金融的深度融合。L1 的去中心化中立性需维护，而应用层则应在用户体验、合规与安全之间做务实权衡，保留技术上的用户救济路径以防运营方失败。AI 在支付与自动化场景中具备巨大潜力，但高价值自动化仍需谨慎。总体态度是既乐观于技术与模式创新，也强调时间、治理与风险管理的重要性。
