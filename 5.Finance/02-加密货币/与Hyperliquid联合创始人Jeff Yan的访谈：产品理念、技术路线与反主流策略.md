# 2. Overview

本视频主要围绕 Hyperliquid（简称 HL）联合创始人 Jeff Yan 的创业历程、产品理念与对加密金融（DeFi）未来的判断展开。核心论点是：当前中心化交易所的系统性风险暴露（如 FTX 崩盘）为去中心化金融提供了加速器，Hyperliquid 致力于构建“可被普通用户直观使用、性能可匹配中心化交易所”的去中心化层一（L1）链与链上永续合约交易所，并以“社区优先、不从服务活动直接抽取交易费、不接受传统风投控股”等反主流路径来实现长线价值捕获。Jeff 强调以用户为中心（user-centric／Bezos 式思路）、技术优先与长期主义，并把 HL 设想为“流动性领域的 AWS（亚马逊网络服务）”，通过 Builder Codes 等机制让构建金融应用的开发者直接利用 HL 的原生流动性与基础设施，从而催生“以产品与用户价值驱动”的生态。

# 3. 按照主题来梳理

## 3.1 创业背景与早年轨迹（如何从量化交易转到构建 Hyperliquid）

- Jeff 的早期职业背景主要在做高频/量化交易（Quant Trading、Market Making）。他最初接触加密市场的方式是写一些简单脚本，研究中心化交易所的价差与低效性。早期市场相比现状更不竞争，给了他“快速验证策略”的机会。通过不断把策略工程化、把 Python 脚本推进到生产级别（latency-sensitive 的交易系统），他学会了如何搭建应对高并发、低延迟、处理真金白银风险的系统——这是构建 Hyperliquid 非常关键的能力。
- 他强调了从“写分析脚本”到“写生产级交易系统”的差别：前者侧重于策略思想与统计回测，后者需要工程化、可靠性、日常运维与风险控制。做 Market Making 时面临的技术与运营风险（代码出错、系统崩溃带来资金损失）让团队积累了应对实盘与高资金周转的经验。这些经验后来成为他们决定把交易系统、流动性机制以及基础设施搬到链上（即去中心化实现）时的重要资本。
- 促成转变的外部事件：FTX 崩盘是一个关键的“点火事件”。Jeff 认为这件事让公众与机构都看见中心化交易所的深层风险——并非抽象理念，而是真实的资金损失与信任破裂。那一刻对他的团队来说，是“世界准备好进入 DeFi 的信号”。尽管人们后来部分回流中心化平台，但这一事件为 Hyperliquid 提供了“启动动力”与产品方向的社会合理性。
- 从个人动机到团队决策：Jeff 提到他曾“短暂退休、环游世界”并尝试过以套利和量化策略“复制成功然后放松生活”的方式，但他发现自己更喜欢不断做难题、忍受日常痛苦以获得更深层次成就感。因此他从量化交易转向构建可以影响整个金融基础设施的长期项目，既带来技术上的延续（对流动性、撮合、风险管理的理解）也带来使命上的升级（构建可持续、信任度高的链上金融基础设施）。

## 3.2 Hyperliquid 是什么：产品定位、核心功能与对用户的承诺

- 对普通用户的解释（给妈妈讲解版）：Hyperliquid 是一个把“链上”与“Web2 金融体验”结合起来的系统。它目标是让用户在去中心化的前提下，仍能享受到“低成本、即时结算、可集成、可以在应用里无缝使用”的金融服务，且流动性与交易体验可与中心化交易所相媲美。换言之，HL 要让用户既能“掌控自己资产”、又不必在体验上做太多妥协。
- 核心产品构成：Hyperliquid 并非单一产品，而是一个包含多层的系统。
    - 原生 L1：提供链级的性能与状态机器（相较传统 EVM 或其它 L1，有专门针对金融应用优化的原生组件）。
    - 链上订单簿（on-chain order book）与永续合约（perpetuals）交易引擎：目标是把中心化交易所的做市深度、撮合性能以去中心化、可验证的方式实现，且支持高吞吐、低延迟的交易体验。
    - Builder Codes：一种鼓励第三方应用在 HL 之上构建并能直接使用 L1 原生流动性的机制（见后文专门展开）。
- 用户承诺与差异点：
    - 不抽取交易费作为团队收入：Jeff 明确表示 HL 团队不从增加的链上活动中直接抽成交易费，而是把收入/回报直接回馈给社区（视频中提到超过 2500 万美元收入返还社区的例子）。这种做法是在 DeFi 语境下「社区优先、用户优先」的极端演绎。
    - 产品导向：HL 更注重打造真正好用的金融基础设施，而不是依赖营销、发行代币或早期风投助力拉高估值的“造币游戏”。目标是提供 10x 甚至更高的体验改进，以吸引用户自然迁移。
    - 长期主义：借鉴 Amazon（AWS）做法，把基础设施优先做好，让其它开发者在其上构建真正的产品。HL 要成为“流动性的 AWS”，抽象复杂的撮合与流动性问题，让应用开发者专注业务与用户体验。
- 对风险与信任的处理：相比传统中心化平台，HL 希望通过链上治理、透明协议逻辑与把收益返还社区的方式，来建立信任。FTX 崩盘之后，人们对中心化信任链的警觉让这种链上透明性与非托管特性更受重视。

## 3.3 不募资、不抽手续费的策略与背后逻辑（社区优先与反提取）

- Jeff 解释他们为何选择不用传统 VC 早期控股与为何不把交易费作为团队直接营收流。
    - 路径依赖与所有权问题：如果早期的 VC 或若干大机构在网络早期占据过高份额（例如持有 50% 代币或控制很多治理权），这会在长期成为网络的“伤疤”。尤其当目标是把金融服务的控制权从中心化机构向终端用户下放时，早期集中化的所有权结构与利益分配会破坏这一目标。
    - 长期主义与扩张策略：类似 Amazon 在早期放弃利润以换取市场与基础设施扩张的做法，HL 选择把可得的利润回流给生态与用户，目的是最大化长期价值与网络效用，而不是短期财务回报给创始团队或早期投资者。
    - 反对行业的“提取”文化：Jeff 描述加密圈一个长期问题是“从零和或不成熟用户中抽取价值”的文化（ICO 泡沫、代币发行给早期强关系方、中心化交易所与项目之间的幕后交易等），他认为这种文化在摧毁行业长期信任，所以 HL 的选择是做“另外一种示范”来吸引理性用户与长期建设者。
- 实际效果与挑战：
    - 好处：能赢得那些因中心化崩盘而失去信任的用户、吸引想做长期产品的开发者、创造更广泛的参与感与网络效应（因为不同参与者更信任协议规则与收入分配）。
    - 挑战：缺少外部资金会带来“烧钱”的压力（Jeff 自述团队是自筹、烧钱并且增长的），以及在需要快速市场推广、招聘、法务合规时可能面临资源受限。同时，不收费用或放弃立刻变现会让短期内的商业可持续性存在风险，需要依赖未来协议本身的价值自然回流（例如生态增长、代币模型、其他长期变现路径）。
- 与行业对比：Jeff 指出很多项目通过早期代币抛售或“给大玩家低价配售”来筹集资金并形成短期利益，这种方法看起来合法但本质可能还是“对零售提取”。他认为 HL 的模式在 DeFi 历史上并不常见，是一种对现有提取路径的挑战性实验。

## 3.4 技术路线：为什么要自己做 L1、链上订单簿与 Builder Codes 的意义

- 为什么 HL 要做自己的 L1：Jeff 和团队早期评估了现有链（如以太坊、Solana、Cosmos 子链、DYDX v4 方案等），发现没有任何一个现成平台能同时满足他们对“低延迟、高吞吐、链上订单簿原生支持以及金融原语（primitives）高性能实现”的需求。许多现有链的抽象（例如把一切当作通用智能合约）在效率与确定性上不足以支撑高性能的链上永续与撮合引擎。因此团队选择在 L1 层提供针对金融应用优化的原生构件，使上层应用可以享受近于中心化交易所的体验。
- 链上订单簿 vs AMM：传统 DeFi 的自动做市商（AMM，Automated Market Maker）在简化流动性提供、资产交易上有极大贡献，但在衍生品撮合、深度做市、低滑点大额交易与高频撮合方面存在局限。链上订单簿目标是把中心化交易所的撮合逻辑（订单薄、挂单撮合、限价/市价等）以链上方式实现，同时解决去中心化可审计与用户自持私钥的信任问题。
- Builder Codes 的定位与工作方式：
    - 定义：Builder Codes 是一套允许任何前端或协议在 HL 链上接入并使用原生订单簿流动性的“后端中立”接口/机制。它把链上流动性做成可复用的基础服务（类似 AWS 的 API），任何想做地域性交易所、钱包内交易、社交交易或其它金融应用的开发者可以直接把交易流量与用户撮合到 HL 的原生流动性池中。
    - 作用：让专业做产品/前端体验的团队（他们知道本地用户、语言、商业化路径）专注做界面与用户获取，不必自己去做全部的流动性和撮合基础设施。这降低了构建复杂金融产品的门槛，鼓励垂直化与地域化的生态繁荣。
    - 商业模型与治理：Builder Codes 的设计目标是让构建者能“按贡献获取收益”，直接从他们带来的交易量中获利，而不是通过幕后不透明的交易费返佣。这样可以把应用方的商业利益与协议的长期健康对齐。
- 建设三合一的难度：Jeff 形容他们是在“硬模式下”同时构建三类系统：高性能 L1、可编程链上订单簿撮合引擎，以及面向开发者友好的抽象与 SDK（即 Builder Codes）。这意味着大量底层研究、实现、优化、以及产品体验打磨工作，难度与技术风险都极高，但一旦成功，会有乘数级的影响。

## 3.5 个人心态、长期主义与团队文化（为什么要“受苦”与如何看待创业）

- 受苦是驱动力：Jeff 直言自己对“长期、艰难的工作”有很高容忍度，他把日常的“苦”视为必需的磨砺，若没有这种持续痛苦会引发更大的“==存在性焦虑”（existential dread），他宁可把痛苦用于创造而非虚度。做难事能带来显而易见的收获感：回头能说“我们留下了些有意义的东西”==。
- 第一性原理与反常识：Jeff 强调团队常常从第一性原理出发质疑行业的“常态做法”（如广泛依赖市场制造商、风投入股、扩张营销等）。在 HL 的设计里，他们选择反直觉的方式（不募资、不设置隐秘利益方、把收益返还社区），这种选择源自对长期目标的判断，而非迎合短期流量与估值。
- 对“赚钱动机”的看法：Jeff 认为没有什么问题是因为人们最初进入加密是为了赚钱；市场机制允许“自私的人在规则下创造通用价值”。量化或做市作为把才能转化为金融优势的方法，并不丢脸。重要的是用这种能力去创造能持续惠及用户与生态的东西，而不是仅仅把钱提取走。
- 软技能与精神调适：他曾一度对社交媒体（如 Crypto Twitter）和外界的评价非常敏感，但后续学会少看并把社交媒体与团队内部职责分离，让更善于应对外界的团队成员处理公共关系，自己则专注产品实现。这是典型创始人在心态管理上成熟的表现——把注意力集中在能产生长期回报的事情上。
- 对“短期满足感”的反思：Jeff 认为许多人误以为“达到某个财务目标或早退休”会带来长期幸福，但体验显示短暂的自由过后会陷入无意义感。他认为选择“==有目标、有贡献的受苦==”能带来更持久的满足感。对他而言，构建 Hyperliquid 是既充满挑战也富有意义的“长期苦修”。

# 4. 框架 & 心智模型（Framework & Mindset）

- 第一性原理（First-principles thinking）作为决策核心：
    - 解释与应用：Jeff 强烈强调把每项决策回到最基本的问题上：我们要解决什么真实的问题？谁是真实用户？什么架构能长期可持续地满足用户需求？不盲从行业“参考答案”，而是拆解问题（例如为什么现有 L1/DEX 无法满足高性能永续合约？订单簿为什么不在链上？）并从头设计解决方案。
    - 实际体现：拒绝走传统筹资与市场化路径（不以 VC 为中心、不以短期市场推广为导向），而是把资源优先投入到能提升用户体验与基础设施性能的工程上。这一心智模型驱动他们去做“高难度但根本”的技术工程，而非可快速投机的表面工程。
    - 好处与风险：能产生长期差异化竞争力（例如 HL 的链上订单簿、原生金融基础设施），但短期内会面临资源压力、市场怀疑与更高的实现风险。
- 用户至上与“基础设施为先”框架（User-centric + Infrastructure-first）：
    - 灵感来源：以 Jeff Bezos 与 AWS 的做法为类比，HL 把“让第三方开发者能构建产品”放在优先位置。AWS 的核心是把复杂的硬件/运维抽象化，HL 的目标是把复杂的流动性、撮合、永续合约机制抽象化为可被安全调用的链上服务（Builder Codes）。
    - 实践要点：先把链与撮合做稳做快，然后提供 SDK/API 与经济激励，让前端团队去做地域化与产品化工作。对内：投入工程资源打磨底层性能与安全；对外：把收益与治理尽量透明，最大程度把用户作为协议的核心利益承载者。
    - 适用场景与边界：适合那些希望形成长期网络效应、需要大量第三方应用接入的基础设施类项目。但若短期目标是快速套利或制造流量，这套框架难以奏效。
- 反提取（Anti-extractive）与社区优先模型：
    - 本质：与传统“先募资、先分配代币给早期利益方、后发行给公众”的商业路径相反，HL 的原则是让协议价值更多回流给真正的长期用户、构建者与使用者，避免早期过度集中化的所有权模式。
    - 具体措施：团队不从交易费中直接抽取、把部分收入回流社区、避免把治理或价值过早集中到少数投资者手中。经济上，这意味着短期牺牲（放弃可即时变现的收益），但长期可能带来更高的用户信任与更广泛的采用率。
    - 对行业影响：此模型旨在改变加密行业普遍的“抽取流行病”（ICO、操纵上市、内幕配售等），用透明与用户对齐来修复行业声誉，从而降低监管与用户阻力。
- 产品导向的增长（Product-led growth）而非营销/代币驱动的增长：
    - 理念：真正持久的用户迁移不是通过大规模空投、炒作或营销，而是通过“产品足够好”——满足用户未被满足的切实需求（更低成本、更快捷、更可信的跨境转账、对冲、借贷与交易体验）。
    - 操作步骤：识别真实痛点（如在高通胀国家对价值储存的刚需），做出适配本地用户的前端体验（语言、法币通道、本地合规），并把这些前端与 HL 的原生流动性结合，使价值自然通过产品体验传递并转化为长期活跃用户。
    - 风险控制：在产品导向的同时要兼顾经济激励（例如 Builder Codes 的收益分享），防止“免费好产品却没人赚钱”的悖论导致开发者离开生态。

# 总结

视频核心传达的是：Hyperliquid 不只是另一个 DeFi 项目，它试图用长期主义与工程为先的方式，解决链上金融长期以来的性能、流动性与信任问题。Jeff Yan 把自己从量化交易转向基础设施构建的轨迹，展示了如何把对市场低效的敏锐（从套利到做市的理解）转化为设计高性能链上金融系统的能力。Hyperliquid 的差异化在于：做底层 L1 与链上订单簿、坚持社区优先（不依赖传统 VC 与不从交易费直接获利）、推出 Builder Codes 为上层应用解锁流动性。这既是技术挑战，也是对行业商业模式与伦理的一种反思与实验。视频也反复强调，真正驱动迁移到去中心化金融的，不是空喊的价值观，而是“产品够好、体验够好、且能为用户带来实在好处”的那一天。
