## 1. 基本概念

### 钱包（Wallet）

- **定义**：一个软件或硬件工具，用于**生成、管理和存储加密货币的私钥、公钥及地址**。钱包不直接存储资金，而是控制区块链上的地址。
- **类型**：
    - 热钱包（在线，如手机App）：方便但安全性较低。
    - 冷钱包（离线，如硬件设备）：更安全，用于大额存储。
- **核心功能**：签名交易、查看余额、发送/接收资产。

### 账户（Account）

- **定义**：钱包生成的**特定地址（公钥派生），对应一组私钥，用于持有和交易资产**。每个账户有独立的余额和交易历史。
- **表示**：通常是一个字符串地址，例如ETH的`0x123...abc`。
- **特点**：每个账户可视为 **“子钱包”**，**独立操作但受钱包整体控制**。

---

## 2. 钱包与账户的关系

**核心关系**：**一个钱包可以管理多个账户**。

- 钱包像“容器”或“文件夹”，账户像里面的“文件”或“子文件夹”。
- 通过一个统一的“种子”（助记词）生成所有账户，确保一致性。

### 视觉化表示（基于用户截图示例）

| 钱包名称         | 包含账户      | 示例余额/状态 | 对应地址示例        |
| ------------ | --------- | ------- | ------------- |
| **Wallet 1** | Account 1 | US$1.59 | `0xAbC...123` |
|              | Account 2 | 未显示     | `0xDeF...456` |
| **Wallet 2** | Account 1 | 未显示     | `0xGhi...789` |

- **为什么多个账户？**
    - **隐私**：**用新地址接收资金，避免交易追踪。**
    - **隔离**：不同账户用于不同目的（如交易 vs. 持有）。
    - **多链支持**：同一钱包生成ETH、BTC等链的地址。

**类比**：钱包 = 皮夹子；账户 = 皮夹子里的多张银行卡。每张卡有独立卡号（地址）和余额，但都由皮夹子统一管理。

## 3. 底层实现原理

加密货币钱包的底层基于**分层确定性钱包（HD Wallet）标准****，主要遵循BIP-32**（分层派生）、**BIP-39**（助记词）和**BIP-44**（多币种路径）。这些是比特币改进提案（Bitcoin Improvement Proposals），被以太坊等主流链采用。

### 3.1 核心组件

- **助记词（Mnemonic Phrase）**：12/24个英文单词（如“apple banana cat...”）。这是钱包的 **“根密钥”**，用户备份的核心。
- **种子（Seed）**：从助记词通过 PBKDF2（密码派生函数）+ HMAC-SHA512 哈希生成一个**512 位随机种子**。
- **主私钥（Master Private Key）**：从种子通过 HMAC-SHA512 派生：`Master Key = HMAC-SHA512("Bitcoin seed", Seed)`。
- **派生路径（Derivation Path）**：树状结构，用于生成子密钥。格式：`m / purpose' / coin_type' / account' / change / address_index`。
    - 示例（BIP-44 for ETH）：`m/44'/60'/0'/0/0` → Account 1。
    - 每个路径生成一对私钥/公钥。

### 3.2 密钥生成流程（分层确定性派生）

1. **生成种子**：
    - 输入：**用户随机熵（128-256位） → BIP-39 → 助记词 → PBKDF2（盐："mnemonic" + 可选密码） → 种子（512位）。**
2. **主密钥派生**（BIP-32）：
    - `IL = HMAC-SHA512(Key = "Bitcoin seed", Data = Seed)[:32]`（左半为链码，右半为主私钥）。
3. **子密钥派生**（CKD - Child Key Derivation）：
    - 从主私钥递归派生：`Child Private Key = Parent Private Key + HMAC-SHA512(Parent Chain Code, Parent Public Key || Index)[:32]`。
    - **硬化（Hardened）**：Index ≥ 2^31，使用私钥哈希，确保子密钥不可从公钥逆推（安全性高）。
    - **非硬化**：用于公钥派生（轻钱包场景）。
4. **地址生成**：
    - 私钥 → **ECDSA（椭圆曲线数字签名算法，secp256k1曲线）** → 公钥。
    - 公钥 → **Keccak-256哈希（ETH） → 取后20字节 → 添加**`**0x**`**前缀** → 地址。
    - 示例（简化伪代码）：
```plain text
Private Key (256位随机)
↓ (ECDSA secp256k1)
Public Key (未压缩: 04 + x + y)
↓ (Keccak-256)
Hash[: -20:] (后20字节)
↓
Address: 0x + hex(20字节)
```

### 3.3 为什么“确定性”？

- **HD特性**：用同一种子，总能重现相同密钥树。丢失设备？用助记词恢复所有账户！
- **安全性**：私钥永不暴露；派生使用单向哈希，防逆推。
- **多账户实现**：增量Index（如`/0/0` → Account 1；`/0/1` → Account 2），无限扩展。

**图示流程**（文本版）：

```plain text
助记词 (BIP-39)
↓ PBKDF2 + HMAC-SHA512
种子 (512位)
↓ HMAC-SHA512 ("Bitcoin seed")
主私钥 + 链码
↓ CKD (BIP-32, 路径 m/44'/60'/0'/0/0)
Account 1: 私钥1 → 公钥1 → 地址1
↓ CKD (路径 m/44'/60'/0'/0/1)
Account 2: 私钥2 → 公钥2 → 地址2
...
```

## 4. 实际用途与注意事项

### 用途

- **备份**：只备份助记词，即恢复整个钱包（所有账户）。
- **导入/导出**：助记词兼容多数钱包；单个账户可导出私钥（不推荐，风险高）。
- **多设备同步**：用同一助记词在新设备生成相同地址树。

### 注意事项

| 风险 | 防范措施 |
| --- | --- |
| **助记词泄露** | 手写纸备份，离线存储；永不截屏/在线分享。 |
| **私钥暴露** | 避免导出单个私钥；用硬件钱包签名。 |
| **路径不匹配** | 不同钱包可能用不同BIP路径（e.g., Ledger vs. MetaMask），导入前确认。 |
| **量子威胁** | 未来升级到后量子签名；当前secp256k1安全。 |

**小贴士**：测试恢复——新建钱包，记下助记词，删除后用其恢复，确认所有账户出现。
