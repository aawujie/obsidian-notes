## 总览

QuantSkills 12 技能包是一套面向 AI Agent（Claude Code / Codex / OpenClaw / Cursor）的量化投资技能集合。每一个 Skill 对应一个量化团队中的"岗位角色"，12 个 Skill 覆盖了从数据获取 → 数据仓库 → 选股 → 个股尽调 → 风险预警 → 复盘 → 估值轮动 → 研报复现 → 因子生成 → 因子挖掘 → 形态识别 → 回测的完整投研闭环。

**数据后端**：所有数据类 Skill 依赖 **Pandadata**（`panda_data` Python SDK），185 个数据接口，需配置 `~/.pandadata/pandadata.env` 凭证。

**设计哲学**：
- 每个数字可溯源到来源接口、参数、数据日期
- 事实与解读分开（先列数据，再给观点）
- 数据缺失时标注"数据缺失"，不混入严格计数
- 接口签名一律从 `pandadata-api` skill 查询，不靠记忆

## 12 个 Skill 逐一详解

### 1. pandadata-api — 数据接口工程师

| 维度 | 详情 |
|:---|:---|
| 定位 | 把自然语言数据需求路由到正确的 Pandadata API，生成可直接运行的 Python 代码 |
| 覆盖 | **185 个数据接口**，7 大数据域 |
| 核心原则 | Prefer the bundled reference over memory（先查文档，再回答） |
| 数据域 | A股、期货、期权、宏观、行业/特色、港美股、指数 |
| 依赖 | 无（基础 Skill，其他 Skill 的数据契约来源） |
| 状态 | ✅ stable, runnable, official |

**7 大数据域速览**：

| 数据域 | 代表接口 | 说明 |
|:---|:---|:---|
| A股数据 | `get_stock_daily` `get_stock_dividend` `get_fina_reports` | 行情、概念行业、资金、公司行为、财务 |
| 期货数据 | `get_future_daily` `get_future_dominant` `get_broker_netmarg` | 行情、主力合约、DeepView 持仓席位 |
| 期权数据 | `get_option_daily` `get_option_implied_volatility` | 期权信息、日线、波动率 |
| 宏观数据 | `get_macro_na` `get_macro_cal` | 中国/国际宏观、行业、特色数据、经济日历 |
| 港美股数据 | `get_hkus_daily` `get_us_daily` | 港美股日线、分钟线、财务 |
| 指数数据 | `get_index_daily` `get_index_valuation` `get_index_weights` | 指数行情、估值、成分权重 |
| 资金面数据 | `get_money_flow` `get_northbound` `get_margin` `get_block_trade` | 资金流向、北向、两融、大宗交易 |

**该 Skill 本身不执行数据拉取**，而是作为"翻译层"：Agent 根据用户自然语言需求 → 查文档 → 找到精确的 `panda_data.get_xxx()` 方法名、参数、返回字段 → 生成 Python 代码。

### 2. pandadata-warehouse — 数据仓库工程师

| 维度 | 详情 |
|:---|:---|
| 定位 | 把 Pandadata 行情数据增量下载到本地 DuckDB + Parquet 仓库 |
| 覆盖 | A股/指数/期货/期权/港美股日线分钟线、复权因子、研究因子、交易日历 |
| 技术栈 | DuckDB + Parquet 分区存储 |
| 依赖 | `pandadata-api`（接口契约） |
| 状态 | ✅ stable, runnable, community |

**核心能力**：

- **增量刷新 + 水位线**：以最新完整交易日为水位，只补缺失的交易日；历史可变数据集（如前复权价、因子表）整分区重写
- **失败可续传**：失败分区记录在元数据里，成功分区原样保留，绝不静默删除
- **Parquet 分区 + DuckDB 视图**：数据落在分区 Parquet 文件，DuckDB 建视图查询，不复制进数据库
- **九大表族**：日线、分钟线、复权因子、财务、指数、期货、期权、港美股、研究因子

**使用场景**：回测、因子研究、批量报告等需要反复查询同一份数据的场景，避免重复调用 API 产生费用和延迟。

### 3. market-daily-review — 收盘复盘员

| 维度 | 详情 |
|:---|:---|
| 定位 | 收盘后一句话生成 A 股当日复盘报告 |
| 输出 | 固定 7 章结构 Markdown 报告 |
| 依赖 | `pandadata-api`（数据契约） |
| 状态 | ✅ stable, runnable, official |

**7 章报告结构**：

| 章节 | 接口 | 产出 |
|:---|:---|:---|
| 1️⃣ 指数与估值 | `get_index_daily` `get_index_valuation` | 主要指数涨跌幅、PE/PB 分位 |
| 2️⃣ 市场宽度 | `get_stock_daily` | 涨跌家数、涨停跌停数、成交量 |
| 3️⃣ 行业与概念 | `get_industry_daily` | 行业涨跌排名、概念热点 |
| 4️⃣ 龙虎榜与大宗 | `get_lhb` `get_block_trade` | 龙虎榜上榜、大宗交易 |
| 5️⃣ 两融与北向 | `get_margin` `get_hsgt_hold` | 两融余额变化、北向加减仓前列（T+1 标注） |
| 6️⃣ 风险提示 | — | 关键风险事件汇总 |
| 7️⃣ 数据说明 | — | 接口、数据截止、缺失/降级说明 |

**特色功能**：
- 内置校验脚本 `validate_report.py`：检查章节完整性、数据来源标注、免责声明
- 支持**定时自动生成**：交易日 18:30 后自动产出（等两融/北向数据落库）
- **幂等**：当日报告已存在时重新生成覆盖

### 4. index-valuation-rotation — 市场配置分析员

| 维度 | 详情 |
|:---|:---|
| 定位 | 指数估值分位 + 行业轮动分析 |
| 核心输出 | 估值温度计、行业动量排名、轮动信号、定投参考 |
| 依赖 | `pandadata-api`（数据契约） |
| 状态 | ✅ stable, runnable, community |

**核心能力**：

- **估值温度计**：计算 PE/PB 历史分位（如"当前 PE 处于近 5 年 78% 分位"），输出宽基指数定投参考
- **行业轮动**：20/60/120 日动量排名，识别行业强弱切换
- **事实与解读分开**：先给分位和排名，再把配置/定投/轮动观点标注为"研究解读"
- **每个数字可追溯**：标注接口方法、参数、数据窗口、最新数据日期

**触发词**：指数估值分位、现在贵不贵、估值温度计、宽基指数定投参考、行业轮动、行业动量排名

### 5. stock-screener — 选股员

| 维度 | 详情 |
|:---|:---|
| 定位 | 自然语言 → 标准化筛选漏斗 → 带依据的股票清单 |
| 筛选维度 | 分红、估值、质押、北向、行业/概念、财务增长、股东变化、风险排除 |
| 依赖 | `pandadata-api`（数据契约） |
| 状态 | ✅ stable, runnable, community |

**核心机制 — 筛选漏斗**：

```
全市场 → 行业/概念池 → 行情过滤 → 财务过滤 → 质押/解禁/股东（逐股查询） → 输出清单
```

执行顺序按**筛除率与 API 成本**排：先跑批量便宜的池过滤，再跑行情和财务，质押/解禁/增减持/十大股东只对幸存池执行。

**关键能力**：

- **条件原子化**：每个条件解析为标准过滤器（指标、运算符、阈值、时间窗、日期口径、缺失数据策略）
- **歧义自动确认**：如"连续3年分红"到底指"3个会计年度有现金分红"还是"3个自然年有除权除息事件"——先确认再执行
- **结果可审计**：每个条件展示真实命中值，不是 pass/fail 标志；筛选漏斗记录每层进出数量
- 数据缺失的股票标记"数据缺失"，不混入通过计数

**触发词**：选股、筛选股票、连续分红、低估值、质押率低、北向加仓

### 6. a-share-stock-dossier — 个股研究员

| 维度 | 详情 |
|:---|:---|
| 定位 | 输入一个 A 股代码 → 输出一份可溯源的中文尽调报告 |
| 覆盖 | 25+ 个 Pandadata 接口，5 个数据阶段，10 条分级风险规则 |
| 输出 | 固定 9 章结构 Markdown 报告 |
| 依赖 | `pandadata-api`（数据契约） |
| 状态 | ✅ stable, runnable, official |

**5 个数据阶段**：

| 阶段 | 内容 | 回答什么 |
|:---|:---|:---|
| 🏢 公司画像 | 基本信息、行业、股本、ST 历史 | 这家公司是干什么的？ |
| 📊 财务分析 | 三张报表、成长性、盈利能力 | 财务状况如何？ |
| 💰 分红与资本运作 | 分红历史、送转、增发 | 对股东好不好？ |
| 👥 股东行为 | 十大股东、增减持、质押、解禁 | 大股东在干什么？ |
| 📈 资金面 | 北向、两融、大宗交易 | 资金在进还是出？ |

**10 条分级风险规则**：覆盖质押、解禁、减持、ST、业绩预告、审计意见、股东人数变化等，**组合风险信号自动触发**（如"质押率高 + 解禁临近"、"减持计划 + 业绩预告下修"）。

**固定 9 章报告**：公司画像 → 财务分析 → 分红与资本运作 → 股东行为 → 风险事件 → 资金面 → 风险信号清单 → 数据附录 → 免责声明

### 7. event-risk-alert — 风险排雷员

| 维度 | 详情 |
|:---|:---|
| 定位 | 对自选股/持仓清单做 7 大事件风险扫描，输出分级预警 |
| 风险面 | 解禁、质押、减持、ST、业绩预告、审计意见、股东人数变化 |
| 依赖 | `pandadata-api`（数据契约） |
| 状态 | ✅ stable, runnable, community |

**默认分级规则**：

| 风险面 | 🔴 high | 🟠 medium | 🟢 low |
|:---|:---|:---|:---|
| 股权质押 | 累计质押比例 ≥ 50% | 累计比例 ≥ 30% | 解押、小额质押 |
| 限售解禁 | 解禁数量 ≥ 总股本 5% | 解禁比例 ≥ 1% | 小额解禁 |
| 股东减持 | 预披露减持计划 | 已完成减持 | 增持行为 |
| ST 风险 | 已 ST 或 \*ST | 连续亏损两年 | 业绩预告亏损 |
| 业绩预告 | 预亏/大幅下修 | 略减 | 预增/预盈 |
| 审计意见 | 保留/否定/无法表示 | 带强调事项段 | 标准无保留 |
| 股东人数 | 连续 3 期大幅减少 | 单期大幅减少 | 正常波动 |

**特色功能**：

- **状态去重**：相同风险事件不重复报送，按 `事件日期 + 股票代码 + 风险类型` 做幂等
- **定时监控**：可设置交易日定时扫描，支持 Feishu/WeCom 推送
- **Watchlist 管理**：JSON 格式清单，脚本验证格式

### 8. report-replication — 研报复现员

| 维度 | 详情 |
|:---|:---|
| 定位 | 把一篇量化研报/论文/PDF 转化为真实数据驱动的研究复现交付包 |
| 流程 | 翻译 → 摘要 → 因子重构 → 有效性验证 → HTML 报告 → 策略代码 → 本地回测 → 中文解释报告 → 交付摘要 |
| 依赖 | `pandadata-api`（数据） + `backtest`（回测协议） |
| 状态 | ✅ stable, runnable, official |

**8 步复现流水线**：

```
1. 全文翻译（中文）→ 2. AI 摘要 → 3. 因子公式复现（Python 代码）
→ 4. 因子有效性验证（IC/ICIR/分组收益）→ 5. 独立 HTML 因子报告（小白可读）
→ 6. 策略代码生成 → 7. 真实本地回测 → 8. 交付摘要
```

**关键约束**：

- 🚫 **禁止合成数据**：必须用 Pandadata 真实行情，不允许模拟数据证明因子有效性
- 固定随机种子的随机因子只能作为**负控制基准**，且需建立在同一份真实收益数据上
- 数据覆盖不足时必须在报告和 manifest.json 中说明

**辅助脚本**：`create_project.py`（创建标准目录）、`pandadata_market_data.py`（拉取真实行情）、`quality_gate_check.py`（质量门检查）、`local_backtest.py`（本地回测执行）

### 9. doc-to-alphas — Alpha 提炼员

| 维度 | 详情 |
|:---|:---|
| 定位 | 从文档文本（研报、财报、市场评论）生成 Alpha 因子表达式，并提供校验 |
| 输出 | 标准化 OHLCV 因子表达式 + 合成数据校验结果 |
| 依赖 | 无（自包含，无外部 API 依赖） |
| 状态 | ⚠️ draft, listed, community |

**核心机制**：

1. Agent 基于大模型能力从文档中提取投资逻辑，生成 Alpha 因子表达式
2. 表达式遵循标准化的 OHLCV 公式契约（`formulas.py` 定义可用算子）
3. `generate_alphas.py` 基于合成数据批量求值，捕获三类错误：
   - 语法错误（Python 表达式不合法）
   - 数值异常（NaN / Inf / 溢出）
   - 逻辑越界（分母为零、未来函数嫌疑）

**注意**：该 Skill 不产生真实市场数据回测结果，只做**表达式层面的语法和逻辑校验**。真实验证需配合 `report-replication` 或 `backtest`。

### 10. factormad-debate-factor-mining — 因子研究小组

| 维度 | 详情 |
|:---|:---|
| 定位 | FactorMAD 风格的 LLM 多 Agent 辩论式因子挖掘 |
| 机制 | 两个 LLM Agent 围绕候选因子辩论、批评、修正 → 输出可执行 Python 代码 |
| 依赖 | 无（自包含，需 OpenAI API Key） |
| 状态 | ✅ activate, runnable, community |

**核心工作流**：

```
输入 OHLCV 行情数据 → Proposer Agent 生成候选因子 → Critic Agent 批评验证
→ 辩论修正 → 轻量 IC/ICIR 评估 → 输出最佳因子（Python 函数 + 参数）
```

**核心特色**：

- **代码型因子**：输出 Python function + arguments，不是固定算子组合
- **双 Agent 辩论**：Proposer 提出因子，Critic 从过拟合、未来函数、经济逻辑等角度攻击
- **dry_run 模式**：不调用 LLM 也能验证安装和输出路径
- **轻量 IC/ICIR**：仅作为内部筛选参考，不替代独立样本外验证
- **时间戳输出目录**：保留每次运行的审计产物

**⚠️ 重要**：输出的因子必须后续用独立流程做样本外、交易成本、风险暴露和组合级回测验证。

### 12. backtest — 回测工程师

| 维度 | 详情 |
|:---|:---|
| 定位 | 不是回测框架，而是**截面多头回测的标准协议** |
| 核心假设 | T+1 开盘成交、Top 10% 等权、双边 15bp、涨跌停剔除 |
| 依赖 | 无（自包含，需自行准备行情数据） |
| 状态 | ✅ stable, listed, community |

**回测协议**：

| 参数 | 设定 |
|:---|:---|
| 成交价 | T+1 开盘价（T 日收盘后才有信号） |
| 仓位 | 截面排名 Top 10%，等权持有 |
| 持仓 | 滚动持仓，H 日重叠，每日 1/H 资金被换仓 |
| 剔除 | A 股 `trade_status==1` 或 `close >= limit_up*0.99` |
| 手续费 | 双边 15bp（佣金+印花+滑点，美股可降到 5bp） |

**标准诊断四联图**：净值曲线 vs 基准、回撤曲线、分组收益柱状图、IC 时序图

**5 项健康度自检**：换手率合理性、收益集中度、极端行情表现、覆盖度、基准对比

**边界声明**：假设资金无限大、无市场冲击；回测净值仅反映历史数据模拟，不代表未来表现，**不构成投资建议**。

## 总体评价

### 优点

1. **闭环完整**：从数据 → 选股 → 尽调 → 风控 → 复盘 → 因子 → 回测，12 个 Skill 覆盖了量化投研的全流程
2. **可审计**：每个数字标来源接口和参数，事实与观点分离，不是"黑箱输出"
3. **可落地**：依赖真实 Pandadata 数据，禁止合成数据，fail-fast 设计
4. **工程化程度高**：校验脚本、增量刷新、状态去重、幂等性、dry_run 模式——考虑到了生产环境的实际问题
5. **多 Agent 协作**：factormad 的辩论式因子挖掘是亮点，把 LLM 的多角色能力用在因子挖掘场景

### 局限

1. **数据强依赖 Pandadata**：如果 Pandadata 不覆盖某个数据需求，大部分 Skill 无法工作
2. **部分 Skill 成熟度不高**：doc-to-alphas 是 draft 状态，backtest 是 listed 而非 runnable
3. **需要编程能力**：虽然 Agent 可以代劳，但调试和定制仍需 Python 基础
4. **回测协议较简单**：只支持截面多头等权，不支持多空、行业中性、动态仓位等高级策略
5. **无实盘对接**：只有回测和研究，没有交易执行模块

### 与现有 panda_factor 的互补性

panda_factor 是底层因子计算框架（去极值、中性化、分层回测），QuantSkills 是上层 AI Agent 自动化工作流。两者结合：
- panda_factor 提供严谨的因子检验方法论
- QuantSkills 提供 AI 驱动的因子发现、选股、复盘、预警自动化
- 互补而非替代
