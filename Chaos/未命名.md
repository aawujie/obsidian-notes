# 【李宏毅机器学习】各式各样神奇的自注意力机制（Self-attention）


变型 完整文案 现场的同学、线上的同学大家好，那我们就开始上课吧。 今天要讲的是各式各样的Self-attention技术，我这边假设你已经看过Self-attention相关的上课录像，已经知道Self-attention是什么，接下来我们要讲，其实Self-attention有各式各样的变形。 在之前Self-attention上课录像的结尾，我们有提到，Self-attention并不是只有上课讲的那种标准形式——产生Q、K、V三种向量，Q跟K两两算内积，对Value做加权求和，再做Attention。假设你对这一整套机制已经非常清楚，那要知道，Self-attention远不止于此。 在之前的影片里，我们停在一个页面，告诉你Self-attention有各式各样的变化，它们往往都用“XXformer”作为结尾，那是另外一个很长的故事，今天我们就要来讲这个故事。 先很简短地复习一下什么是Self-attention，还有它的难点、痛点在哪里。 我们知道，Self-attention存在的意义，是处理输入为一个序列（Sequence）的情况。现在假设输入是一个序列，序列长度用大写N表示，这个序列可以是各种不同的资料形态：可能是一个句子，句子里的每一个Token、每一个词汇当作一个单位；可能是一段语音讯号，语音里的一个Frame当作单位；甚至现在常把Self-attention用在影像处理上，输入是一张图片，图片里的每一个Pixel当作一个单位。 Self-attention要做的事，就是处理这个输入序列。输入序列长度为N后，我们会产生N个Key向量跟N个Query向量，这N个Key跟N个Query会两两之间算内积，总共有N²次内积。把N²次内积的结果集合起来，就得到一个N×N的矩阵，这个矩阵叫做Attention Matrix。我们根据这个Attention Matrix，对Value向量做加权求和，这些都是过去已经讲过的内容。 之前的课程也提过，Self-attention的痛点，就是这个N×N的矩阵，计算量会非常惊人，尤其是输入序列非常长的时候，这个N×N的Attention矩阵计算量会大到无法承受，所以就有一系列方法，想办法加速Attention机制的计算。 不过在开始之前，要提醒大家：Self-attention往往只是巨大神经网络的其中一个模块。举例来说，用Transformer的话，里面不是只有Self-attention，还有其他模块。 今天虽然说Self-attention的运算量和输入序列长度N的平方成正比，但如果Self-attention的运算没有主导整个网络的运算，那加快Self-attention的运算，帮助可能不大。很多同学用了新的Self-attention技术，在Transformer里发现加速效果有限，很可能是因为网络里Feed-Forward部分的运算量，比Self-attention大得多。 那什么时候Self-attention会主导整个网络的运算呢？当输入序列N的长度非常长的时候，整个Transformer里最主要的运算就会来自Self-attention。所以只有序列很长的时候，加快Self-attention才有帮助。 这也是为什么接下来看到的这些Self-attention变形，最早往往都用在影像处理上——因为把Self-attention用在影像时，障碍非常大。 举个例子：处理256×256的图片，如果硬要用标准Self-attention，把每个Pixel当作一个单位，把所有Pixel拉直，输入序列长度N就是256×256。标准Self-attention的运算量正比于N²，也就是(256×256)²，等于256的四次方，运算量极其惊人。所以这些Self-attention变形，最早都用在影像处理上。 总之先强调：**只有输入序列非常长时，接下来的招数才能发挥真正效用**。 那有哪些Self-attention的变形？有什么方法可以加快Self-attention的运算？ 我们说过，Self-attention最大的计算瓶颈，是需要计算N×N的Attention矩阵，所以人们就从这个地方下手：有没有办法不用计算Attention矩阵里的每一个数值？ 根据人类对问题的理解，有些位置的Attention Weight，我们可以直接设定，不需要计算。 先举第一个例子：有时候做Attention时，不一定需要看整个序列，有些问题里，每个位置只需要看左右邻居，就能得到正确答案、理解Token的信息。 那做Self-attention时，就可以把远距离的Attention Weight直接设为0，只计算局部的数值。这种方法叫做**Local Attention**，也叫**Truncated Attention**。 但它有明显问题：只看小范围资讯，Attention就和CNN没什么差别了。之前课程讲过CNN和Attention的关系，如果Attention只关注小范围，本质就是CNN，那直接用CNN就好。所以Local Attention能加速，但效果不一定好。 除了Local Attention，还有**Strided Attention**：不是看紧邻的邻居，而是间隔几格，看更远位置的资讯。对应到Attention Matrix里，只有间隔位置的数值需要计算，其余直接填0，间隔数可以自己根据任务决定。 还有**Global Attention**：前面两种都是以某位置为中心看局部，而Global Attention想了解整个序列的信息。做法是在原始序列里加入特殊Token（Special Token），比如NLP任务里加特殊符号。 Global Attention会做两件事： 1. 特殊Token会去Attend到序列里的每一个Token，收集整个句子的信息； 2. 所有Token也都会去Attend这个特殊Token。 具体操作有两种做法： - 从原有序列里选Token当特殊Token，比如BERT里的`[CLS]` Token，或句子末尾的句号； - 直接额外添加新的特殊Token，不管输入是什么，都固定加几个，它们和所有Token互相Attend。 对应Attention Matrix：特殊Token所在的行，全部需要计算；特殊Token所在的列，也全部需要计算；其他普通Token之间，一律设为0，互不计算。打个比方，特殊Token就像“里长”，大家都认识里长，里长也认识所有人，资讯通过里长传递。 那到底哪种Attention最好？答案是：小孩子才做选择，成熟的方案是全部都用。 Self-attention里有Multi-head机制，可以设定多个Head，让每个Head做不同的事：有的Head做Local Attention，有的做Strided Attention，有的做Global Attention。 知名的变形模型就是这么做的： - **Longformer**：组合Local + Strided + Global Attention； - **BigBird**：在Longformer基础上，再加**Random Attention**——随机选一些Token，让它们彼此之间也做Attention，具体妙用可以看原论文。 以上都是靠人工先验知识，决定哪些位置要算Attention、哪些直接设0。但人工设计真的是最优解吗？不见得。 能不能用数据驱动的方法，不依赖人工规则？ 思路：Attention Matrix里，某些位置Weight很大，某些很小，把很小的直接设0，对结果影响不大，还能减少计算。问题是：怎么快速估算哪些位置会有大的Attention Value？ **Reformer**和**Rin Transformer**用了类似思路：对Query和Key做快速聚类（Clustering），把相近的向量归为同一簇，只有同簇的Query和Key，才计算Attention Weight，不同簇直接设0。 有人会问：聚类本身会不会很耗运算？其实聚类有很多快速近似方法，复杂度远低于N²，所以能有效降低整体计算量。 再进一步：能不能让网络自己“学会”哪些位置要算Attention？ 有个方法叫**Sparse Sorting Network**：用一个额外的小网络，输入序列，输出一个0-1二值Mask矩阵，深色为1（需要计算），浅色为0（直接设0）。这个过程是可微分的，Mask矩阵会和主网络一起训练，让模型自己决定Attention的计算位置。 实际实现里，为了进一步提速，会让多个输入向量共用同一个Mask，降低小网络的输出维度，再放大成N×N的Mask，避免运算量回到N²。 再换个角度：我们真的需要完整的N×N Attention Matrix吗？ **Informer**的实验发现：Attention Matrix其实是**低秩矩阵**，很多列是重复的、线性相关的，存在大量冗余信息。所以不需要完整矩阵，只需要选K个有代表性的Key，把N×N矩阵变成N×K，就能大幅减少计算。 具体做法： 1. 从N个Key里挑K个最具代表性的； 2. 只计算这K个Key和所有Query的Attention，得到N×K矩阵； 3. 对应挑出K个Value，用Attention Weight对这K个Value做加权，得到输出。 为什么不精简Query？因为精简Query会缩短输出序列长度。如果任务需要每个位置都输出Label（如序列标注），就不能精简Query；只有分类这类只输出一个Label的任务，才可以精简Query。 那怎么选代表性Key？ - **Compress Attention**：用CNN对Key序列做下采样，缩短长度作为代表Key； - **Linformer**：把Key矩阵（D×N）乘一个N×K的投影矩阵，得到D×K矩阵，每一列是原有Key的线性组合，作为代表Key。 接下来从矩阵乘法的角度，做更极致的加速。 先复习标准Self-attention的矩阵运算： 输入I → 乘W_Q得Q（D×N），乘W_K得K（D×N），乘W_V得V（D'×N）； Attention Matrix A = Softmax(K^T · Q)； 输出O = A · V。 复杂度核心：K^T · Q是N×D乘D×N，得到N×N矩阵，运算量O(N²)。 如果**改变矩阵相乘顺序**：先算V · K^T，再乘Q。 - V·K^T：D'×N 乘 N×D → 得到D'×D小矩阵，运算量O(D'·N·D)； - 再乘Q（D×N）：运算量O(D'·D·N)； - 总复杂度从O(N²)降到O(N)，当N远大于D时，提速极其明显。 这个思路就是**Linear Transformer**和**Performer**的核心：通过核函数技巧，把exp(Q·K^T)拆解为F(Q)·F(K)^T，保留Softmax的同时，实现线性复杂度的计算。 最后，我们再重新思考：做Self-attention，一定要用Q和K算Attention吗？ **Synthesizer**给出了颠覆性答案：不需要Q和K，直接把Attention Matrix当作网络的可学习参数，训练时直接优化这个N×N矩阵，不再计算Attention Weight。 实验发现，这种做法性能下降不多，让我们重新思考Attention的价值——过去认为Attention要随输入动态变化，其实固定的Attention矩阵也能学到足够的模式。 更进一步，处理序列一定要用Attention吗？现在已经有一系列Attention-Free的方法，用MLP等结构替代Attention，这又是另一个故事了。 最后看Long Range Arena基准的对比结果： - 横轴：速度（越右越快）； - 纵轴：效果（分数越高越好）； - 圆圈大小：内存占用。 - 标准Transformer：效果最好，但最慢、最耗内存； - Local Attention：最快，但效果差； - Reformer：聚类方案，效果一般； - Sparse Sorting Network：效果有下降，速度明显提升； - Informer、Performer、Linear Transformer：速度极快，效果和标准Transformer差距较小，是长序列场景的优选； - Synthesizer：效果略降，速度提升。 以上就是今天要分享的，各式各样Self-attention的变形，谢谢大家。
