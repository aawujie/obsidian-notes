# MoE 混合专家模型 - 面试要点

> 面试背诵版 | 整理自视频总结

---

## 一句话定义

MoE (Mixture of Experts) = 将 FFN 拆分成多个专家模块，每个 token 只激活少数专家处理，实现"大参数量 + 小激活成本"。

---

## 核心要点（背诵顺序）

### 1. 为什么 MoE 成为主流？

**打破不可能三角**：性能、规模、成本三选二 → 三者兼顾
- 总参数量大 → 性能强
- 激活参数量小 → 成本低
- 解耦两者 = MoE 的魔法

**代表模型**：Gemini、Qwen、DeepSeek V3、Mixtral

---

### 2. MoE vs 稠密模型

| | 稠密模型 | MoE |
|---|---|---|
| 激活方式 | 全参数激活 | 稀疏激活（只激活 top-k 专家） |
| 计算量 | ∝ 总参数量 | ∝ 激活参数量 |
| 知识存储 | 均匀分布 | 专家分工 |
| 训练速度 | 基准 | 2.5-7x 加速 |

---

### 3. 架构流程（面试必背）

```
输入 token → Router → 选 top-k 专家 → 专家并行计算 → 加权求和 → 输出
```

**Router**：轻量网络，输出专家概率分布  
**top-k**：超参数，通常 k=2 或 k=4  
**加权**：Router 概率作为权重

---

### 4. DeepSeek MoE 优化（加分项）

- **细颗粒度专家**：把大专家拆成更多小专家 → 路由更灵活
- **共享专家**：部分专家对所有 token 激活 → 通用知识
- 结论：专家数量有最优平衡点，共享专家作用有限

---

### 5. 路由策略对比

| 策略 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **Token Choice** | token 选专家 | 效果好 | 负载不均 |
| **Expert Choice** | 专家选 token | 负载均衡 | token 丢失、推理难 |

主流：Token Choice + 辅助损失函数平衡负载

---

### 6. 训练挑战

**核心问题**：训练不稳定，loss 突然飙升

**解决方案**：
- 特殊初始化（专家权重小方差）
- 学习率调整（Router 用更小 LR）
- 梯度裁剪
- 负载均衡损失

---

## 面试高频问题

### Q: MoE 为什么能做大模型？
A: 解耦总参数量和激活参数量。总参数大存储知识多，激活少算力成本低。

### Q: MoE 的专家是怎么分工的？
A: 每层有独立专家组，Router 动态选择。不同专家倾向不同知识领域，模型自动学习专业化分工。

### Q: MoE 训练有什么坑？
A: 不稳定，loss 会突然飙升。需要特殊初始化、梯度裁剪、负载均衡损失等技术。

### Q: 为什么不用 Expert Choice？
A: 推理时专家选 token 会有 token 丢失问题，而且难以处理变长序列。Token Choice 更适合实际部署。
