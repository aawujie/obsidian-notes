# JIT 即时编译详解

> 编译技术核心概念 | 整理时间：2026-03-22

---

## 一、什么是 JIT？

**JIT = Just-In-Time（即时编译）**

```
传统编译：源代码 → 编译 → 机器码 → 执行
JIT 编译：源代码 → 字节码 → 运行时编译成机器码 → 执行
```

**核心思想**：在程序运行时才把代码编译成机器码，而不是提前编译好。

---

## 二、三种执行方式对比

| 类型 | 全称 | 编译时机 | 代表语言/引擎 |
|------|------|----------|---------------|
| **AOT** | Ahead-Of-Time | 运行前编译 | C/C++、Rust、Go |
| **JIT** | Just-In-Time | 运行时编译 | Java JVM、JavaScript V8 |
| **解释器** | Interpreter | 逐行解释执行 | Python (CPython)、Ruby |

---

## 三、执行流程图

### AOT（提前编译）

```
源代码 ──[编译器]──► 机器码 ──[运行]──► 执行
         (一次性)              (直接运行)
```

### JIT（即时编译）

```
源代码 ──[编译]──► 字节码 ──[JIT编译器]──► 机器码 ──► 执行
                   (分发)     (运行时)       (优化后)
```

### 解释器

```
源代码 ──[解释器]──► 逐行执行
         (运行时)
```

---

## 四、JIT 的优势

| 优势 | 说明 |
|------|------|
| ✅ **运行时优化** | 根据实际执行情况做优化（热点代码优化） |
| ✅ **跨平台** | 分发字节码，不同平台各自 JIT 编译 |
| ✅ **动态语言高效** | 让 Python、JavaScript 等也能跑得快 |
| ✅ **自适应优化** | 根据运行数据动态调整优化策略 |

---

## 五、JIT 的劣势

| 劣势 | 说明 |
|------|------|
| ❌ **启动慢** | 需要预热，冷启动性能差 |
| ❌ **内存占用大** | JIT 编译器和编译结果占用内存 |
| ❌ **编译开销** | 运行时编译消耗 CPU 资源 |
| ❌ **复杂性高** | 实现复杂，调试困难 |

## 六、常见 JIT 实现

### Java JVM

```
Java 源码 ──► 字节码 (.class) ──► JVM JIT ──► 机器码

HotSpot JVM 的 JIT 编译器：
- C1 (Client): 快速编译，启动快
- C2 (Server): 深度优化，性能高
- Graal: 新一代 JIT 编译器
```

### JavaScript V8

```
JS 源码 ──► 字节码 ──► Ignition 解释器 ──► TurboFan JIT ──► 机器码

优化策略：
- 热点函数标记
- 类型特化优化
- 内联缓存
```

### Python PyPy

```
Python 源码 ──► 字节码 ──► PyPy JIT ──► 机器码

性能对比：
- CPython (解释器): 基准 1x
- PyPy (JIT): 5-10x 更快
```

### 其他常见 JIT

| 语言/引擎 | JIT 编译器 | 特点 |
|-----------|------------|------|
| **.NET** | RyuJIT | 跨平台，高性能 |
| **Lua** | LuaJIT | 游戏开发常用，极快 |
| **Android** | ART (AOT+JIT) | 混合模式 |
| **Python** | Numba | 数值计算 JIT |

## 七、JIT vs AOT 选择

| 场景 | 推荐 | 原因 |
|------|------|------|
| 启动速度要求高 | AOT | 无预热，立即运行 |
| 长时间运行服务 | JIT | 运行时优化，峰值性能高 |
| 动态特性多 | JIT | 支持运行时生成代码 |
| 嵌入式/资源受限 | AOT | 内存占用小 |
| 跨平台分发 | JIT 字节码 | 一次编译，到处运行 |

---

## 八、混合模式：AOT + JIT

现代系统常采用混合模式：

```
Android ART:
├── 安装时 AOT 编译（核心代码）
└── 运行时 JIT 编译（热点代码）

Java GraalVM:
├── AOT 编译为原生镜像（启动快）
└── JIT 编译优化（运行时）

Python (Numba):
├── 解释执行（首次）
└── JIT 编译热点函数（优化后）
```

## 九、面试高频问题

### Q: JIT 和解释器的区别？
A: 解释器逐行解释执行，不生成机器码；JIT 在运行时将热点代码编译成机器码，后续执行更快。

### Q: 为什么 Java 既能跨平台又高效？
A: 字节码跨平台分发，JVM 在各平台用 JIT 编译优化，兼顾移植性和性能。

### Q: Python 为什么慢？
A: CPython 是解释器，无 JIT。用 PyPy 或 Numba 可以获得 JIT 加速。

### Q: JavaScript 为什么能跑这么快？
A: V8 引擎使用 JIT（Ignition + TurboFan），对热点代码深度优化。

> **AOT 先编译后跑，JIT 边跑边编译。**  
> **解释器逐行跑，JIT 热点优化快。**  
> **启动快选 AOT，长期跑选 JIT。**
