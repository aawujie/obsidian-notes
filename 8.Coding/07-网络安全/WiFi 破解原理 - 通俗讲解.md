## 🎯 核心原理（两件事）

整个 WiFi 破解只干**两件事**：

| 步骤 | 目标 | 产出 |
|------|------|------|
| **1️⃣ 抓包** | 捕获加密握手包 | `.cap` 文件 |
| **2️⃣ 撞库** | 字典暴力破解 | 明文密码 |

```
抓包 → 握手包.cap → 字典碰撞 → 密码
```

---

## 📡 第一部分：抓包原理

### 为什么要抓「四次握手」？

当你连接 WiFi 时，手机和路由器会进行 **4-way handshake（四次握手）**：

```
┌─────────┐                    ┌─────────┐
│  手机   │                    │ 路由器  │
└────┬────┘                    └────┬────┘
     │                              │
     │  ───── 1. 发送随机数 A ────→ │
     │ ← ──── 2. 发送随机数 B ───── │
     │                              │
     │  ───── 3. 验证 + PTK ──────→ │
     │ ← ──── 4. 确认连接 ───────── │
     │                              │
```

**关键点：**
- ❌ **不会**直接把密码发出去
- ✅ 但会带上**用密码加密过的一段数据**（PMK/PTK）
- ✅ 这段数据 = 密码的"加密影子"（哈希）

**攻击者的目标：**
```
截获 4 次握手 → 提取哈希值 → 保存为 .cap 文件
```

---

### 🥊 「踢人攻击」是干嘛的？

**问题：** 没人连 WiFi 时，没有握手，抓不到包。

**解决：** 用 **Deauth 攻击** 把已连接的设备踢下线！

```
攻击者发送伪造的「断开连接帧」
        ↓
    设备被踢下线
        ↓
    设备自动重连
        ↓
    触发四次握手 ✨
        ↓
    抓包成功！🎯
```

**工具命令：**
```bash
# aireplay-ng 发送踢人包
sudo aireplay-ng -0 10 -a <路由器 MAC> wlan0mon
```

---

## 🔓 第二部分：破解原理

### 字典撞密码

抓到的 `.cap` 文件**不是密码本身**，是**密码的哈希值**。

**破解流程：**

```
┌─────────────────────────────────────────────────┐
│  1. 准备字典（如 rockyou.txt，1000 万 + 密码）    │
│         ↓                                       │
│  2. 对每个密码计算哈希（PBKDF2-SHA1）            │
│         ↓                                       │
│  3. 与抓包中的哈希一一比对                       │
│         ↓                                       │
│  4. 匹配成功 → 密码找到！✅                      │
│     匹配失败 → 试下一个密码 ❌                   │
└─────────────────────────────────────────────────┘
```

**工具命令：**
```bash
# 用 aircrack-ng 破解
aircrack-ng -w rockyou.txt capture.cap

# 用 hashcat（更快，支持 GPU）
hashcat -m 2500 capture.cap rockyou.txt
```

> 1. **WiFi 连接时会产生一段带密码影子的握手数据**

# 📝 补充章节（进阶细节）

## 🔬 细节 1：四次握手的每一帧到底传了什么？

```
┌─────────────────────────────────────────────────────────────────┐
│ 第 1 帧：AP → Client                                             │
│ ─────────────────────────                                        │
│ 内容：ANonce（AP 的随机数）                                      │
│ 作用：告诉客户端「我要开始握手了，这是我的随机数」                │
│ 加密：❌ 未加密                                                  │
├─────────────────────────────────────────────────────────────────┤
│ 第 2 帧：Client → AP                                             │
│ ─────────────────────────                                        │
│ 内容：SNonce（客户端的随机数）+ MIC（消息完整性校验）            │
│ 作用：「收到，这是我的随机数，这是我用密码算的校验值」            │
│ 加密：✅ 用 PTK 加密 MIC                                         │
│ 关键：⚠️ 这一帧包含密码的哈希！抓包目标！                        │
├─────────────────────────────────────────────────────────────────┤
│ 第 3 帧：AP → Client                                             │
│ ─────────────────────────                                        │
│ 内容：GTK（组临时密钥）+ MIC                                     │
│ 作用：「校验通过，这是组播密钥，正式连接吧」                      │
│ 加密：✅ 用 PTK 加密                                             │
├─────────────────────────────────────────────────────────────────┤
│ 第 4 帧：Client → AP                                             │
│ ─────────────────────────                                        │
│ 内容：确认 ACK                                                   │
│ 作用：「收到，连接完成！」                                       │
│ 加密：✅ 用 PTK 加密                                             │
└─────────────────────────────────────────────────────────────────┘
```

**关键点：**
- **PMK（Pairwise Master Key）** = `PBKDF2(密码，SSID, 4096, 256)`
  - 密码 + SSID + 4096 次迭代 → 256 位密钥
- **PTK（Pairwise Transient Key）** = `PMK + ANonce + SNonce + AP_MAC + Client_MAC`
  - 用于加密单播数据
- **MIC** = 用 PTK 计算的校验值，**验证密码是否正确**

## 🎯 细节 2：为什么哈希不能反向推导？

**问题：** 既然抓到了哈希，为什么不直接反推出密码？

**答案：** PBKDF2 是**单向函数**！

```
密码 → PBKDF2 → 哈希
  ↑              ↓
  └────────── ❌ 无法反向
```

**为什么？**
1. **信息丢失**：哈希计算过程中丢弃了大量信息
2. **多对一映射**：无数个密码可能产生同一个哈希
3. **计算不可逆**：数学上无法从结果推导输入

**唯一方法：** 暴力碰撞（字典攻击）

```
试密码 1 → 算哈希 → 比对 ❌
试密码 2 → 算哈希 → 比对 ❌
试密码 3 → 算哈希 → 比对 ✅ 找到了！
```

## 💀 细节 3：PMKID 攻击（不需要客户端！）

**传统攻击的痛点：** 需要等有客户端连接才能抓握手包。

**PMKID 攻击（2018 年发现）：** 直接找 AP 要哈希，**不需要客户端！**

### 原理

```
传统方式：
等待客户端连接 → 抓四次握手 → 破解
     ↓
  可能需要等很久 😫

PMKID 攻击：
主动请求 AP → AP 返回 PMKID → 破解
     ↓
  立等可取！😎
```

### 命令

```bash
# 1. 获取 PMKID（hcxdumptool）
sudo hcxdumptool -i wlan0mon -o pmkid.pcapng --enable_status=1

# 2. 转换为 hashcat 格式
hcxpcapngtool -o pmkid.hash pmkid.pcapng

# 3. 破解
hashcat -m 16800 pmkid.hash rockyou.txt
```

### 对比

| 特性 | 四次握手 | PMKID |
|------|----------|-------|
| 需要客户端 | ✅ 是 | ❌ 否 |
| 等待时间 | 不确定 | 立即 |
| 成功率 | 高 | 中等（部分 AP 不支持） |
| 工具 | aircrack-ng | hcxdumptool |

**建议：** 先试 PMKID，不行再用四次握手。

## ⚡ 细节 5：GPU 加速破解（hashcat）

**aircrack-ng** = CPU 破解，速度慢（~100 密码/秒）

**hashcat** = GPU 破解，速度快（~10 万 密码/秒）

### 性能对比

| 工具 | 硬件 | 速度 | 破解 1434 万密码 |
|------|------|------|------------------|
| aircrack-ng | CPU 4 核 | 100/s | 40 小时 |
| hashcat | GPU GTX 1060 | 5 万/s | 5 分钟 |
| hashcat | GPU RTX 4090 | 50 万/s | 30 秒 |

### 常用命令

```bash
# WPA/WPA2 破解（模式 2500）
hashcat -m 2500 -a 0 capture.cap rockyou.txt

# PMKID 破解（模式 16800）
hashcat -m 16800 -a 0 pmkid.hash rockyou.txt

# 掩码攻击（知道密码格式）
# 例如：8 位数字密码
hashcat -m 2500 -a 3 capture.cap ?d?d?d?d?d?d?d?d

# 规则攻击（变形字典）
hashcat -m 2500 -a 0 -r rules/best64.rule capture.cap rockyou.txt
```

### 常见规则

```bash
# best64.rule - 64 条最佳规则
# 示例变形：
password → Password, password1, password123, p@ssword

# 使用方式
hashcat -m 2500 -a 0 -r /usr/share/hashcat/rules/best64.rule capture.cap rockyou.txt
```

## 🛠️ 细节 6：实战常见问题

### Q1: 抓不到握手包怎么办？

**原因：**
- 没有客户端连接
- 信号太弱
- 信道不对

**解决：**
```bash
# 1. 踢人攻击强制重连
sudo aireplay-ng -0 10 -a <AP_MAC> wlan0mon

# 2. 监听指定信道
sudo airodump-ng -c 6 --bssid <AP_MAC> -w output wlan0mon

# 3. 等待更长时间
# 有些设备几分钟才重连一次
```

### Q2: 怎么验证抓到的包有效？

```bash
# 用 aircrack-ng 验证
aircrack-ng capture.cap

# 输出：
# Aircrack-ng 1.7
# [00:00:00] 1/4 key tested
# 
# 如果显示「KEY FOUND!」说明包有效
# 如果显示「No valid WPA handshakes found」说明包无效
```

### Q3: 破解一直失败怎么办？

**可能原因：**
1. 密码不在字典中 → 换更大的字典
2. 密码太复杂 → 用掩码攻击
3. 包损坏 → 重新抓包
4. WPA3 → 不支持（需要新工具）

**解决：**
```bash
# 1. 换字典
hashcat -m 2500 capture.cap probable-v2.txt

# 2. 掩码攻击（知道部分信息）
# 例如：姓名 +4 位数字
hashcat -m 2500 -a 3 capture.cap wang?d?d?d?d

# 3. 组合攻击
hashcat -m 2500 -a 6 capture.cap names.txt ?d?d?d?d
```

### Q4: 信号太弱抓不到怎么办？

**解决：**
```bash
# 1. 靠近目标
# 2. 用高增益天线
# 3. 用 USB 网卡 + 延长线

# 检查信号强度
sudo airodump-ng wlan0mon
# 查看 PWR 列，数值越接近 0 越好
# -30 ~ -50: 极好
# -50 ~ -70: 可用
# < -70: 困难
```

## 🚨 细节 7：WPA3 怎么办？

**WPA3（2018 年发布）使用 SAE 协议**，传统方法失效。

### 差异对比

| 特性 | WPA2 | WPA3 |
|------|------|------|
| 握手协议 | 4-way | SAE (Dragonfly) |
| 离线破解 | ✅ 可以 | ❌ 极难 |
| 前向保密 | ❌ 无 | ✅ 有 |
| 密码重试 | 无限制 | 限速 |

### 现状

- **SAE 协议** 设计时就防离线破解
- 目前**没有成熟的 WPA3 破解方法**
- 只能通过**社会工程学**获取密码

### 过渡方案

很多路由器支持 **WPA2/WPA3 混合模式**，这时可以：
1. 强制降级到 WPA2
2. 用传统方法破解

```bash
# 发送降级攻击（部分路由器有效）
sudo aireplay-ng --deauth 10 -a <AP_MAC> wlan0mon
```
