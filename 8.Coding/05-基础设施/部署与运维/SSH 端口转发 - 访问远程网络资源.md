# SSH 端口转发 - 访问远程网络资源

## 问题场景

当你在局域网机器 A 上，想要访问机器 B 所在子网的路由器/内网资源时，直接访问是不可能的（因为不在同一网段）。

**拓扑示例：**
```
Mac (10.24.99.x) ←→ Ubuntu (10.24.99.65) ←→ 路由器 (192.168.8.1)
     你在这里                                    目标在这里
```

## 解决方案：SSH 本地端口转发

### 基本命令

```bash
ssh -N -L [本地端口]:[目标地址]:[目标端口] [用户]@[跳板机 IP]
```

### 实际案例

```bash
# 访问 Ubuntu 背后的路由器管理页面
ssh -N -L 8080:192.168.8.1:443 dr@10.24.99.65
```

然后在浏览器访问：`https://localhost:8080`

---

## 参数详解

| 参数 | 含义 |
|------|------|
| `-N` | 不执行远程命令，只做端口转发（终端会阻塞） |
| `-L` | Local port forwarding（本地端口转发） |
| `8080` | 本地监听端口（可自定义） |
| `192.168.8.1` | 目标地址（跳板机能访问的） |
| `443` | 目标端口（HTTPS） |
| `dr@10.24.99.65` | 跳板机登录信息 |

---

## 工作原理

```
┌─────────────┐    SSH 隧道    ┌─────────────┐   HTTP   ┌─────────────┐
│   你的 Mac   │──────────────→│   Ubuntu    │─────────→│   路由器    │
│ localhost:8080│              │ 10.24.99.65 │          │ 192.168.8.1 │
└─────────────┘               └─────────────┘          └─────────────┘
```

1. SSH 在 Mac 的 8080 端口监听
2. 所有发往 `localhost:8080` 的流量通过 SSH 隧道加密传输到 Ubuntu
3. Ubuntu 将流量转发到 `192.168.8.1:443`
4. 响应沿原路返回

## 常见使用场景

### 1. 访问远程数据库
```bash
# 访问远程 MySQL（默认 3306）
ssh -N -L 3306:localhost:3306 user@remote-server
# 本地连接：mysql -h 127.0.0.1 -P 3306
```

### 2. 访问远程 Web 服务
```bash
# 访问远程运行的 Jupyter Notebook
ssh -N -L 8888:localhost:8888 user@remote-server
```

### 3. 访问不同网段的路由器
```bash
# 如本文案例
ssh -N -L 8080:192.168.8.1:80 user@gateway
```

### 4. 绕过防火墙/访问内网
```bash
# 访问公司内网服务器
ssh -N -L 9000:internal-server:80 user@company-gateway
```

## 注意事项

### ✅ 端口选择
- 避免使用系统端口（<1024）
- 推荐：8080, 8888, 9000 等

### ✅ HTTPS vs HTTP
- 如果目标服务强制 HTTPS，转发 443 端口
- 浏览器访问时用 `https://localhost:端口`
- 自签名证书会提示不安全，点"继续访问"即可

### ✅ 终端阻塞是正常的
- 加 `-N` 后终端会停住，这是正常的（隧道保持活跃）
- 新开终端窗口访问服务
- 用完 Ctrl+C 断开

### ✅ 防火墙
- 确保跳板机 SSH 端口（22）开放
- 本地端口转发不需要跳板机开放额外端口

## 进阶用法

### 转发多个端口
```bash
ssh -N -L 8080:192.168.8.1:80 -L 8443:192.168.8.1:443 dr@10.24.99.65
```

### 后台运行（自动断开重连）
```bash
ssh -f -N -L 8080:192.168.8.1:443 dr@10.24.99.65
# -f 表示后台运行
```

### 远程端口转发（反向隧道）
```bash
# 让远程机器能访问你本地的服务
ssh -N -R 8080:localhost:3000 user@remote-server
```

### SOCKS 代理（转发所有流量）
```bash
# 把远程机器当代理服务器
ssh -N -D 1080 user@remote-server
# 然后配置浏览器 SOCKS 代理 localhost:1080
```

## 故障排查

### 1. 连接被拒绝
```bash
# 检查本地端口是否被占用
lsof -i :8080
# 或换一个端口
```

### 2. 隧道不通
```bash
# 加 -v 看详细日志
ssh -N -L 8080:target:port -v user@host
```

### 3. 跳板机能访问目标吗？
```bash
# 在跳板机上测试
curl -v http://目标地址
```

### 4. 本地端口通吗？
```bash
# 在本地测试
nc -zv localhost 8080
```

---

## 总结

SSH 端口转发是系统管理员/开发者的必备技能：
- **安全**：流量通过 SSH 加密
- **方便**：无需额外软件，OpenSSH 自带
- **灵活**：可转发任意 TCP 端口

记住核心命令格式：
```bash
ssh -N -L 本地端口：目标地址：目标端口 用户@跳板机
```
