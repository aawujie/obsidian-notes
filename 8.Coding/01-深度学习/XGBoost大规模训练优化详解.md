# 2. Overview

本视频核心论题是介绍 XGBoost 在面对大规模训练数据时所采用的一系列工程与算法优化，这些优化使得 XGBoost 在速度与内存使用上表现优异。结论是：XGBoost 并不仅仅靠统计或树模型的数学性质取胜，而是通过近似贪心（approximate greedy）算法、加权分位草图（weighted quantile sketch）、稀疏感知分裂查找（sparsity-aware split finding）、缓存友好访问（cache-aware access）、盘外块计算（blocks for out-of-core computation）以及随机子采样特征/样本等工程手段来大幅提升在大数据场景下的训练效率与可扩展性。

# 3. 按照主题来梳理

## 3.1 近似贪心算法（Approximate Greedy）

- XGBoost 在构建回归树或分类树时的基本做法是贪心（greedy）地为每个节点选择使得分裂增益（gain）最大的阈值。这种贪心决策意指：在评估某个节点时，选择当前看来最优的阈值，而不回溯或考虑后续叶子如何进一步分裂。贪心策略的好处是构树速度快，避免遍历所有可能的全局树结构，但代价是可能不是全局最优。视频在前几部分已经解释了如何用相似性分数（similarity）和增益（gain）来评估分裂，因此这里接着讨论当数据量极大时，逐一测试每个可能阈值的代价会非常高。
- 近似贪心算法的核心思想是：不要测试每一个可能的阈值，而是把连续特征的取值划分为若干“候选阈值”（candidate thresholds），这些候选来自数据的分位点（quantiles）。例如把排序后的剂量（dosage）值按分位切分，取分位边界作为候选阈值。这样把原本可能是成千上万的阈值检验，压缩为几十个或更少的候选，从而显著减小分裂搜索的计算量。选择分位数的个数会影响准确率与速度的折中：分位数越少（例如只用 1 个将数据一分为二），候选阈值越少，速度越快但效果可能很差；分位数越多，效果越接近穷举，但开销也更大。XGBoost 默认使用“约 33 个”分位数（这里的约来自分布估算与加权合并机制，实际不是每次严格 33 个），这是对精度与效率的一种经验折中。
- 当数据量大到单机内存容纳不了时，分位点计算本身变慢，因为需要排序或统计。为此引入了“草图”（sketch）类算法来近似地构建分布。草图可以把每台机器上局部数据的分布压缩为小体积的摘要（summary），然后在机器间合并这些摘要生成近似直方图或近似分位。合并后的近似直方图就被用来选择候选分位点，供近似贪心算法使用。这样就能在分布式场景下并行计算候选阈值，显著提升大数据下的可扩展性。
- 总结上面几点：近似贪心不再枚举每个阈值，而是用分位（quantiles）作为候选，通过草图算法在分布式环境下并行合并得到近似分位点，从而在可接受精度损失下大幅加速建树过程。

## 3.2 加权分位草图（Weighted Quantile Sketch）

- 当数据被分成多个机器或数据块时，普通的分位（每个分位包含相等数量的观测）并不总是最合适的选择，尤其在梯度提升框架中每个观测对目标函数的贡献并不相同。XGBoost 引入“加权分位草图”（weighted quantile sketch），这里的“权重”源自每个样本在当前模型下的覆盖（cover）或二阶信息，即损失函数的二阶导数（Hessian，海森）。直观上，每个观测的权重代表它在当前残差调整中的重要性。
- 对于回归问题（常见的平方损失），二阶导数为常数 1，因此权重一致；在这种情况下，加权分位退化为普通分位，等量观测分配到每个分位。对于分类问题，权重为 p*(1-p)，其中 p 是当前预测的概率（previous probability）。因此预测接近 0 或 1（模型已有高置信度）的样本权重较小，预测接近 0.5（不确定）的样本权重大。加权分位将样本按照权重总和相等的方式划分分位，而不是观测数量相等。
- 这样做的好处：把“重要的、模型不确定的样本”分散到更多、更细的分位中，使得在这些区域的阈值搜索更精细、更有可能找到能提高模型的分裂。反过来，对于模型已非常有信心的样本，分位可以更粗，从而避免浪费计算资源去在不需要改进的区域做精细分裂。视频用具体示例说明：若某些剂量点预测概率接近 0.5，它们的权重较大，会被单独放入更小的分位，而置信度高的点（概率接近 0 或 1）会聚合在较大的分位中。
- 技术实现上：加权分位草图同样需要在分布式或内存受限场景合并各块的草图摘要。草图算法必须支持带权的样本合并与近似分位查询，这是 XGBoost 在实现上的一大工程点。通过加权草图，XGBoost 在维持速度的同时能保留对“重要样本”更高的分裂分辨率，从而在大规模分类任务上获得更好效果。

## 3.3 稀疏感知分裂查找（Sparsity-Aware Split Finding）

- 在实际数据中常有缺失值或“稀疏特征”（sparse features）。XGBoost 提供的稀疏感知分裂查找（sparsity-aware split finding）既能处理训练数据中的缺失值，也能决定在预测时新样本缺失某特征时应当走向哪一支（默认路径）。核心思路是：在计算某个特征的候选阈值时，把有该特征值的观测与没有（Missing）的观测分开处理，然后尝试把“缺失值”当作放到左叶或放到右叶，计算两种情形的增益（gain_left、gain_right），选择能带来更大总增益的那种放置方式。
- 具体步骤可以表述为：
    - 把数据分为两张表：一张包含具有该特征值的观测（有值），另一张包含缺失该特征的观测（无值）。
    - 在有值表中，根据排序或（近似）分位生成候选阈值；对每个候选阈值，将有值样本划分到左/右叶并计算各叶的增益构成的基线。
    - 对于每个候选阈值，还要分别计算两种把缺失样本放入左叶或放入右叶的增益（gain_left 和 gain_right）。
    - 记录使得总体增益（考虑缺失样本放置后）最大的配置；该配置确定了缺失样本的“默认方向”（default direction）。在预测阶段，新样本如果缺失该特征，则沿着该默认分支前进。
- 这样做保证了训练期间就为缺失值做了基于增益的最优决策，而不是简单地用常数或均值填补缺失值。它的优点包括：对稀疏数据友好、能在分裂时合理利用缺失信息、以及对预测阶段的新样本缺失场景给出一致的默认路径。视频以剂量（dosage）示例逐步演示了计算 gain_left 与 gain_right 的过程，最后选择某一阈值并决定默认走左叶，从而明确了模型对后续缺失样本的处理策略。

## 3.4 缓存友好访问（Cache-Aware Access）

- 在单机层面，CPU 的性能并非仅由计算速度决定，内存访问模式对总体速度影响极大。CPU 有多级存储：最快的是少量的缓存（cache），其次是主内存（RAM），再是更慢的磁盘（硬盘或 SSD）。为了获得最佳性能，应该尽量把热数据放在缓存里，让计算访问速度最快的数据结构。XGBoost 做了专门的工程优化，把需要频繁访问的梯度（gradients）与海森（Hessians，即二阶信息）等小数组放入可以被缓存高效利用的内存布局，从而在计算相似性分数（similarity）与叶子输出（output values）时减少内存延迟。
- 实践上，缓存友好设计包含几方面：
    - 将相关数据按访问顺序打包（memory layout），减少 CPU 访问不同内存位置时的缓存未命中（cache miss）。
    - 把频繁使用的中间量（如每个节点或候选分裂的累积梯度/海森）尽量保存在较小的数据结构中，方便放入 L1/L2 缓存。
    - 通过按块处理（blocking）来控制一次处理的数据量，避免把大量数据装入主内存然后频繁访问导致缓存抖动（cache thrashing）。
- 这些优化并不是统计学上的改进，而是系统工程层面的提升，但对训练速度影响显著：同样的算法逻辑，在缓存友好与否的实现下，可能存在数倍的运行时间差异。视频强调这类优化虽“看起来很底层”，却是 XGBoost 能在工业级数据上高效运转的重要原因之一。

## 3.5 磁盘外块计算（Blocks for Out-of-Core Computation）

- 当数据集大到连主内存（RAM）也放不下时，必须把部分数据放在磁盘上（out-of-core）。磁盘 I/O 是整个系统中最慢的环节，频繁读写会极大拖慢训练速度。XGBoost 的策略是最小化磁盘访问次数与大小，具体做法包括数据压缩、按块（blocks）读取与磁盘分片（sharding）。
- 要点如下：
    - 数据压缩：在磁盘上保存压缩后的数据，读取时由 CPU 解压缩。尽管解压会占用 CPU 周期，但通常解压耗时远小于从磁盘读取更多未压缩数据所需的时间，因此整体可提升速度。
    - 按块读取与处理：把大型数据集预先组织成若干块（blocks），训练时一次只将一个或几个块载入内存并处理完与该块相关的计算，减少多个来回的磁盘读写。通过合理设置块大小，可在内存限制下保持较高的磁盘吞吐利用率。
    - 分片（sharding）：当有多个磁盘设备时，将数据切分并分配到不同磁盘，使多个磁盘并行读写，提高 I/O 并发。视频举例说明，如果数据被分到两块磁盘，两块可同时读数据，CPU 可以并行消费，这比单盘顺序读要快得多。
- 结合上面的缓存友好访问策略，XGBoost 在处理磁盘外数据时尽量在每次磁盘读取中把数据以缓存/内存友好的顺序组织与传递，以减少解压与内存重新布局带来的额外开销。整体目标是：以尽量少的磁盘读取次数来完成尽可能多的计算。

## 3.6 随机子采样（Row & Feature Subsampling）

- XGBoost 也支持在建树时对训练样本和特征做随机子采样（subsampling）。这是两类随机化：
    - 行子采样（row subsampling）：每棵树只使用训练数据的一个随机子集来拟合。这减少了每棵树的训练开销并能增加模型的鲁棒性（类似于随机森林的思想），有助于减小过拟合并提升并行效率。
    - 列子采样（feature subsampling）：在寻找分裂时只考虑特征的随机子集。这样每次分裂的候选特征减少，计算量随之降低，同时还能增加模型多样性，抑制特征间的过拟合。
- 这些随机化手段与近似贪心、加权草图等优化配合使用时，可以进一步缩短训练时间并提供合适的精度/速度折中。视频以“BAM”突出了这是另一组能显著加速训练的手段，同时也能在一定程度上保持或提升泛化性能。

# 4. 框架 & 心智模型（Framework & Mindset）

- 大体心智模型：在处理大规模机器学习问题时，需要同时从算法准确性与系统实现两方面优化。XGBoost 的成功在于把统计学习（如何定义增益、相似性、二阶近似）和系统工程（分布式草图、缓存优化、磁盘块、并行 I/O）结合起来。一个有效的思路是将问题拆成“重要性不同的子问题”并用不同的策略来对待：对“重要”数据（高权重、低置信度）做精细优化，对“次要”数据做近似或粗化处理。
- 可操作的步骤/心智框架：
    1. 明确度量和优先级：在梯度提升框架中，用一阶梯度和二阶海森来衡量每个样本当前的“重要度”。这让我们能把有限的计算资源优先分配到最有可能改进模型的部分。
    2. 分层近似：对搜索空间（比如特征阈值）进行分层近似。对于全局最优的穷举不现实时，先用粗粒度（如分位）的候选减小搜索，再在候选中做较精细的评估。加权分位就是把“粗/细”分配到样本重要性不同的区域。
    3. 并行与分布式摘要：当单机资源受限，用轻量、可合并的摘要（sketch）在多台机器间汇总信息，避免全量通信或排序。摘要应支持合并操作与适当的误差界。
    4. 软处理稀疏性：面对缺失值或稀疏特征，不要简单填补，而是在分裂决策时显式考虑缺失样本的去向，选出能最大化增益的默认路径，这样训练与预测阶段行为一致。
    5. 系统级优化优先级：把热路径（频繁访问的数据：梯度、海森、候选统计）放到缓存友好的内存布局，按块读取大数据并压缩磁盘存储以减少慢 I/O。工程实现要与算法设计协同，使实现层面的优化最大化算法收益。
    6. 随机化作为加速器：用样本/特征随机子采样减少计算同时保持或改进泛化，作为速度与精度间的常用折中手段。
- 这种心智模型强调“分层聚焦”（focus where it matters）和“算法与系统共设计”（co-design）。当数据规模小且能放入内存时，可退回到更精确的算法（纯贪心、全量分位）；当数据规模大时，用近似、加权、摘要和工程优化来牺牲可控的小量精度以换取可用性与速度。

# 总结

XGBoost 的速度与可扩展性来自多方面协同的优化：在算法层面用近似贪心和加权分位草图减少候选阈值并优先关注重要样本；在数据稀疏处理上用稀疏感知分裂确保对缺失值的合理处理和预测一致性；在系统层面通过缓存友好布局、压缩存储、按块与分片的磁盘 I/O 优化大规模训练；再辅以样本与特征的随机子采样作为进一步加速手段。这些优化将统计学习方法与工程实现深度结合，使 XGBoost 在工业与研究中广泛成功。
